# `AI`、`RAG` 与 `Agent` 实战路线

这条路线把“理解模型”与“交付系统”放在一条线上。每个阶段都要留下一个可以运行、测量或解释的产物；只读文章不算完成。已经能稳定写 `Python`、调用 `HTTP API` 的读者可以从第 3 阶段开始，跳过的知识仍要用验收题补齐。

## 一、总图

```text
工具与编程
    ↓
机器学习 / Transformer / LLM
    ↓
模型调用与结构化输出
    ↓
Embedding → 数据摄取 → 检索与重排 → 生成与引用
    ↓                         ↓
RAG 评估与权限                Agent 状态与工具
    └──────────────→ 生产化、观测、成本与回滚
```

路线中有三条并行线：知识线回答“为什么这样工作”，工程线回答“怎样实现”，交付线回答“怎样证明可靠”。每阶段的验收必须同时覆盖至少两条线。

## 二、阶段总览

| 阶段 | 核心问题 | 最小产出 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 1. 工具与编程 | 能否读数据、调接口、记录失败 | 带测试的 CLI | 能处理空输入、超时和重试 |
| 2. 模型原理 | 模型为何能表示和生成文本 | Mini `Transformer` 笔记或代码 | 能解释 tokenizer、attention、采样 |
| 3. 模型调用 | 如何稳定得到结构化结果 | 抽取 `API` | 有 schema 校验、成本和错误日志 |
| 4. `Embedding` 与搜索 | 如何找到相关证据 | 可复现检索实验 | 能比较 dense、关键词和混合检索 |
| 5. `RAG` 实现 | 如何让回答有证据并会拒答 | 带引用问答 Demo | 每个答案能回指来源 |
| 6. 评估与权限 | 如何知道系统是否变好且不越权 | 固定题集和回归报告 | 有检索、生成、权限三类指标 |
| 7. `Agent` 编排 | 如何让模型安全调用多个步骤 | 受限工具 Agent | 有状态、步数、审批和恢复 |
| 8. 生产化 | 如何上线、观测和控制成本 | 可回滚服务方案 | 有 p95、预算、告警和演练记录 |

## 三、逐阶段学习与交付

### 1. 工具与编程基础

**要学的知识。** `Python` 模块和类型、虚拟环境、`Git`、`Linux`、`HTTP`、`JSON`、异步、异常、日志和测试。重点是把输入、外部调用和持久化边界分开。

**前置条件。** 能阅读函数、列表、字典和文件操作；不会 `Python` 时先读 [Python 基础与工程实践学习路线](../python/README.md)。

**实践产出。** 写一个命令行程序：读取文本，调用一个公开 `API`，把响应保存成 `JSON`，处理空输入、超时、非 2xx 响应和重复运行。为成功、失败和空结果各写一个测试。

**验收标准。** 能画出输入→请求→解析→保存的边界；命令在无网络时给出可读错误；日志不打印密钥；测试可以重复运行。

**替代选择。** `Python` 适合 AI 生态和数据实验；熟悉 `TypeScript` 的团队可以用 Node.js，但要补齐类型校验、异步错误和脚本运行方式。不要为了换语言同时维护两套示例。

对应资料：[Python 后端全栈学习路线](../python/Python%20后端全栈学习路线.md)、[HTTP 请求方式总结](../http/4、HTTP请求方式总结.md)。

### 2. 机器学习、深度学习与 `Transformer`

**要学的知识。** 向量和矩阵、概率、损失函数、梯度下降、过拟合、训练集切分、反向传播、`MLP`、注意力、`Multi-Head Attention`、位置编码、`LayerNorm`、残差、`Tokenizer/BPE`、`logits`、`softmax`、`temperature`、`top-k/top-p`、`causal mask` 和 `KV cache`。

**前置条件。** 阶段 1 的 `Python` 和基础线性代数；不要求先推导完整论文，但每个概念要能对应到一个输入、输出和失败现象。

**实践产出。** 先用纯 `Python` 实现线性回归或二分类器，再用 `PyTorch` 完成一个最小 `Transformer`，记录一次训练损失和一次生成采样。

**验收标准。** 能解释 token 如何变成向量，attention 如何决定权重，为什么 `temperature` 会改变分布；能指出上下文长度、过拟合和 hallucination 的边界。

**替代选择。** 想理解机制可读 `micrograd` 和 `nanoGPT`；想尽快做应用可先使用 Hugging Face 模型，把训练实现放到后续。两条路径都必须保留一份数值或输出对照记录。

对应资料：[AI 知识图谱](../ai/README.md)、[深度学习与 Transformer](../ai/02-深度学习与Transformer.md)、[大语言模型](../ai/03-大语言模型.md)。

### 3. 模型调用与结构化输出

**要学的知识。** 消息角色、上下文窗口、提示词、结构化输出、`JSON Schema`、函数调用、流式响应、重试、超时、模型路由、token 统计和密钥管理。

**前置条件。** 能使用阶段 1 的 CLI 发起并记录 `HTTP` 请求；理解阶段 2 的 token、概率和上下文限制。

**实践产出。** 做一个结构化信息抽取 `API`：输入一段合同或工单，输出经过 schema 校验的 `JSON`；保存模型版本、输入 token、输出 token、延迟和错误类型。

**验收标准。** 非法 JSON 会进入修复或重试分支；超时不会无限等待；模型输出不能绕过业务校验；成本可以按请求和每天汇总。

**替代选择。** 托管模型适合快速交付，优点是质量和运维成本可控；本地模型适合隐私、离线和固定负载，代价是部署、显存和评测。模型 SDK 适合单供应商，统一网关适合多模型路由，但会增加一层故障和计费排查。

对应资料：[大模型与 Agent 全栈学习专题](../ai/13-AI大模型与Agent全栈学习专题.md)、[模型调用示例](../langchain/03-model-calling.md)。

### 4. `Embedding`、数据摄取与搜索

**要学的知识。** 文档解析、清洗、分块、元数据、`Embedding`、向量距离、关键词检索、`BM25`、混合检索、过滤、索引更新、删除和版本。先理解“召回相关证据”，再讨论生成。

**前置条件。** 阶段 3 的结构化数据和错误处理；准备一套脱敏、带标题和来源的文档。

**实践产出。** 对同一批文档跑三组实验：dense、`BM25`、混合检索。为每个问题保存 gold source、返回的 top-k、延迟和失败原因。

**验收标准。** 删除文档后不会继续被召回；相同输入和索引版本能复现结果；能解释 chunk 太大、太小和元数据缺失分别造成什么问题。

**方案比较。**

| 方案 | 优点 | 代价 | 适合 |
| --- | --- | --- | --- |
| `BM25`/关键词 | 可解释、便宜、专名准确 | 同义改写和跨语言较弱 | 规章编号、错误码、精确术语 |
| Dense 向量 | 语义召回好，接近自然语言提问 | 依赖模型和索引，专名可能漂移 | FAQ、相似问题、语义搜索 |
| 混合检索 | 同时利用词面和语义 | 权重、去重和调参更复杂 | 企业知识库默认起点 |
| 托管向量库 | 上手快、扩缩容简单 | 成本、网络和供应商绑定 | 先交付、团队运维能力有限 |
| `PostgreSQL` + 向量扩展 | 数据、权限、事务集中 | 超大规模检索需额外设计 | 已有关系库、租户隔离要求高 |

对应资料：[数据摄取](../rag/02-数据摄取.md)、[检索与重排](../rag/03-检索与重排.md)。

### 5. `RAG`：生成、引用与拒答

**要学的知识。** 查询改写、`reranker`、上下文拼接、提示模板、引用格式、证据不足拒答、上下文预算、答案与来源的对应关系。

**前置条件。** 阶段 4 能稳定返回带 metadata 的证据；先定义“什么算有证据”，再写生成提示词。

**实践产出。** 用脱敏制度文档做一个问答服务，输出答案、来源文件、章节和引用片段。实现 `ingest`、`ask`、`test` 三个命令，并保留一次失败样本。

**验收标准。** 每个事实性结论能回指来源；证据不足时明确拒答；索引重建后旧版本不会混入；提示词注入不会改变检索权限。

**替代选择。** 轻量 FAQ 可用检索后模板填充；多跳问题再引入 query rewriting 或 Agent；先调 chunk 和检索，再考虑换更大的生成模型。复杂度应由失败样本驱动。

对应资料：[RAG 原理地图](../rag/01-RAG原理地图.md)、[生成与引用](../rag/04-生成与引用.md)、[最小实战](../rag/05-最小实战.md)。

### 6. 评估、权限与回归

**要学的知识。** 固定题集、`Recall@k`、`MRR`、引用覆盖率、答案正确率、拒答率、人工盲评、`LLM-as-Judge` 的偏差、租户和版本过滤、审计日志。

**前置条件。** 阶段 5 已有可运行链路和失败样本；题集必须包含正常问题、无答案问题、相似干扰和越权问题。

**实践产出。** 建立至少 20 条 `JSONL` 评估集，记录 gold source、检索结果、回答、引用和人工标签；每次改 chunk、模型或提示词都生成一份前后对比报告。

**验收标准。** 指标来自固定数据集而非挑选样本；权限过滤发生在检索前；低置信度和证据冲突会升级人工；报告能定位是摄取、召回、重排还是生成出错。

**替代选择。** 小团队先人工盲评和规则指标，成本低且易解释；规模增大后再使用自动评审，但保留人工校准集。`LLM-as-Judge` 只能作为辅助信号，不能独立决定上线。

对应资料：[RAG 评估](../rag/06-评估.md)、[RAG 生产化](../rag/07-生产化.md)、[Agent Evals](../agent/22、Agent%20Evals%20—%20先把轨迹看懂，再谈效果.md)。

### 7. `Agent` 状态、工具与编排

**要学的知识。** 状态、观察、工具 schema、`ReAct`、规划、最大步数、超时、幂等、人工审批、失败恢复、子 Agent、`Skill` 和 `MCP`。

**前置条件。** 阶段 6 已有固定评估集和权限边界；先把 RAG 做成一个受限工具，再增加其他工具。

**实践产出。** 做一个只允许搜索、读取、汇总三个工具的研究 Agent。每次调用记录参数、权限判断、工具结果、耗时和停止原因；支持达到步数上限时保存状态。

**验收标准。** 工具参数在执行前校验；模型不能直接执行任意命令；失败可重试或转人工；轨迹能解释 Agent 为什么结束。

**方案比较。**

| 方案 | 优点 | 代价 | 适合 |
| --- | --- | --- | --- |
| 自研状态机 | 边界最清晰、依赖少 | 要自己做持久化和可观测性 | 工具少、流程固定 |
| `LangGraph` | 状态图、暂停恢复、调试友好 | 学习和版本成本 | 多步骤、有人工节点 |
| 模型厂商 Agents SDK | 接入快、工具和追踪集成 | 厂商绑定、抽象变化 | 单一模型生态的快速验证 |
| 多 Agent 框架 | 角色协作表达力强 | 通信成本和责任边界复杂 | 确有角色分工的研究任务 |

对应资料：[Agent Loop](../agent/01、Agent%20Loop%20—%20一个循环就够了.md)、[Tool Use](../agent/02、Tool%20Use%20—%20多加一个工具，只加一行.md)、[MCP Tools](../agent/19、MCP%20Tools%20—%20外接工具，标准协议.md)。

### 8. 生产化、性能与成本

**要学的知识。** 服务拆分、队列、缓存、批处理、模型路由、限流、熔断、超时、重试、`p50/p95`、追踪、灰度、数据保留、预算、回滚和灾备。

**前置条件。** 阶段 6 的评估报告和阶段 7 的轨迹日志；没有基线指标不要直接压测或换模型。

**实践产出。** 把 RAG 或 Agent 部署为服务，加入健康检查、超时、重试、权限、指标和预算上限；写一份上线评审表，包含降级、回滚和数据删除演练。

**验收标准。** 能报告 p50/p95 延迟、单请求成本、错误率和人工升级率；上游限流时服务有可预测降级；模型或索引版本可回滚；敏感数据不会进入调试日志。

**替代选择。** 低流量先用单服务和托管模型，减少运维面；高并发再拆队列、缓存和批处理；隐私或成本稳定后再评估本地模型。不要为了“生产架构”提前引入微服务。

对应资料：[Cost and Reliability](../agent/25、Cost%20and%20Reliability%20—%20让%20Agent%20跑得稳、算得清.md)、[Durable Execution](../agent/24、Durable%20Execution%20—%20让长任务可暂停、可恢复.md)、[RAG 培训计划](../rag/09-培训计划.md)。

## 四、贯穿项目

| 项目 | 覆盖阶段 | 必须留下的证据 |
| --- | --- | --- |
| `Tokenizer` + Mini `Transformer` | 1–2 | token、attention、损失和采样记录 |
| 结构化抽取 `API` | 3 | schema、重试、成本日志和错误样本 |
| 带引用的企业 `RAG` | 4–6 | 索引版本、题集、检索指标、引用和拒答 |
| 受限工具 `Agent` | 6–7 | 工具 schema、权限、轨迹、步数和恢复 |
| 生产级智能服务 | 7–8 | p95、预算、告警、回滚和删除演练 |

## 五、技术选型的统一规则

1. 先用能解释的最小方案建立基线，再用失败样本推动替换。
2. 先修数据、分块、权限和评估，再升级模型或增加 Agent。
3. 选择托管服务时记录成本、锁定风险和退出方案；选择本地方案时记录显存、运维和质量差距。
4. 每一次替代都必须回答：解决了哪个可观测问题，增加了什么新故障，如何回滚。

## 六、两周团队培训如何接入

团队培训可以直接使用 [RAG 两周培训计划](../rag/09-培训计划.md)：第 1 天到第 5 天对应阶段 4–5，第 6 天到第 8 天对应阶段 6，第 9 天到第 10 天对应阶段 8 的上线评审。阶段 1–3 的知识缺口用个人预习或结对讲解补齐，阶段 7 的 Agent 编排作为培训后的扩展任务。

完成路线后，读者应能用大白话解释每个组件的输入、输出、失败边界，并用固定数据集证明一次改动到底让系统变好还是变坏。
