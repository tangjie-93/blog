## 5.1 Spring Cloud生态（第1-21天）

### 5.1.1 微服务架构概述

#### 什么是微服务
微服务架构是一种将单体应用程序拆分为一组小型服务的方法，每个服务运行在自己的进程中，通过轻量级机制（通常是HTTP REST API）进行通信。

**与前端对比：**
| 前端概念 | 微服务概念 |
|---------|-----------|
| 单页应用（SPA） | 单体应用 |
| 微前端（qiankun/module federation） | 微服务 |
| 组件拆分 | 服务拆分 |
| npm包管理 | Maven依赖管理 |
| API网关（Nginx） | Spring Cloud Gateway |
| 服务注册（Consul） | Nacos/Eureka |
| 状态管理（Redux/Vuex） | 分布式配置中心 |

#### 微服务架构图
```
┌─────────────────────────────────────────────────────────────┐
│                        客户端（Web/App）                      │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│                   API网关（Spring Cloud Gateway）             │
│              - 路由转发、鉴权、限流、日志                       │
└────────┬──────────────┬──────────────┬──────────────────────┘
         │              │              │
    ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
    │ 用户服务 │    │ 订单服务 │    │ 商品服务 │  <- 各个微服务
    │ (8081)  │    │ (8082)  │    │ (8083)  │
    └────┬────┘    └────┬────┘    └────┬────┘
         │              │              │
    ┌────▼──────────────▼──────────────▼────┐
    │        服务注册与发现（Nacos）           │
    │     - 服务注册、服务发现、健康检查        │
    └─────────────────┬─────────────────────┘
                      │
         ┌────────────┼────────────┐
         │            │            │
    ┌────▼────┐  ┌────▼────┐  ┌───▼─────┐
    │  MySQL  │  │  Redis  │  │ RabbitMQ│  <- 基础设施
    │ (数据库) │  │ (缓存)  │  │ (消息)  │
    └─────────┘  └─────────┘  └─────────┘
```

### 5.1.2 Spring Cloud Alibaba简介

Spring Cloud Alibaba是阿里巴巴提供的微服务解决方案，是国内主流的微服务框架套件。

#### 核心组件
| 组件 | 功能 | 对标Netflix |
|------|------|------------|
| Nacos | 服务注册与发现、配置中心 | Eureka + Config |
| OpenFeign | 服务调用 | Feign |
| Sentinel | 熔断降级、流量控制 | Hystrix |
| Seata | 分布式事务 | 无 |
| Spring Cloud Gateway | API网关 | Zuul |
| Spring Cloud LoadBalancer | 负载均衡 | Ribbon |

### 5.1.3 Nacos服务注册与发现

#### Nacos简介
Nacos是阿里巴巴开源的服务注册中心和配置中心，类似于前端的Consul或Etcd。

**与前端对比：**
| 前端 | Nacos |
|------|-------|
| 环境变量配置 | 配置中心 |
| 服务发现（DNS） | 服务注册与发现 |
| 健康检查 | 服务健康检查 |

#### 安装Nacos
1. 下载Nacos：[Nacos官网](https://nacos.io/zh-cn/docs/quick-start.html)
2. 解压到指定目录
3. 启动（单机模式）：
```bash
# Windows
startup.cmd -m standalone

# Linux/Mac
sh startup.sh -m standalone
```

4. 访问控制台：`http://localhost:8848/nacos`
   - 默认账号密码：nacos/nacos

### 5.1.4 OpenFeign服务调用

#### OpenFeign简介
OpenFeign是Spring Cloud提供的声明式REST客户端，简化了微服务之间的调用。类似于前端的axios封装。

**与前端对比：**
| 前端 | OpenFeign |
|------|-----------|
| axios/fetch | OpenFeign |
| API封装 | FeignClient接口 |
| 拦截器 | Feign拦截器 |
| 请求/响应转换器 | Encoder/Decoder |

#### 定义Feign客户端

**创建Feign接口：**
```java
package com.example.order.feign;

import com.example.order.entity.User;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.*;
import java.util.List;

/**
 * 用户服务Feign客户端
 * name: 服务提供者的服务名称
 * fallback: 降级处理类
 */
@FeignClient(name = "service-user", fallback = UserFeignFallback.class)
public interface UserFeignClient {
    
    /**
     * 根据ID查询用户
     * 对应服务提供者的接口：GET /api/users/{id}
     */
    @GetMapping("/api/users/{id}")
    User getUserById(@PathVariable("id") Long id);
    
    /**
     * 查询所有用户
     */
    @GetMapping("/api/users")
    List<User> getAllUsers();
    
    /**
     * 创建用户
     */
    @PostMapping("/api/users")
    User createUser(@RequestBody User user);
    
    /**
     * 更新用户
     */
    @PutMapping("/api/users/{id}")
    User updateUser(@PathVariable("id") Long id, @RequestBody User user);
    
    /**
     * 删除用户
     */
    @DeleteMapping("/api/users/{id}")
    void deleteUser(@PathVariable("id") Long id);
}
```

```java
    }

    public void deleteUser(Long id) {
        // 降级处理

}
```

**订单服务：**
```java
package com.example.order.service;

import com.example.order.entity.Order;
import com.example.order.entity.User;
import com.example.order.feign.UserFeignClient;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.math.BigDecimal;
import java.util.*;

@Service
public class OrderService {
    
    @Autowired
    private UserFeignClient userFeignClient;
    
    // 模拟数据库
    private static final Map<Long, Order> ORDER_DB = new HashMap<>();
    
    static {
        Order order1 = new Order();
        order1.setId(1L);
        order1.setOrderNo("ORD20240101001");
        order1.setUserId(1L);
        order1.setAmount(new BigDecimal("99.99"));
        order1.setStatus(1);
        order1.setCreatedAt(new Date());
        ORDER_DB.put(1L, order1);
    }
    
    /**
     * 根据ID查询订单（包含用户信息）
     */
    public Order getOrderById(Long id) {
        Order order = ORDER_DB.get(id);
        if (order != null) {
            // 通过Feign调用用户服务获取用户信息
            User user = userFeignClient.getUserById(order.getUserId());
            order.setUser(user);
        }
        return order;
    }
    
    /**
     * 查询所有订单（包含用户信息）
     */
    public List<Order> getAllOrders() {
        List<Order> orders = new ArrayList<>(ORDER_DB.values());
        
        // 批量获取用户信息
        for (Order order : orders) {
            User user = userFeignClient.getUserById(order.getUserId());
            order.setUser(user);
        }
        
        return orders;
    }
    
    /**
     * 创建订单
     */
    public Order createOrder(Order order) {
        // 验证用户是否存在
        User user = userFeignClient.getUserById(order.getUserId());
        if (user == null) {
            throw new RuntimeException("用户不存在");
        }
        
        Long id = ORDER_DB.size() + 1L;
        order.setId(id);
        order.setOrderNo("ORD" + System.currentTimeMillis());
        order.setStatus(0);
        order.setCreatedAt(new Date());
        ORDER_DB.put(id, order);
        
        return order;
    }
}
```

```java
package com.example.gateway.filter;

import org.springframework.cloud.gateway.filter.GatewayFilterChain;
import org.springframework.cloud.gateway.filter.GlobalFilter;
import org.springframework.core.Ordered;
import org.springframework.http.HttpStatus;
import org.springframework.http.server.reactive.ServerHttpRequest;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ServerWebExchange;
import reactor.core.publisher.Mono;
import java.util.Arrays;
import java.util.List;

/**
 * 全局鉴权过滤器
 */
@Component
public class AuthGlobalFilter implements GlobalFilter, Ordered {
    
    // 白名单路径
    private static final List<String> WHITE_LIST = Arrays.asList(
        "/api/users/login",
        "/api/users/register",
        "/api/products/list"
    );
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        String path = request.getURI().getPath();
        
        // 白名单直接放行
        if (WHITE_LIST.contains(path)) {
            return chain.filter(exchange);
        }
        
        // 获取Token
        String token = request.getHeaders().getFirst("Authorization");
        
        // 验证Token
        if (token == null || token.isEmpty()) {
            // 未授权，返回401
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        
        // TODO: 验证Token有效性
        
        // 将用户信息传递给下游服务
        ServerHttpRequest mutatedRequest = request.mutate()
            .header("X-User-Id", "1")  // 模拟用户ID
            .header("X-User-Name", "张三")
            .build();
        
        return chain.filter(exchange.mutate().request(mutatedRequest).build());
    }
    
    /**
     * 过滤器执行顺序，数值越小优先级越高
     */
    @Override
    public int getOrder() {
        return -1;
    }
}
```

```java
import com.example.order.feign.UserFeignClient;
import io.seata.spring.annotation.GlobalTransactional;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.math.BigDecimal;
import java.util.Date;

@Service
public class OrderService {
    
    @Autowired
    private UserFeignClient userFeignClient;
    
    @Autowired
    private OrderMapper orderMapper;
    
    @Autowired
    private StockFeignClient stockFeignClient;
    
    /**
     * 创建订单（分布式事务）
     * @GlobalTransactional 开启全局分布式事务
     */
    @GlobalTransactional(name = "create-order", timeoutMills = 30000)
    public Order createOrder(Order order) {
        // 1. 验证用户
        User user = userFeignClient.getUserById(order.getUserId());
        if (user == null) {
            throw new RuntimeException("用户不存在");
        }
        
        // 2. 扣减库存（调用库存服务）
        boolean stockResult = stockFeignClient.deductStock(order.getProductId(), order.getQuantity());
        if (!stockResult) {
            throw new RuntimeException("库存不足");
        }
        
        // 3. 创建订单
        order.setOrderNo("ORD" + System.currentTimeMillis());
        order.setStatus(0);
        order.setCreatedAt(new Date());
        orderMapper.insert(order);
        
        // 4. 模拟异常（测试事务回滚）
        // int i = 1 / 0;  // 抛出异常，整个事务回滚
        
        return order;
    }
}
```

## 5.2 消息队列（第22-35天）

### 5.2.1 消息队列概述

#### 什么是消息队列
消息队列（Message Queue，简称MQ）是一种用于异步通信的中间件，类似于前端的EventBus或发布订阅模式。

**与前端对比：**
| 前端 | 消息队列 |
|------|---------|
| EventBus | 消息队列 |
| 发布/订阅模式 | 消息发布/消费 |
| 异步回调 | 异步消息处理 |
| Promise.all | 消息确认 |
| 事件监听 | 消息监听 |

#### 消息队列应用场景
1. **异步处理**：用户注册后发送邮件/短信
2. **应用解耦**：订单系统与库存系统解耦
3. **流量削峰**：秒杀活动中的请求排队
4. **日志处理**：集中收集和处理日志
5. **消息通讯**：聊天系统中的消息传递

#### 主流消息队列对比
| 特性 | RabbitMQ | Kafka | RocketMQ |
|------|----------|-------|----------|
| 开发语言 | Erlang | Scala/Java | Java |
| 协议 | AMQP | 自定义协议 | 自定义协议 |
| 消息模型 | 队列模型 | 分区模型 | 队列模型 |
| 吞吐量 | 万级 | 百万级 | 十万级 |
| 延迟 | 微秒级 | 毫秒级 | 毫秒级 |
| 适用场景 | 企业应用 | 大数据/日志 | 金融交易 |

### 5.2.4 消息确认机制

#### 生产者确认

**application.yml配置：**
```yaml

  rabbitmq:
```

**生产者确认回调：**
```java
package com.example.mq.config;

import org.springframework.amqp.rabbit.core.RabbitTemplate;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Configuration;
import javax.annotation.PostConstruct;

@Configuration
public class RabbitMQProducerConfig implements RabbitTemplate.ConfirmCallback, RabbitTemplate.ReturnsCallback {
    
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    @PostConstruct
    public void init() {
        rabbitTemplate.setConfirmCallback(this);
        rabbitTemplate.setReturnsCallback(this);
    }
    
    /**
     * 确认回调（消息到达交换机）
     */
    @Override
    public void confirm(CorrelationData correlationData, boolean ack, String cause) {
        if (ack) {
            System.out.println("消息成功到达交换机");
        } else {
            System.out.println("消息到达交换机失败：" + cause);
        }
    }
    
    /**
     * 退回回调（消息未路由到队列）
     */
    @Override
    public void returnedMessage(ReturnedMessage returned) {
        System.out.println("消息被退回：" + returned.getMessage());
        System.out.println("退回原因：" + returned.getReplyText());
        System.out.println("交换机：" + returned.getExchange());
        System.out.println("路由键：" + returned.getRoutingKey());
    }
}
```

```java
@Component
public class ManualAckConsumer {
    
    @RabbitListener(queues = "manual.queue")
    public void handleMessage(String message, Channel channel, 
                             @Header(AmqpHeaders.DELIVERY_TAG) long deliveryTag) throws IOException {
        try {
            System.out.println("接收消息：" + message);
            
            // 处理业务逻辑
            processMessage(message);
            
            // 手动确认（成功）
            channel.basicAck(deliveryTag, false);
            
        } catch (Exception e) {
            System.out.println("处理失败：" + e.getMessage());
            
            // 手动拒绝（不重新入队）
            channel.basicNack(deliveryTag, false, false);
            
            // 或者手动拒绝（重新入队）
            // channel.basicNack(deliveryTag, false, true);
        }
    }
    
    private void processMessage(String message) throws Exception {
        // 模拟处理
        if (message.contains("error")) {
            throw new Exception("处理失败");
        }
        System.out.println("处理成功：" + message);
    }
}
```

### 5.2.5 死信队列

#### 死信队列简介
死信队列（Dead Letter Queue，DLQ）用于存放无法被消费的消息。类似于前端的错误处理机制。

**死信原因：**
1. 消息被拒绝（basic.reject/basic.nack）且不重新入队
2. 消息TTL过期
3. 队列达到最大长度

**架构图：**
```
生产者 -> 正常队列 -> 消费者
              ↓（死信）
         死信交换机 -> 死信队列 -> 死信消费者
```

**配置类：**
```java
@Configuration
public class DeadLetterConfig {
    
    /**
     * 正常队列（绑定死信交换机）
     */
    @Bean
    public Queue normalQueue() {
        return QueueBuilder.durable("normal.queue")
            .deadLetterExchange("dlx.exchange")  // 死信交换机
            .deadLetterRoutingKey("dlx.routing.key")  // 死信路由键
            .ttl(10000)  // 消息TTL（10秒）
            .maxLength(100)  // 队列最大长度
            .build();
    }
    
    /**
     * 死信交换机
     */
    @Bean
    public DirectExchange dlxExchange() {
        return new DirectExchange("dlx.exchange");
    }
    
    /**
     * 死信队列
     */
    @Bean
    public Queue dlxQueue() {
        return QueueBuilder.durable("dlx.queue").build();
    }
    
    /**
     * 绑定死信队列到死信交换机
     */
    @Bean
    public Binding dlxBinding() {
        return BindingBuilder.bind(dlxQueue()).to(dlxExchange()).with("dlx.routing.key");
    }
}
```

### 5.2.7 消息幂等性处理

#### 幂等性简介
消息幂等性是指同一条消息被多次消费时，产生的效果与消费一次相同。类似于前端的防抖和节流。

**与前端对比：**
| 前端 | 消息幂等性 |
|------|-----------|
| 防抖（debounce） | 消息去重 |
| 唯一标识 | 消息ID |
| 状态标记 | 消费记录 |

#### 消息幂等性实现

**方案1：唯一消息ID**
```java
@Component
public class IdempotentConsumer {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @RabbitListener(queues = "idempotent.queue")
    public void handleMessage(String message, Message msg) throws IOException {
        String messageId = msg.getMessageProperties().getMessageId();
        System.out.println("接收消息ID：" + messageId);
        
        // 使用Redis SETNX判断是否已处理
        String key = "mq:processed:" + messageId;
        Boolean isNew = redisTemplate.opsForValue().setIfAbsent(key, "1", 24, TimeUnit.HOURS);
        
        if (Boolean.FALSE.equals(isNew)) {
            System.out.println("消息已处理，跳过：" + messageId);
            return;
        }
        
        try {
            // 处理业务逻辑
```

### 5.3.1 CAP理论与BASE理论

#### CAP理论

**CAP理论简介：**
CAP理论是分布式系统设计的基本理论，指出一个分布式系统最多只能同时满足以下三个特性中的两个：

- **C（Consistency，一致性）**：所有节点在同一时刻看到的数据是一致的
- **A（Availability，可用性）**：每个请求都能收到一个响应（不保证是最新数据）
- **P（Partition tolerance，分区容错性）**：网络分区时，系统仍能继续运行

**与前端对比：**
| 前端 | CAP理论 |
|------|---------|
| 数据同步（WebSocket） | 一致性 |
| 服务可用性 | 可用性 |
| 网络异常处理 | 分区容错性 |

**CAP权衡：**
- **CP（一致性 + 分区容错性）**：如Zookeeper、Redis Cluster
- **AP（可用性 + 分区容错性）**：如Eureka、Cassandra
- **CA（一致性 + 可用性）**：单节点数据库（不常见）

#### BASE理论

**BASE理论简介：**
BASE理论是对CAP理论中一致性和可用性权衡的结果，核心思想是即使无法做到强一致性，但可以采用适当的方式使最终一致性得到满足。

- **BA（Basically Available，基本可用）**：系统出现故障时，允许损失部分可用性
- **S（Soft state，软状态）**：允许系统中的数据存在中间状态
- **E（Eventually consistent，最终一致性）**：系统中的所有数据在经过一段时间后，最终能够达到一致的状态

**与前端对比：**
| 前端 | BASE理论 |
|------|---------|
| 乐观更新 | 最终一致性 |
| 加载状态 | 软状态 |
| 降级UI | 基本可用 |

**最终一致性实现方案：**

1. **读时修复**
```java
public User getUser(Long userId) {

    User user = redisTemplate.opsForValue().get("user:" + userId);

        // 缓存未命中，从数据库读取

            redisTemplate.opsForValue().set("user:" + userId, user);

        asyncCheckConsistency(userId, user);

            // 数据不一致，更新缓存
            redisTemplate.opsForValue().set("user:" + userId, dbUser);
        }
    });
}
```

**方案3：雪花算法（Snowflake）**

**雪花算法简介：**
雪花算法是Twitter开源的分布式ID生成算法，生成的ID是一个64位的long型数字。

**ID结构：**
```
0 - 41位时间戳 - 10位工作机器ID - 12位序列号

- 1位符号位：始终为0
- 41位时间戳：毫秒级，可使用69年
- 10位工作机器ID：支持1024个节点
- 12位序列号：每毫秒可生成4096个ID
```

**雪花算法实现：**
```java
package com.example.common.id;

public class SnowflakeIdGenerator {
    
    // 起始时间戳（2020-01-01）
    private final long epoch = 1577836800000L;
    
    // 机器ID位数
    private final long workerIdBits = 5L;
    
    // 数据中心ID位数
    private final long datacenterIdBits = 5L;
    
    // 序列号位数
    private final long sequenceBits = 12L;
    
    // 机器ID最大值
    private final long maxWorkerId = ~(-1L << workerIdBits);  // 31
    
    // 数据中心ID最大值
    private final long maxDatacenterId = ~(-1L << datacenterIdBits);  // 31
    
    // 机器ID左移位数
    private final long workerIdShift = sequenceBits;  // 12
    
    // 数据中心ID左移位数
    private final long datacenterIdShift = sequenceBits + workerIdBits;  // 17
    
    // 时间戳左移位数
    private final long timestampLeftShift = sequenceBits + workerIdBits + datacenterIdBits;  // 22
    
    // 序列号掩码
    private final long sequenceMask = ~(-1L << sequenceBits);  // 4095
    
    // 工作机器ID（0-31）
    private long workerId;
    
    // 数据中心ID（0-31）
    private long datacenterId;
    
    // 序列号（0-4095）
    private long sequence = 0L;
    
    // 上次生成ID的时间戳
    private long lastTimestamp = -1L;
    
    public SnowflakeIdGenerator(long workerId, long datacenterId) {
        if (workerId > maxWorkerId || workerId < 0) {
            throw new IllegalArgumentException("Worker ID can't be greater than " + maxWorkerId + " or less than 0");
        }
        if (datacenterId > maxDatacenterId || datacenterId < 0) {
            throw new IllegalArgumentException("Datacenter ID can't be greater than " + maxDatacenterId + " or less than 0");
        }
        this.workerId = workerId;
        this.datacenterId = datacenterId;
    }
    
    /**
     * 生成下一个ID
     */
    public synchronized long nextId() {
        long timestamp = System.currentTimeMillis();
        
        if (timestamp < lastTimestamp) {
            throw new RuntimeException("Clock moved backwards. Refusing to generate id for " + 
                (lastTimestamp - timestamp) + " milliseconds");
        }
        
        if (lastTimestamp == timestamp) {
            // 同一毫秒，递增序列号
            sequence = (sequence + 1) & sequenceMask;
            if (sequence == 0) {
                // 序列号溢出，等待下一毫秒
                timestamp = tilNextMillis(lastTimestamp);
            }
        } else {
            // 新的毫秒，序列号重置为0
            sequence = 0L;
        }
        
        lastTimestamp = timestamp;
        
        // 组合ID
        return ((timestamp - epoch) << timestampLeftShift) |
               (datacenterId << datacenterIdShift) |
               (workerId << workerIdShift) |
               sequence;
    }
    
    /**
     * 等待下一毫秒
     */
    private long tilNextMillis(long lastTimestamp) {
        long timestamp = System.currentTimeMillis();
        while (timestamp <= lastTimestamp) {
            timestamp = System.currentTimeMillis();
        }
        return timestamp;
    }
    
    /**
     * 解析ID
     */
    public void parseId(long id) {
        long timestamp = (id >> timestampLeftShift) + epoch;
        long datacenterId = (id >> datacenterIdShift) & maxDatacenterId;
        long workerId = (id >> workerIdShift) & maxWorkerId;
        long sequence = id & sequenceMask;
        
        System.out.println("时间戳：" + timestamp);
        System.out.println("数据中心ID：" + datacenterId);
        System.out.println("机器ID：" + workerId);
        System.out.println("序列号：" + sequence);
    }
    
    public static void main(String[] args) {
        SnowflakeIdGenerator generator = new SnowflakeIdGenerator(1, 1);
        
        for (int i = 0; i < 10; i++) {
            long id = generator.nextId();
            System.out.println(id);
        }
    }
}
```

#### Redis实现分布式锁

**方案1：基础实现**
```java
@Component
public class RedisLock {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * 获取锁
     */
    public boolean lock(String key, String value, long expireSeconds) {
        // SETNX：如果key不存在，则设置成功返回true
        Boolean result = redisTemplate.opsForValue()
            .setIfAbsent(key, value, expireSeconds, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(result);
    }
    
    /**
     * 释放锁
     */
    public void unlock(String key, String value) {
        // 只释放自己持有的锁
        String currentValue = redisTemplate.opsForValue().get(key);
        if (value.equals(currentValue)) {
            redisTemplate.delete(key);
        }
    }
}
```

**AOP切面实现：**
```java
package com.example.common.aspect;

import com.example.common.annotation.RedissonLock;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.reflect.MethodSignature;
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.core.DefaultParameterNameDiscoverer;
import org.springframework.expression.EvaluationContext;
import org.springframework.expression.Expression;
import org.springframework.expression.spel.standard.SpelExpressionParser;
import org.springframework.stereotype.Component;
import java.lang.reflect.Method;
import java.util.concurrent.TimeUnit;

@Aspect
@Component
public class RedissonLockAspect {
    
    @Autowired
    private RedissonClient redissonClient;
    
    private SpelExpressionParser parser = new SpelExpressionParser();
    private DefaultParameterNameDiscoverer nameDiscoverer = new DefaultParameterNameDiscoverer();
    
    @Around("@annotation(redissonLock)")
    public Object around(ProceedingJoinPoint joinPoint, RedissonLock redissonLock) throws Throwable {
        // 解析SpEL表达式
        String key = parseKey(redissonLock.key(), joinPoint);
        String lockKey = "lock:" + key;
        
        RLock lock = redissonClient.getLock(lockKey);
        
        try {
            // 获取锁
            boolean locked = lock.tryLock(
                redissonLock.timeoutSeconds(),
                redissonLock.expireSeconds(),
                TimeUnit.SECONDS
            );
            
            if (!locked) {
                throw new RuntimeException(redissonLock.errorMessage());
            }
            
            // 执行方法
            return joinPoint.proceed();
            
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
    
    /**
     * 解析SpEL表达式
     */
    private String parseKey(String keyExpression, ProceedingJoinPoint joinPoint) {
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        Method method = signature.getMethod();
        
        EvaluationContext context = new StandardEvaluationContext();
        String[] paramNames = nameDiscoverer.getParameterNames(method);
        Object[] args = joinPoint.getArgs();
        
        if (paramNames != null) {
            for (int i = 0; i < paramNames.length; i++) {
                context.setVariable(paramNames[i], args[i]);
            }
        }
        
        Expression expression = parser.parseExpression(keyExpression);
        return expression.getValue(context, String.class);
    }
}
```

**JWT工具类：**
```java
package com.example.common.util;

import io.jsonwebtoken.*;
import io.jsonwebtoken.security.Keys;
import java.security.Key;
import java.util.Date;
import java.util.Map;

public class JwtUtil {
    
    // 密钥（生产环境应使用更安全的密钥）
    private static final Key KEY = Keys.secretKeyFor(SignatureAlgorithm.HS256);
    
    // 过期时间（24小时）
    private static final long EXPIRATION = 24 * 60 * 60 * 1000;
    
    /**
     * 生成Token
     */
    public static String generateToken(String userId, Map<String, Object> claims) {
        return Jwts.builder()
            .setClaims(claims)
            .setSubject(userId)
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + EXPIRATION))
            .signWith(KEY)
            .compact();
    }
    
    /**
     * 解析Token
     */
    public static Claims parseToken(String token) {
        return Jwts.parserBuilder()
            .setSigningKey(KEY)
            .build()
            .parseClaimsJws(token)
            .getBody();
    }
    
    /**
     * 验证Token
     */
    public static boolean validateToken(String token) {
        try {
            parseToken(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
    
    /**
     * 获取用户ID
     */
    public static String getUserId(String token) {
        return parseToken(token).getSubject();
    }
    
    /**
     * 刷新Token
     */
    public static String refreshToken(String token) {
        Claims claims = parseToken(token);
        claims.setIssuedAt(new Date());
        claims.setExpiration(new Date(System.currentTimeMillis() + EXPIRATION));
        
        return Jwts.builder()
            .setClaims(claims)
            .signWith(KEY)
            .compact();
    }
}
```

**JWT拦截器：**
```java
package com.example.gateway.filter;

import com.example.common.util.JwtUtil;
import io.jsonwebtoken.Claims;
import org.springframework.cloud.gateway.filter.GatewayFilterChain;
import org.springframework.cloud.gateway.filter.GlobalFilter;
import org.springframework.core.Ordered;
import org.springframework.http.HttpStatus;
import org.springframework.http.server.reactive.ServerHttpRequest;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ServerWebExchange;
import reactor.core.publisher.Mono;
import java.util.Arrays;
import java.util.List;

@Component
public class JwtAuthFilter implements GlobalFilter, Ordered {
    
    private static final List<String> WHITE_LIST = Arrays.asList(
        "/api/auth/login",
        "/api/auth/register"
    );
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();
        
        // 白名单放行
        if (WHITE_LIST.contains(path)) {
            return chain.filter(exchange);
        }
        
        // 获取Token
        String token = exchange.getRequest().getHeaders().getFirst("Authorization");
        
        if (token == null || token.isEmpty()) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        
        // 验证Token
        if (!JwtUtil.validateToken(token)) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        
        // 解析用户信息
        Claims claims = JwtUtil.parseToken(token);
        String userId = claims.getSubject();
        
        // 将用户信息传递给下游服务
        ServerHttpRequest mutatedRequest = exchange.getRequest().mutate()
            .header("X-User-Id", userId)
            .build();
        
        return chain.filter(exchange.mutate().request(mutatedRequest).build());
    }
    
    @Override
    public int getOrder() {
        return -1;
    }
}
```

### 5.3.5 分库分表（ShardingSphere）

#### 分库分表简介
分库分表是用于解决单库单表数据量过大导致的性能问题。类似于前端的数据分页和虚拟滚动。

**与前端对比：**
| 前端 | 分库分表 |
|------|---------|
| 数据分页 | 分表 |
| 数据分片 | 分库 |
| 虚拟滚动 | 数据路由 |

#### 为什么要分库分表
- 单表数据量过大（超过1000万行）
- 数据库连接数瓶颈
- 读写性能瓶颈
- 单库容量限制

#### 分库分表策略

**垂直拆分：**
- 按业务拆分：用户库、订单库、商品库
- 按字段拆分：大字段单独存储

**水平拆分：**
- 按ID取模：user_id % 4
- 按时间范围：按月/年拆分
- 按哈希范围：一致性哈希

#### ShardingSphere简介
ShardingSphere是Apache开源的分布式数据库中间件，提供分库分表、读写分离等功能。

#### Maven依赖

#### 分库分表注意事项

1. **分片键选择**
   - 选择查询频率高的字段
   - 选择数据分布均匀的字段
   - 避免使用会频繁更新的字段

2. **跨分片查询**
   - 尽量避免跨分片查询
   - 使用冗余字段或宽表
   - 使用ES等搜索引擎

3. **分布式事务**
   - 使用Seata保证跨库事务
   - 使用消息队列实现最终一致性

4. **数据迁移**
   - 使用双写方案
   - 使用ShardingSphere的数据迁移工具
