#### 堆（Heap）详解

堆是JVM中最大的内存区域，用于存储所有对象实例。

```java
/**
 * 堆内存分配示例
 * 通过JVM参数观察堆内存变化
 */
public class HeapDemo {
    
    public static void main(String[] args) {
        // 查看堆内存信息
        Runtime runtime = Runtime.getRuntime();
        long maxMemory = runtime.maxMemory();       // 最大堆内存
        long totalMemory = runtime.totalMemory();   // 当前堆内存
        long freeMemory = runtime.freeMemory();     // 空闲内存
        
        System.out.println("最大堆内存: " + maxMemory / 1024 / 1024 + " MB");
        System.out.println("当前堆内存: " + totalMemory / 1024 / 1024 + " MB");
        System.out.println("可用空闲内存: " + freeMemory / 1024 / 1024 + " MB");
        
        // 对象在堆中的分配
        // 所有new出来的对象都在堆中
        byte[] data1 = new byte[10 * 1024 * 1024];  // 分配10MB
        System.out.println("分配10MB后空闲: " + runtime.freeMemory() / 1024 / 1024 + " MB");
        
        byte[] data2 = new byte[50 * 1024 * 1024];  // 分配50MB
        System.out.println("分配50MB后空闲: " + runtime.freeMemory() / 1024 / 1024 + " MB");
        
        // 触发GC
        data1 = null;
        data2 = null;
        System.gc();
        System.out.println("GC后空闲: " + runtime.freeMemory() / 1024 / 1024 + " MB");
    }
}
```

**堆的分代结构：**

```
堆内存分代模型：

新生代（Young Generation）—— 占堆的1/3
├── Eden区（80%）           —— 新对象首先分配在这里
├── Survivor 0（10%）       —— Minor GC后存活的对象
└── Survivor 1（10%）       —— 与S0交替使用

老年代（Old Generation）—— 占堆的2/3
└── 长期存活的对象（经过多次GC仍然存活）
    ├── 大对象直接进入老年代
    └── 年龄达到阈值的对象（默认15岁）
```

#### 虚拟机栈（VM Stack）详解

每个线程创建时都会分配一个虚拟机栈，存储方法调用的栈帧。

```java
/**
 * 虚拟机栈示例
 * 每个方法调用创建一个栈帧
 */
public class StackDemo {
    
    public static void main(String[] args) {
        methodA();
    }
    
    public static void methodA() {
        int a = 1;           // 局部变量表
        int b = 2;
        methodB(a, b);
    }
    
    public static void methodB(int x, int y) {
        int sum = x + y;
        methodC(sum);
    }
    
    public static void methodC(int value) {
        System.out.println("结果: " + value);
        // 此时调用栈为：methodC -> methodB -> methodA -> main
    }
}

/*
 * 栈帧结构（以methodB为例）：
 * ┌─────────────────────────┐
 * │  局部变量表              │
 * │  [0] x = 1              │
 * │  [1] y = 2              │
 * │  [2] sum = 3            │
 * ├─────────────────────────┤
 * │  操作数栈               │
 * │  [  ]                   │
 * ├─────────────────────────┤
 * │  动态链接 → 方法区引用    │
 * ├─────────────────────────┤
 * │  返回地址 → methodA下一行 │
 * └─────────────────────────┘
 */
```

**栈溢出示例：**

```java
/**
 * StackOverflowError 示例
 * 类比前端：递归组件没有终止条件导致栈溢出
 */
public class StackOverflowDemo {
    
    // 无限递归 —— 类比前端无限递归渲染
    public static void infiniteRecursion() {
        infiniteRecursion();  // 每次调用都会在栈中新增一个栈帧
    }
    
    public static void main(String[] args) {
        try {
            infiniteRecursion();
        } catch (StackOverflowError e) {
            System.out.println("栈溢出！");
            // 类似前端的 "Maximum call stack size exceeded"
        }
    }
}
```

#### 方法区（Method Area）详解

方法区存储类的元数据信息、常量池、静态变量等。

```java
/**

 */
public class MethodAreaDemo {

    // 常量存储在方法区（运行时常量池）

 */
```

### 8.1.2 垃圾回收算法与收集器

#### 如何判断对象可以回收

**1. 引用计数法（简单但有循环引用问题）**

```java
/**
 * 引用计数法问题：循环引用
 * JavaScript使用"标记-清除"解决此问题
 */
public class ReferenceCountDemo {
    private Object partner;  // 互相引用
    
    public static void main(String[] args) {
        ReferenceCountDemo a = new ReferenceCountDemo();
        ReferenceCountDemo b = new ReferenceCountDemo();
        
        a.partner = b;
        b.partner = a;
        
        // a和b的引用计数都为1
        // 即使a和b都不再被外部使用，引用计数也不为0
        // 这就是循环引用问题
        a = null;
        b = null;
        // 引用计数法无法回收，但可达性分析可以
    }
}
```

**2. 可达性分析算法（JVM实际使用）**

```java
/**
 * 可达性分析算法
 * 从GC Roots出发，不可达的对象即为垃圾
 * 
 * GC Roots包括：
 * 1. 虚拟机栈中引用的对象（局部变量）
 * 2. 方法区中静态属性引用的对象
 * 3. 方法区中常量引用的对象
 * 4. 本地方法栈中引用的对象
 * 5. 被同步锁(synchronized)持有的对象
 */
public class ReachabilityDemo {
    
    // 静态变量是GC Root
    private static Object gcRoot;
    
    public static void main(String[] args) {
        Object obj = new Object();  // 局部变量是GC Root可达
        gcRoot = obj;               // 通过GC Root可达，不会被回收
        
        obj = null;                 // 局部变量不再引用
        // 但gcRoot仍然引用，所以对象不会被回收
        
        gcRoot = null;              // GC Root不再引用
        // 对象变为不可达，下次GC时会被回收
    }
}
```

#### 四种引用类型

```java
import java.lang.ref.*;

public class ReferenceDemo {
    
    public static void main(String[] args) {
        // 1. 强引用（Strong Reference）—— 最常见，不会被回收
        Object strongRef = new Object();
        
        // 2. 软引用（Soft Reference）—— 内存不足时回收
        // 适合做缓存
        SoftReference<Object> softRef = new SoftReference<>(new Object());
        Object cached = softRef.get();  // 可能返回null（已被回收）
        
        // 3. 弱引用（Weak Reference）—— 下次GC时回收
        // 适合做观察者模式等临时引用
        WeakReference<Object> weakRef = new WeakReference<>(new Object());
        Object weakObj = weakRef.get();  // 可能返回null
        
        // 4. 虚引用（Phantom Reference）—— 随时可能回收
        // 用于跟踪对象被回收的活动
        ReferenceQueue<Object> queue = new ReferenceQueue<>();
        PhantomReference<Object> phantomRef = new PhantomReference<>(new Object(), queue);
        
        // 实际使用：WeakHashMap
        WeakHashMap<String, Object> weakMap = new WeakHashMap<>();
        weakMap.put("key", new Object());
        // 当key不再被外部强引用时，整个entry会被回收
    }
}
```

#### 垃圾回收算法

```
1. 标记-清除（Mark-Sweep）
   ┌───┬───┬───┬───┬───┬───┬───┐
   │ 用│ 垃圾│ 用│ 垃圾│ 垃圾│ 用│ 用│
   └───┴───┴───┴───┴───┴───┴───┘
   标记后：
   ┌───┬───┬───┬───┬───┬───┬───┐
   │ ✓ │ ✗ │ ✓ │ ✗ │ ✗ │ ✓ │ ✓ │
   └───┴───┴───┴───┴───┴───┴───┘
   清除后（产生碎片）：
   ┌───┬   ┬───┬   ┬   ┬───┬───┐
   │ ✓ │   │ ✓ │   │   │ ✓ │ ✓ │
   └───┴───┴───┴───┴───┴───┴───┘
   缺点：内存碎片

2. 标记-复制（Copying）
   From区：┌───┬───┬───┬───┐    To区：┌───┬───┬───┬───┐
          │ 用│垃圾│ 用│垃圾│         │   │   │   │   │
          └───┴───┴───┴───┘         └───┴───┴───┴───┘
   复制存活对象：
   From区：┌───┬───┬───┬───┐    To区：┌───┬───┬───┬───┐
          │ 用│垃圾│ 用│垃圾│         │ 用│ 用│   │   │
          └───┴───┴───┴───┘         └───┴───┴───┴───┘
   优点：无碎片  缺点：浪费一半空间

3. 标记-整理（Mark-Compact）
   清除后整理：
   ┌───┬───┬───┬───┬   │   │   │
   │ ✓ │ ✓ │ ✓ │   │   │   │   │
   └───┴───┴───┴───┴───┴───┴───┘
   优点：无碎片，空间利用率高  缺点：移动对象开销大

4. 分代收集（Generational Collection）
   新生代 → 标记-复制（对象存活率低，复制成本小）
   老年代 → 标记-清除 或 标记-整理
```

#### 垃圾收集器

**CMS收集器（Concurrent Mark Sweep）—— 追求最短停顿时间**

```
CMS工作流程：
1. 初始标记（STW）     → 标记GC Roots直接关联的对象，速度快
2. 并发标记             → 与用户线程并发执行，遍历对象图
3. 重新标记（STW）     → 修正并发标记期间的变化
4. 并发清除             → 与用户线程并发执行，清除垃圾

STW = Stop The World（暂停所有用户线程）

优点：低停顿时间
缺点：
  - 对CPU资源敏感（并发阶段占用CPU）
  - 无法处理浮动垃圾（重新标记后新产生的垃圾）
  - 内存碎片（使用标记-清除算法）
```

**G1收集器（Garbage First）—— JDK 9默认收集器**

```
G1将堆划分为多个大小相等的Region：

┌───┬───┬───┬───┬───┬───┬───┬───┐
│ E │ E │ O │ O │ E │ H │ E │ O │
└───┴───┴───┴───┴───┴───┴───┴───┘
E = Eden   O = Old   H = Humongous(大对象)

G1工作流程：
1. 初始标记（STW）
2. 并发标记
3. 最终标记（STW）
4. 筛选回收（STW）—— 选择回收价值最高的Region优先回收

特点：
  - 可预测的停顿时间（通过-XX:MaxGCPauseMillis设置）
  - 整体使用标记-整理，局部使用标记-复制
  - 适合大堆内存（6GB+）
```

**ZGC收集器（JDK 15正式发布）—— 超低停顿**

```
ZGC特点：
  - 停顿时间不超过10ms（与堆大小无关）
  - 支持TB级别的堆
  - 使用染色指针和读屏障技术
  
适用场景：
  - 对延迟极度敏感的应用
  - 超大堆内存的应用
  - 实时性要求高的系统
```

**收集器选择建议：**

| 场景 | 推荐收集器 | 说明 |
|------|-----------|------|
| 小型应用（堆<2G） | Serial | 简单高效 |
| Web应用（堆2-8G） | G1 | 平衡吞吐和延迟 |
| 大堆低延迟（堆>8G） | ZGC | 超低停顿 |
| 后台计算（高吞吐） | Parallel | 最大化吞吐量 |

### 8.1.3 类加载机制

#### 类的生命周期

```
加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
         └──────── 连接阶段 ────────┘
```

#### 双亲委派模型

```java
/**
 * 双亲委派模型
 * 
 * 类加载器层次：
 * 
 * Bootstrap ClassLoader（启动类加载器）
 *     │  加载 rt.jar（java.lang.*, java.util.* 等核心类）
 *     ▼
 * Extension ClassLoader（扩展类加载器）
 *     │  加载 ext 目录下的jar包
 *     ▼
 * Application ClassLoader（应用类加载器）
 *     │  加载classpath下的类（我们的代码）
 *     ▼
 * Custom ClassLoader（自定义类加载器）
 * 
 * 双亲委派流程：
 * 1. 收到类加载请求，先委派给父加载器
 * 2. 父加载器无法加载，才自己尝试加载
 * 3. 保证核心类不被篡改（安全机制）
 * 
 * 前端对比：
 * 类似于模块加载器的解析链
 * webpack resolve.modules 的查找顺序
 * 或者Node.js require的查找路径
 */
public class ClassLoaderDemo {
    
    public static void main(String[] args) {
        // 查看类加载器
        ClassLoader loader = ClassLoaderDemo.class.getClassLoader();
        System.out.println("当前类加载器: " + loader);
        // AppClassLoader
        
        System.out.println("父加载器: " + loader.getParent());
        // PlatformClassLoader (JDK 9+) / ExtClassLoader (JDK 8)
        
        System.out.println("祖父加载器: " + loader.getParent().getParent());
        // null (Bootstrap由C++实现，Java中返回null)
        
        // 核心类由Bootstrap加载
        System.out.println("String加载器: " + String.class.getClassLoader());
        // null（Bootstrap加载的类返回null）
    }
}
```

#### 打破双亲委派

```java
/**
 * 自定义类加载器 —— 打破双亲委派
 * 
 * 应用场景：
 * 1. Tomcat：每个Web应用有独立的类加载器
 * 2. OSGi/热部署：运行时替换类
 * 3. SPI机制：JDBC驱动加载
 */
public class CustomClassLoader extends ClassLoader {
    
    private String classPath;
    
    public CustomClassLoader(String classPath) {
        this.classPath = classPath;
    }
    
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        try {
            // 读取.class文件的字节码
            String fileName = classPath + "/" + name.replace('.', '/') + ".class";
            java.io.FileInputStream fis = new java.io.FileInputStream(fileName);
            byte[] bytes = new byte[fis.available()];
            fis.read(bytes);
            fis.close();
            
            // 调用defineClass将字节码转为Class对象
            return defineClass(name, bytes, 0, bytes.length);
        } catch (Exception e) {
            throw new ClassNotFoundException(name, e);
        }
    }
    
    // 使用示例
    public static void main(String[] args) throws Exception {
        CustomClassLoader myLoader = new CustomClassLoader("D:/classes");
        Class<?> clazz = myLoader.loadClass("com.example.MyService");
        Object instance = clazz.getDeclaredConstructor().newInstance();
        System.out.println("加载的类: " + instance.getClass().getName());
        System.out.println("加载器: " + instance.getClass().getClassLoader());
    }
}
```

### 8.1.4 JVM调优参数

#### 常用JVM参数

```bash
# ===== 堆内存参数 =====
-Xms512m                    # 初始堆大小（建议与-Xmx相同，避免动态扩缩）
-Xmx2g                      # 最大堆大小
-Xmn512m                    # 新生代大小（一般为堆的1/3到1/4）

# ===== 栈内存参数 =====
-Xss256k                    # 每个线程的栈大小（默认1MB）

# ===== 方法区参数 =====
-XX:MetaspaceSize=128m      # 元空间初始大小
-XX:MaxMetaspaceSize=256m   # 元空间最大大小

# ===== GC相关参数 =====
-XX:+UseG1GC                # 使用G1收集器
```

### 8.2.1 SQL优化

#### 执行计划分析

```sql
-- 查看执行计划（MySQL）
EXPLAIN SELECT * FROM users WHERE username = 'test';

-- 输出字段说明：
-- id:          查询序号
-- select_type: 查询类型（SIMPLE/PRIMARY/SUBQUERY/UNION）
-- table:       访问的表
-- type:        连接类型（性能从好到差）
--              system > const > eq_ref > ref > range > index > ALL
-- possible_keys: 可能使用的索引
-- key:         实际使用的索引
-- key_len:     索引长度
-- rows:        预计扫描行数（越少越好）
-- Extra:       额外信息
--              Using index（覆盖索引）
--              Using where（需要过滤）
--              Using filesort（需要排序，需优化）
--              Using temporary（使用临时表，需优化）
```

**执行计划示例分析：**

```sql
-- 慢查询示例
EXPLAIN SELECT u.username, o.order_no, o.amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.age > 20 AND o.status = 1
ORDER BY o.amount DESC;

-- 分析结果：
-- users表：type=ALL（全表扫描！需要加索引）
-- orders表：type=ref（使用了索引）
-- Extra: Using filesort（需要额外排序，考虑加索引）

-- 优化方案：
-- 1. users表age字段加索引
ALTER TABLE users ADD INDEX idx_age (age);

-- 2. orders表联合索引
ALTER TABLE orders ADD INDEX idx_user_status_amount (user_id, status, amount);

-- 3. 优化后的查询
EXPLAIN SELECT u.username, o.order_no, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE u.age > 20 AND o.status = 1
ORDER BY o.amount DESC;
```

#### 索引优化

```sql
-- ===== 索引类型 =====

-- 1. 普通索引
CREATE INDEX idx_username ON users(username);

-- 2. 唯一索引
CREATE UNIQUE INDEX uk_email ON users(email);

-- 3. 联合索引（最左前缀原则）
CREATE INDEX idx_name_age_status ON users(username, age, status);
-- 可以匹配的查询：
-- WHERE username = 'test'                     ✓
-- WHERE username = 'test' AND age = 25        ✓
-- WHERE username = 'test' AND age = 25 AND status = 1  ✓
-- WHERE age = 25                              ✗（缺少最左列）
-- WHERE age = 25 AND status = 1               ✗（缺少最左列）

-- 4. 覆盖索引（避免回表）
-- 如果索引包含了查询需要的所有字段，不需要回表查数据
CREATE INDEX idx_covering ON users(username, age, email);
-- 这个查询可以使用覆盖索引：
SELECT username, age, email FROM users WHERE username = 'test';
-- Extra显示：Using index

-- 5. 前缀索引（节省空间）
CREATE INDEX idx_email_prefix ON users(email(10));

-- ===== 索引失效场景 =====

-- 1. 对索引列使用函数
SELECT * FROM users WHERE UPPER(username) = 'TEST';  -- 索引失效
-- 优化：存储时就统一格式

-- 2. 隐式类型转换
SELECT * FROM users WHERE phone = 13800138000;  -- phone是VARCHAR，传入数字
-- 优化：传入字符串 WHERE phone = '13800138000'

-- 3. LIKE以%开头
SELECT * FROM users WHERE username LIKE '%test';  -- 索引失效
SELECT * FROM users WHERE username LIKE 'test%';  -- 索引有效

-- 4. OR条件（部分列没有索引）
SELECT * FROM users WHERE username = 'test' OR age = 25;  -- 如果age没有索引则全表扫描

-- 5. NOT IN / NOT EXISTS
SELECT * FROM users WHERE id NOT IN (SELECT user_id FROM orders);
-- 优化为 LEFT JOIN：
SELECT u.* FROM users u LEFT JOIN orders o ON u.id = o.user_id WHERE o.user_id IS NULL;

-- 6. 不等于
SELECT * FROM users WHERE status != 1;  -- 可能索引失效

-- ===== 索引设计原则 =====
-- 1. 选择性高的列优先（区分度高的列）
-- 2. 频繁查询的列加索引
-- 3. 联合索引注意列顺序（区分度高的在前）
-- 4. 避免过多索引（影响写入性能）
-- 5. 长字符串考虑前缀索引
```

#### SQL优化实战

```sql
-- ===== 优化1：避免SELECT * =====
-- 慢
SELECT * FROM users WHERE age > 20;
-- 快（减少数据传输量，可能使用覆盖索引）
SELECT id, username, email FROM users WHERE age > 20;

-- ===== 优化2：分页优化 =====
-- 深分页问题（越往后越慢）
SELECT * FROM users LIMIT 1000000, 10;  -- 扫描1000010行，丢弃1000000行

-- 优化方案1：延迟关联
SELECT u.* FROM users u
INNER JOIN (SELECT id FROM users ORDER BY id LIMIT 1000000, 10) tmp
ON u.id = tmp.id;

-- 优化方案2：游标分页（推荐）
-- 前端传入上一页最后一条的id
SELECT * FROM users WHERE id > #{lastId} ORDER BY id LIMIT 10;

-- ===== 优化3：COUNT优化 =====
-- 慢
SELECT COUNT(*) FROM users WHERE status = 1;
-- 如果只需要判断是否有数据
SELECT 1 FROM users WHERE status = 1 LIMIT 1;

-- ===== 优化4：JOIN优化 =====
-- 小表驱动大表
-- 确保JOIN字段有索引
-- 避免在JOIN条件中使用函数

-- ===== 优化5：子查询优化 =====
-- 慢（相关子查询）
SELECT * FROM users WHERE id IN (SELECT user_id FROM orders WHERE amount > 100);
-- 快（改为JOIN）
SELECT DISTINCT u.* FROM users u INNER JOIN orders o ON u.id = o.user_id WHERE o.amount > 100;

-- ===== 优化6：批量操作 =====
-- 逐条插入（慢）
INSERT INTO users (username, email) VALUES ('a', 'a@test.com');
INSERT INTO users (username, email) VALUES ('b', 'b@test.com');
INSERT INTO users (username, email) VALUES ('c', 'c@test.com');

-- 批量插入（快）

('b', 'b@test.com'),
('c', 'c@test.com');
```

#### 缓存常见问题与解决方案

```java
/**
 * 缓存三大问题及解决方案
 */

// ===== 1. 缓存穿透：查询不存在的数据 =====
// 问题：每次都穿透缓存到数据库
// 解决：缓存空值
@Service
public class UserServiceWithPenetrationFix {
    
    @Cacheable(key = "#id", unless = "#result != null")
    public User findById(Long id) {
        User user = userMapper.selectById(id);
        if (user == null) {
            // 缓存空值，设置较短过期时间
            // 防止缓存穿透
            return null;  // 配合unless不缓存null，需要手动处理
        }
        return user;
    }
    
    // 使用布隆过滤器（Bloom Filter）预防
    // RedisBloom模块可以在缓存层判断key是否可能存在
}

// ===== 2. 缓存击穿：热点key过期，大量请求打到数据库 =====
// 解决：互斥锁（分布式锁）
@Service
public class UserServiceWithBreakdownFix {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    public User findByIdWithLock(Long id) {
        String key = "user:" + id;
        
        // 先查缓存
        String cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return JSON.parseObject(cached, User.class);
        }
        
        // 获取分布式锁
        String lockKey = "lock:user:" + id;
        Boolean locked = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", Duration.ofSeconds(10));
        
        if (Boolean.TRUE.equals(locked)) {
            try {
                // 双重检查
                cached = redisTemplate.opsForValue().get(key);
                if (cached != null) {
                    return JSON.parseObject(cached, User.class);
                }
                
                // 查数据库
                User user = userMapper.selectById(id);
                redisTemplate.opsForValue().set(key, JSON.toJSONString(user), Duration.ofHours(1));
                return user;
            } finally {
                redisTemplate.delete(lockKey);
            }
        } else {
            // 获取锁失败，短暂休眠后重试
            try { Thread.sleep(50); } catch (InterruptedException e) {}
            return findByIdWithLock(id);
        }
    }
}

// ===== 3. 缓存雪崩：大量缓存同时过期 =====
// 解决：过期时间加随机值
@Service
public class UserServiceWithAvalancheFix {
    
    private final Random random = new Random();
    
    public void cacheUser(User user) {
        String key = "user:" + user.getId();
        // 基础时间 + 随机时间（避免同时过期）
        int baseTtl = 3600;  // 1小时
        int randomTtl = random.nextInt(600);  // 0-10分钟随机
        redisTemplate.opsForValue().set(key, 
            JSON.toJSONString(user), 
            Duration.ofSeconds(baseTtl + randomTtl));
    }
}
```

```java
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;
import org.springframework.stereotype.Component;

/**
 * 限流算法实现
 * 
 * 前端对比：
 * 类似于请求队列、防抖节流的概念
 * 但限流是在服务端控制请求速率
 */

// ===== 1. 固定窗口限流 =====
@Component
public class FixedWindowRateLimiter {
    
    // key -> [计数器, 窗口开始时间]
    private final ConcurrentHashMap<String, long[]> counters = new ConcurrentHashMap<>();
    
    public boolean tryAcquire(String key, int limit, long windowMs) {
        long now = System.currentTimeMillis();
        
        counters.putIfAbsent(key, new long[]{0, now});
        long[] counter = counters.get(key);
        
        // 窗口过期，重置
        if (now - counter[1] > windowMs) {
            counter[0] = 0;
            counter[1] = now;
        }
        
        // 判断是否超限
        if (counter[0] < limit) {
            counter[0]++;
            return true;
        }
        return false;
    }
}

// ===== 2. 滑动窗口限流 =====
@Component
public class SlidingWindowRateLimiter {
    
    private final ConcurrentHashMap<String, LinkedList<Long>> requestTimes = new ConcurrentHashMap<>();
    
    public boolean tryAcquire(String key, int limit, long windowMs) {
        long now = System.currentTimeMillis();
        
        requestTimes.putIfAbsent(key, new LinkedList<>());
        LinkedList<Long> times = requestTimes.get(key);
        
        synchronized (times) {
            // 移除窗口外的记录
            while (!times.isEmpty() && now - times.getFirst() > windowMs) {
                times.removeFirst();
            }
            
            if (times.size() < limit) {
                times.addLast(now);
                return true;
            }
            return false;
        }
    }
}
```

```java
public @interface RateLimit {
    int limit() default 100;         // 限流数量
    long window() default 60;        // 时间窗口（秒）
    String key() default "";         // 限流key（默认使用方法名）
    RateLimitType type() default RateLimitType.IP;  // 限流维度
}

public enum RateLimitType {
    IP,      // 按IP限流
    USER,    // 按用户限流
    GLOBAL   // 全局限流

// AOP实现
@Aspect
@Component
public class RateLimitAspect {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Around("@annotation(rateLimit)")
    public Object around(ProceedingJoinPoint point, RateLimit rateLimit) throws Throwable {
        String key = "rate_limit:" + rateLimit.key();
        
        // 根据限流维度设置key
        switch (rateLimit.type()) {
            case IP:
                key += ":" + getClientIp();
                break;
            case USER:
                key += ":" + getCurrentUserId();
                break;
        }
        
        Long count = redisTemplate.opsForValue().increment(key);
        if (count == 1) {
            redisTemplate.expire(key, Duration.ofSeconds(rateLimit.window()));
        }
        
        if (count > rateLimit.limit()) {
            throw new RuntimeException("请求过于频繁，请稍后再试");
        }
        
        return point.proceed();
    }
}
```

```java
    private double reduction;
```

```java
public abstract class AbstractExportService<T> {

    public final void export(List<T> data, String filename) {
        // 1. 验证数据
        validate(data);
        
        // 2. 转换数据
        List<Map<String, Object>> rows = convert(data);

        // 5. 记录日志
        log(filename, url, data.size());
    }
    
    private void validate(List<T> data) {
        if (data == null || data.isEmpty()) {
            throw new IllegalArgumentException("导出数据不能为空");
        }
    }
    
    protected abstract List<Map<String, Object>> convert(List<T> data);
    
    protected abstract byte[] generateFile(List<Map<String, Object>> rows);
    
    private String upload(byte[] bytes, String filename) {
        // 上传逻辑

    private void log(String filename, String url, int count) {
        System.out.printf("导出完成: %s, 共%d条, 地址: %s%n", filename, count, url);
    }
}
```

### 8.3.2 DDD领域驱动设计

#### DDD核心概念

```
DDD分层架构：

┌─────────────────────────────────────────┐
│           用户接口层（Interface）          │
│    Controller, DTO, VO, 参数校验         │
├─────────────────────────────────────────┤
│           应用层（Application）           │
│    Service, 事务管理, 事件发布            │
├─────────────────────────────────────────┤
│           领域层（Domain）               │
│    Entity, ValueObject, Aggregate        │
│    DomainService, Repository接口         │
├─────────────────────────────────────────┤
│           基础设施层（Infrastructure）     │
│    Repository实现, 数据库, 消息队列       │
│    外部服务调用, 配置                     │
└─────────────────────────────────────────┘

前端对比：
- 前端分层：UI层 → 业务逻辑层 → 数据层 → API层
- DDD分层思想类似，但更加严谨
- 领域层相当于前端的业务逻辑核心
```

```java
    public void pay() {
        if (this.status != OrderStatus.PENDING) {
            throw new BusinessException("订单状态不允许支付");
        }
        this.status = OrderStatus.PAID;
        // 领域事件
        registerEvent(new OrderPaidEvent(this.orderId));
    }
    
    public void cancel() {
        if (this.status == OrderStatus.SHIPPED) {
            throw new BusinessException("已发货订单不能取消");
        }
        this.status = OrderStatus.CANCELLED;
    }
    
    public void addItem(Product product, int quantity) {
        if (this.status != OrderStatus.PENDING) {
            throw new BusinessException("只能修改待支付订单");
        }
        OrderItem item = new OrderItem(product.getProductId(), product.getName(), 
                                        product.getPrice(), quantity);
        this.items.add(item);
        recalculateAmount();
    }
    
    private void recalculateAmount() {
        this.totalAmount = items.stream()
            .map(OrderItem::getSubtotal)
            .reduce(Money.ZERO, Money::add);
    }
}

// ===== 2. 值对象（Value Object）—— 无唯一标识，不可变 =====
public class Money {
    public static final Money ZERO = new Money(BigDecimal.ZERO);
    
    private final BigDecimal amount;
    private final Currency currency;
    
    public Money(BigDecimal amount, Currency currency) {
        if (amount.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalArgumentException("金额不能为负数");
        }
        this.amount = amount;
        this.currency = currency;
    }
    
    public Money(BigDecimal amount) {
        this(amount, Currency.CNY);
    }
    
    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("不同币种不能相加");
        }
        return new Money(this.amount.add(other.amount), this.currency);
    }
    
    public Money multiply(int quantity) {
        return new Money(this.amount.multiply(BigDecimal.valueOf(quantity)), this.currency);
    }
    
    // equals和hashCode基于值（而非引用）
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Money money = (Money) o;
        return amount.compareTo(money.amount) == 0 && currency.equals(money.currency);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(amount.stripTrailingZeros(), currency);
    }
}
```

### 8.3.4 微服务拆分原则

#### 拆分原则

```
微服务拆分原则：

1. 单一职责原则（SRP）
   - 每个服务只负责一个业务领域
   - 类比前端：组件单一职责

2. 高内聚低耦合
   - 相关功能放在同一个服务
   - 服务间通过API通信

3. 以业务领域为边界（DDD限界上下文）
   - 电商系统拆分示例：
     ├── 用户服务（注册、登录、用户信息）
     ├── 商品服务（商品管理、分类、库存）
     ├── 订单服务（下单、支付、退款）
     ├── 营销服务（优惠券、活动、积分）
     ├── 支付服务（支付渠道、对账）
     └── 物流服务（物流跟踪、签收）

4. 数据独立
   - 每个服务有自己的数据库
   - 不直接访问其他服务的数据库

5. 渐进式拆分
   - 不要一开始就过度拆分
   - 从单体开始，逐步拆分
```

### 8.3.5 高可用架构设计

#### 核心策略

```
高可用架构策略：

1. 冗余（Redundancy）
   - 多实例部署
   - 数据库主从复制
   - 类比前端：CDN多节点

2. 熔断（Circuit Breaker）
   - 类比前端：请求超时重试、错误降级
   - 当下游服务异常时快速失败

3. 限流（Rate Limiting）
   - 类比前端：防抖节流
   - 保护系统不被流量冲垮

4. 降级（Degradation）
   - 类比前端：骨架屏、默认数据
   - 非核心功能暂时不可用

5. 异步（Asynchronous）
   - 消息队列解耦
   - 类比前端：Web Worker、异步渲染
```

#### 熔断器实现

```java
import io.github.resilience4j.circuitbreaker.CircuitBreaker;
import io.github.resilience4j.circuitbreaker.CircuitBreakerConfig;
import io.github.resilience4j.circuitbreaker.CircuitBreakerRegistry;

import java.time.Duration;

/**
 * Resilience4j熔断器
 * 
 * 前端对比：
 * 类似于Axios的请求重试和超时配置
 * 但熔断器更加智能
 */
public class CircuitBreakerDemo {
    
    // 熔断器配置
    CircuitBreakerConfig config = CircuitBreakerConfig.custom()
        .failureRateThreshold(50)                    // 失败率阈值50%
        .slowCallRateThreshold(80)                   // 慢调用比例阈值80%
        .slowCallDurationThreshold(Duration.ofSeconds(2))  // 慢调用定义：2秒
        .waitDurationInOpenState(Duration.ofSeconds(30))   // 熔断打开后等待30秒
        .permittedNumberOfCallsInHalfOpenState(10)   // 半开状态允许10个请求
        .minimumNumberOfCalls(20)                    // 最少20次调用后才计算失败率
        .build();
    
    CircuitBreaker circuitBreaker = CircuitBreaker.of("userService", config);
    
    // 使用熔断器
    public User getUser(Long userId) {
        return CircuitBreaker.decorateSupplier(circuitBreaker, () -> {
            return userService.getUser(userId);
        }).recover(throwable -> {
            // 降级处理
            return User.defaultUser();
        }).get();
    }
}

/*
 * 熔断器状态机：
 * 
 * CLOSED（关闭）──失败率超阈值──→ OPEN（打开）
 *     ↑                              │
 *     │                         等待30秒
 *     │                              ↓
 *     └──成功率达标──── HALF_OPEN（半开）
 * 
 * CLOSED：正常状态，请求正常通过
 * OPEN：熔断状态，直接返回降级结果
 * HALF_OPEN：探测状态，允许少量请求探测下游是否恢复
 */
```

```java
/**
 * Spring事务传播机制
 * 
 * 前端对比：
 * 类似于Promise链中的错误处理
 * 或者组件树中的事件冒泡
 */

@Service
public class TransactionDemo {
    
    @Autowired
    private UserService userService;
    
    @Autowired
    private LogService logService;
    
    // REQUIRED（默认）：有事务就加入，没有就新建
    @Transactional(propagation = Propagation.REQUIRED)
    public void methodA() {
        // 在事务中执行
        userService.updateUser();
    }
    
    // REQUIRES_NEW：总是新建事务，挂起当前事务
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void methodB() {
        // 独立事务，不受外部事务影响
        logService.addLog("操作日志");
    }
    
    // NESTED：嵌套事务（基于Savepoint）
    @Transactional(propagation = Propagation.NESTED)
    public void methodC() {
        // 如果外部事务回滚，嵌套事务也回滚
        // 但嵌套事务回滚，不影响外部事务
    }
    
    // 实际场景：下单流程
    @Transactional
    public void placeOrder(OrderRequest request) {
        try {
            // 创建订单（主事务）
            createOrder(request);
            
            // 扣减库存（加入当前事务）
            deductStock(request);
            
            // 记录日志（独立事务，REQUIRES_NEW）
            // 即使订单失败，日志也要记录
            logService.addLog("下单操作");
            
        } catch (Exception e) {
            // 订单和库存一起回滚
            // 但日志不回滚（独立事务）
            throw new BusinessException("下单失败", e);
        }
    }
}
```

### 8.4.2 Spring Boot自动配置源码

#### 自动配置原理

```java
/**
 * Spring Boot自动配置原理
 * 
 * 核心注解链：
 * @SpringBootApplication
 *   ├── @SpringBootConfiguration → @Configuration
 *   ├── @EnableAutoConfiguration → @Import(AutoConfigurationImportSelector.class)
 *   └── @ComponentScan
 * 
 * 自动配置流程：
 * 1. @EnableAutoConfiguration触发AutoConfigurationImportSelector
 * 2. 读取META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
 *    （JDK 8及之前是 META-INF/spring.factories）
 * 3. 获取所有自动配置类
 * 4. 通过条件注解过滤（@ConditionalOnClass, @ConditionalOnProperty等）
 * 5. 加载符合条件的配置类
 * 
 * 前端对比：
 * 类似于webpack/vite的插件系统
 * 通过配置文件自动加载和注册插件
 */

// ===== 自定义自动配置 =====

// 1. 定义配置属性
@ConfigurationProperties(prefix = "my.service")
public class MyServiceProperties {
    private String prefix = "[MyService]";
    private String suffix = "";
    private boolean enabled = true;
    
    // getter/setter
}

// 2. 定义服务类
public class MyService {
    private MyServiceProperties properties;
    
    public MyService(MyServiceProperties properties) {
        this.properties = properties;
    }
    
    public String wrap(String content) {
        return properties.getPrefix() + content + properties.getSuffix();
    }
}

// 3. 自动配置类
@AutoConfiguration
@ConditionalOnClass(MyService.class)  // classpath下有这个类才生效
@ConditionalOnProperty(prefix = "my.service", name = "enabled", havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(MyServiceProperties.class)
public class MyServiceAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean  // 容器中不存在时才创建
    public MyService myService(MyServiceProperties properties) {
        return new MyService(properties);
    }
}

// 4. 注册自动配置
// 在 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 中添加：
// com.example.MyServiceAutoConfiguration

// 5. 使用方只需引入依赖并配置
// application.yml:
// my:
//   service:
//     prefix: "[Hello]"
//     suffix: "[World]"
```

### 8.4.3 MyBatis源码

#### 核心执行流程

```java
/**
 * MyBatis核心执行流程
 * 
 * 前端对比：
 * 类似于Axios请求拦截器链
 * Configuration → 拦截器链 → 执行器 → 结果处理
 * 
 * 核心组件：
 * 1. SqlSessionFactory：创建SqlSession的工厂
 * 2. SqlSession：与数据库交互的会话
 * 3. Executor：执行器（Simple/Reuse/Batch）
 * 4. StatementHandler：SQL语句处理器
 * 5. ParameterHandler：参数处理器
 * 6. ResultSetHandler：结果集处理器
 * 7. Interceptor：拦截器（插件机制）
 * 
 * 执行流程：
 * SqlSession → Executor → StatementHandler → ParameterHandler → JDBC
 *                                    ↓
 *                            ResultSetHandler → 返回结果
 */

// ===== MyBatis插件原理 =====
// MyBatis允许拦截四大对象的方法：
// 1. Executor（update, query, commit, rollback等）
// 2. StatementHandler（prepare, parameterize, batch, update, query等）
// 3. ParameterHandler（setParameter）
// 4. ResultSetHandler（handleResultSets）

// 示例：分页插件原理
@Intercepts({
    @Signature(
        type = StatementHandler.class,
        method = "prepare",
        args = {Connection.class, Integer.class}
    )
})
public class PageInterceptor implements Interceptor {
    
    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        // 1. 获取StatementHandler
        StatementHandler handler = (StatementHandler) invocation.getTarget();
        
        // 2. 获取原始SQL
        BoundSql boundSql = handler.getBoundSql();
        String originalSql = boundSql.getSql();
        
        // 3. 获取分页参数
        Page<?> page = PageContext.getCurrentPage();
        
        if (page != null) {
            // 4. 改写SQL（添加LIMIT）
            String pageSql = originalSql + " LIMIT " + page.getOffset() + ", " + page.getSize();
            
            // 5. 通过反射修改SQL
            ReflectUtil.setFieldValue(boundSql, "sql", pageSql);
        }
        
        // 6. 执行原方法
        return invocation.proceed();
    }
}
```
