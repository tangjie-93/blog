# `RAG` 团队培训手册

面向能读 `Python`、`HTTP` 和数据库文档的工程师。目标是能解释一次回答为什么正确或失败，并搭出带证据、可评测、可运维的知识库问答系统。

```text
01 原理 → 02 数据摄取 → 03 检索重排 → 04 生成引用
                      ↓
                 05 最小实战
                      ↓
06 评估 → 07 生产化 → 08 高级模式 → 09 培训计划
```

| 文档 | 产出 | 验收 |
|---|---|---|
| [01 原理](./01-RAG原理地图.md) | 系统链路图 | 解释召回失败 |
| [02 数据摄取](./02-数据摄取.md) | 增量文档管线 | 删除旧版不残留 |
| [03 检索与重排](./03-检索与重排.md) | dense/`BM25`/hybrid 选型 | 定位 Recall 下降 |
| [04 生成与引用](./04-生成与引用.md) | 有证据回答 | 无证据拒答 |
| [05 最小实战](./05-最小实战.md) | 本地 Demo | ingest/ask/test |
| [06 评估](./06-评估.md) | 回归报告 | 变更可比较 |

先使用 [05 最小实战](./05-最小实战.md) 跑通虚构的公司报销制度，再回到前四章解释实现。生产项目必须补齐 [06 评估](./06-评估.md) 和 [07 生产化](./07-生产化.md)；没有评估集和权限过滤，不应把 Demo 当上线方案。

## 1、提交标准

每个小组提交一张链路图、一组 20 条带答案的问题、一份失败案例和一份可回滚的索引变更记录。培训中优先问“证据在哪里、版本是什么、用户是否有权限”。
