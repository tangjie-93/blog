## 1. 本期范围

[返回专题首页](./)。采样日期为 `2026-11-08`，以北京时间日期展示，快照中的逐条采样时间使用带时区的时间戳。

- **高星门槛**：`stargazers_count >= 10000`。
- **发现方式**：官方仓库搜索接口、多组主题与关键词、已知项目的官方仓库补查。
- **主要对象**：与大模型 `Agent` 的构建、运行、工具调用、状态、应用或学习直接相关的仓库。
- **人工主榜**：`144` 个，分为 `8` 类；另有 `2` 个低于门槛的观察项目。
- **候选集合**：去重后 `574` 个，包含关键词误命中和未收录项目；不能把候选总数当成合格项目数。

本期没有把所有候选逐一运行或做完整源码审查。对通用数据库、传统监控 `Agent`、普通 `UI` 组件、泛 `AI` 资料和只在描述中提及 `Agent` 的项目，不因为检索命中就直接放入主榜。仍可能有符合条件却未被收录的项目。

## 2. 检索如何复现

实际完成分页的检索如下，使用 `sort=stars`、`order=desc`、`per_page=100`，保留归档仓库以便识别历史项目：

| 查询 | 接口报告数量 | 本期读取页数 |
| --- | ---: | ---: |
| `topic:ai-agents stars:>=10000 fork:false` | `147` | `2` |
| `agent in:name,description stars:>=10000 fork:false` | `446` | `5` |
| `topic:ai-agent stars:>=10000 fork:false` | `62` | `1` |
| `topic:mcp stars:>=10000 fork:false` | `153` | `2` |

每次成功响应均保存查询地址、返回数量、采样时间及 `incomplete_results`；本期这些已保存响应的该字段均为 `false`。表中数量相互重叠，不能相加当作项目数。分页不是事务快照，采样期间星数变化也可能影响排序。

示例查询：

```sh
curl --fail --get 'https://api.github.com/search/repositories' \
  --data-urlencode 'q=topic:ai-agents stars:>=10000 fork:false' \
  --data-urlencode 'sort=stars' \
  --data-urlencode 'order=desc' \
  --data-urlencode 'per_page=100' \
  --data-urlencode 'page=1'
```

搜索页不能覆盖未填写标签或描述中没出现关键词的项目，所以补查了 `OpenClaw`、`n8n`、`AutoGPT`、`OpenHands`、`AI SDK` 等官方仓库。仓库直接查询示例：

```sh
curl --fail 'https://api.github.com/repos/mastra-ai/mastra'
```

本期也尝试过 `topic:llm` 和 `topic:agentic-ai` 查询，但收到 `HTTP 403` 响应，没有计入已完成的搜索范围。`MCP` 查询首次失败后已重新获取并完成分页。保留这个边界比把失败请求当成“没有项目”更准确。

官方规则与返回字段参考：[搜索仓库接口](https://docs.github.com/en/rest/search/search#search-repositories)、[读取仓库接口](https://docs.github.com/en/rest/repos/repos#get-a-repository)、[REST API 限流说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。

## 3. 去重和分类

使用 `API` 返回的规范仓库名归一化，并用仓库 `id` 检查同一仓库的重复记录。遇到重命名或转移，不把旧地址和新地址计为两个项目。

例如 `google/A2A` 现转向 `a2aproject/A2A`，`jlowin/fastmcp` 现转向 `PrefectHQ/fastmcp`；快照和主表均使用当前接口返回的规范名字。

每个项目只进入一个主要类别。分类是本站编辑判断，并不直接照搬仓库标签。主表内部按本次星数从高到低排列，没有跨类别总冠军，也没有根据营销口号给项目打分。

## 4. 快照字段怎么理解

[下载本期 JSON 快照](/agent-projects/2026-11-08-snapshot.json)。这是供核对和再次整理的数据，不是自动更新服务。

| 字段 | 含义 |
| --- | --- |
| `id` / `full_name` / `html_url` | 官方仓库标识、规范名称和地址 |
| `stargazers_count` | 采样时关注数，不是实时值 |
| `language` | `GitHub` 统计的主要语言；不代表全部语言绑定 |
| `archived` | 仓库归档字段；为否也可能已宣布停止维护 |
| `pushed_at` | 仓库最近推送时间；不能直接证明有效维护或发版 |
| `license_spdx` | `GitHub` 识别出的许可标识；空值或 `NOASSERTION` 需要读实际文本 |
| `retrieved_at` / `source_api` | 本地取得该条数据的时间及对应官方接口 |
| `included_in_topic` / `category` | 是否进入人工主榜及主要分类 |
| `editorial_note` | 本站整理的中文用途与阅读建议 |
| `watchlist` | 低于阈值、但与本文选型相关的观察项目标记 |
| `status_note` / `status_source` | 对停止维护、教学替代或产品许可的补充说明与来源 |

许可证字段只是元数据，不是完整授权判断。单仓库可能包含多种许可或商业部分；需要复用代码时回到该仓库实际文件核对。本专题没有将 `NOASSERTION` 自动改写为 `MIT`，也没有把“公开可见”统一称为“开源”。

## 5. 手动更新流程

1. 先保存当前快照，重新执行上面的检索并读取所有结果页；若单个查询达到接口检索上限，需要拆分星数区间。
2. 补查已收录项目，检查删除、转移、归档和低于阈值的情况；请求失败时保留旧值并记录失败，不能写成 `0`。
3. 对新候选阅读官方说明，确认它属于框架、应用、工具、技能还是资料；不直接复制宣传性效果结论。
4. 同批更新数据文件、分类表、观察名单、日期与数量；保留旧快照，新建日期文件。
5. 检查官方状态说明是否与归档字段不同。推荐使用的候选还要核对当前文档、发布信息和运行条件。
6. 在仓库根目录运行导航、文章与构建检查，通过后再发布。

```sh
node --test tests/navigation.test.mjs tests/article-outline.test.mjs
npm run build
```

构建检查覆盖本地页面、链接和资源，不会证明外部仓库的软件能安装或运行。手动更新时还应打开新增项目的官方链接核对。

## 6. 当前未包含的能力

当前没有定时任务、后台管理、增长速度榜或逐项目运行测试。仅凭一次快照无法计算真实的日增长和周增长，也不能据此评出“增长最快”。需要持续跟踪时，应先积累多期快照，再计算可核对的差值。
