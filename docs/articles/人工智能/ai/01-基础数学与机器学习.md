# 01. 基础数学与机器学习

## 1. 先有直觉：机器学习在学什么

传统程序由人写规则，机器学习则让程序从例子调整参数。以预测处理工单所需时间为例，我们给模型工单特征 `x` 和已知时长 `y`，让它形成预测 `ŷ`，再根据偏差修改参数。

这里没有“自动理解业务”的保证。模型能找到训练数据中的规律，也可能记住工单编号，或者利用只有事后才知道的“关闭时间”作弊。

先分清三个东西：

| 对象 | 含义 | 例子 |
| --- | --- | --- |
| 参数 θ | 从训练中学习 | 线性模型的斜率 w 和截距 b |
| 超参数 | 由实验者配置 | 学习率、训练步数、正则强度 |
| 数据 | 学习的例子及目标 | 特征、标签、采集时间和来源 |

本章的验收目标：不用“模型自己学会了”这种说法，解释一次参数更新；并说明为什么训练误差低不代表上线表现好。

## 2. 一次更新：把抽象公式变成数字

<AiConcept mode="training" />

取一个非常小的模型：`ŷ = wx + b`。设 `x=2，y=4，w=1，b=0`，定义平方损失的一半：

```text
ŷ = 1×2 + 0 = 2
L = (ŷ−y)² / 2 = 2
∂L/∂w = (ŷ−y)×x = −4
∂L/∂b = ŷ−y = −2
```

学习率 `η=0.1` 时，两个参数使用**同一次前向计算**的梯度同时更新：

```text
w_new = 1 − 0.1×(−4) = 1.4
b_new = 0 − 0.1×(−2) = 0.2
ŷ_new = 1.4×2 + 0.2 = 3
L_new = (3−4)² / 2 = 0.5
```

负梯度给出局部下降方向，不是通往全局最优的导航。对同一样本，若学习率改为 `1`，会得到 `w=5，b=2，ŷ=12，L=32`，比原来更糟。

**重点：**梯度告诉你“往哪边微调”，学习率决定“迈多大一步”；步子过大时，局部近似不再有效。

## 3. 向量与矩阵：为什么到处都是 shape

### 3.1 从特征表到张量

假设每条工单有两个特征：问题长度、附件数。三个样本组成矩阵 `X [3,2]`；将两个特征映射成两个输出的权重为 `W [2,2]`；预测是 `XW+b [3,2]`。

手算一个样本：

```text
x = [1, 2]
W = [[0.2, −0.1],
     [0.5,  0.3]]
b = [0.1, 0.2]
xW+b = [1×0.2+2×0.5+0.1, 1×(−0.1)+2×0.3+0.2]
     = [1.3, 0.7]
```

矩阵乘法的内侧维度必须一致，`[n,d] @ [d,k] → [n,k]`。写模型前先写 shape，比遇到报错反复改转置更有效。

### 3.2 内积和余弦：相关性从何而来

内积 `a·b = Σ aᵢbᵢ` 同时受方向和长度影响。余弦相似度把长度除掉：

```text
cos(a,b) = (a·b) / (||a||₂ ||b||₂)
a=[1,0]，b=[2,0]：内积=2，余弦=1
a=[1,0]，c=[0,1]：内积=0，余弦=0
```

零向量的余弦没有定义，需要显式处理。只有经过训练、把相关性编码进方向的表示，余弦才可能对应有用的语义相似；不是把任意文本变成几个数字就能检索。

### 3.3 特征缩放为何影响训练

如果“长度”范围是几千，而“附件数”通常小于十，两个参数的梯度尺度可能差很多。标准化可改善优化条件，但均值和标准差只能在训练集拟合，再应用到验证与测试集。

PCA 保留高方差方向，不保证保留业务相关信息。训练更快或二维图更漂亮，都不能代替下游指标。

## 4. 概率与损失：为什么不直接优化正确率

### 4.1 正确率没有告诉你错得多离谱

若正确类别是“需人工处理”，模型 A 给它概率 `0.51`，模型 B 给 `0.99`，二者都预测正确，准确率相同；但交叉熵分别约为：

```text
L_A = −ln(0.51) ≈ 0.673
L_B = −ln(0.99) ≈ 0.010
```

若正确类别概率只有 `0.01`，损失约为 `4.605`。交叉熵给出了连续的训练信号，能反映模型给正确类别多少概率。

对于目标分布 p 与预测分布 q：`CE(p,q)=−Σ pᵢ ln qᵢ`。标签为 one-hot 时，只剩正确类别的一项。数值实现通常直接使用 logits 和稳定的 log-softmax，避免 `ln(0)`。

### 4.2 概率不是事实保证

`P(y|x)` 是模型对标签的条件分布。给出 `0.9` 不代表这种预测在真实环境中就有 90% 正确率；需要用可靠性分桶检查校准。

熵 `H(p)=−Σpᵢlnpᵢ` 衡量分布不确定性。分布尖锐可以表示模型确信，也可以表示它**确信地错了**。后续语言模型的 token 概率同样不能直接当作回答可信度。

## 5. 反向传播与优化器：自动化的是什么

反向传播使用链式法则：如果 `x → z → a → L`，那么：

```text
dL/dx = (dL/da) × (da/dz) × (dz/dx)
```

自动微分框架记录计算图，再沿图传播导数。它替你算梯度，但不替你确认标签正确、损失合理或测试集独立。

多个没有非线性激活的线性层仍可合并为一个线性变换；神经网络通过 ReLU、GELU 等激活形成更丰富的函数族。复杂模型也更需要数据与泛化检查。

| 手段 | 改变了什么 | 不能解决什么 |
| --- | --- | --- |
| Mini-batch SGD | 用部分样本估计梯度 | 不能保证每一步训练损失都下降 |
| Adam | 维护梯度一阶、二阶统计来调整更新 | 不会自动选对学习率与任务目标 |
| L2 / 权重衰减 | 约束参数规模，具体实现有区别 | 不能修复标签错误或泄漏 |
| Dropout | 训练时随机屏蔽部分激活 | 不是通用的数据增强替代品 |
| 早停 | 按验证集表现选择停止点 | 反复查看测试集再停止仍属泄漏 |

## 6. 泛化：最容易被忽视的核心问题

训练集用于更新参数；验证集用于选超参数、阈值和模型；最终测试集用于估计未参与这些选择的数据表现。**一旦用测试结果指导修改，它就事实上变成了验证集。**

团队知识助手有 100 份制度，每份切成 20 块。如果随机把 2,000 个 chunk 切成训练和测试，同一制度的相邻片段可能两边都有。系统认出了熟悉的表达，分数却被当成了“能处理新制度”的证据。

更合理的切分单位取决于目标：

| 希望估计的能力 | 切分方式 | 额外检查 |
| --- | --- | --- |
| 面对新文档 | 按文档或文档族 | 模板和近重复是否跨集合 |
| 面对新客户 | 按客户或组织 | 同一实体别名是否泄漏 |
| 面对未来请求 | 按时间 | 特征在预测时点是否可得 |
| 面对已知分布的新独立样本 | 随机或分层 | 独立同分布假设是否成立 |

RAG 允许从知识库检索测试问题需要的资料，这本身不是泄漏；泄漏在于把隐藏测试答案、调参反馈或同源重复样本用来优化，再声称独立评测。

## 7. 不要选错业务指标

假设 100 条请求里只有 5 条需要人工处理。永远预测“不需要”的模型准确率 95%，却一条高风险请求都没找出。

若实际预测了 8 条需人工，其中 4 条正确，则：

```text
TP=4，FP=4，FN=1，TN=91
Precision = TP/(TP+FP) = 4/8 = 0.50
Recall    = TP/(TP+FN) = 4/5 = 0.80
Accuracy  = (TP+TN)/100 = 0.95
```

准确率仍然 95%，但业务能力与多数类基线完全不同。漏掉高风险请求与增加人工工作量，哪个更贵？这决定阈值与指标，而不是“哪个分数最好看”。

回归可用 MAE/RMSE，排序可用 Recall@k/MRR，生成要看任务成功与事实支持。不同指标不能不看分母就横向比较。

## 8. 动手：不装框架也能验证

下载 <a :href="withBase('/ai-examples/foundations.py')" download>foundations.py</a>，或在仓库根目录运行：

```bash
python3 docs/public/ai-examples/foundations.py
python3 docs/public/ai-examples/foundations.py --test
```

完整说明见 [基础实验包](./examples/)。纯标准库脚本包含：

1. 上面的单样本梯度更新，应得到 `w=1.4，b=0.2，新损失=0.5`。
2. 对无噪声的 `y=3x+1` 做批量梯度下降，观察 w、b 接近 3、1。
3. 检查损失下降和参数近似值的自动测试。

**这是机制演示，不是有效泛化评测。**五个简单无噪声点无法证明模型能处理真实工单。

扩展时每次只改一个变量：学习率从 `0.05` 改为 `0.00001`，比较相同步数下误差；再试较大值，记录震荡而不是直接认定“训练坏了”。加入噪声后，不要再断言损失能降至零。

## 9. 失败诊断与分层练习

| 现象 | 优先假设 | 如何证伪或验证 |
| --- | --- | --- |
| 训练和验证都差 | 特征无用、标签错、欠拟合 | 检查小样本，先过拟合一小批正确数据 |
| 训练好、验证差 | 过拟合、切分差异 | 学习曲线、去重和分组切分 |
| 离线很好、线上很差 | 泄漏、数据漂移、训练服务不一致 | 按时间回放，比较特征与预处理版本 |
| 损失骤增或非有限数 | 学习率、异常输入、数值不稳 | 记录梯度范数、输入范围和首个异常步骤 |

**入门：**不看正文，重算一次 η=0.1 的更新，解释为什么 w 增大。

**进阶：**实现标准库逻辑回归，报告混淆矩阵；阈值从 0.5 改到 0.3 时，哪些指标可能变化？

**工程：**用文档族构建一次切分方案，记录去重规则、数据版本和验证流程。先设计报告，再选复杂模型。

::: details 自测答案：训练损失越低越好吗？
不一定。可能是记住训练集、学到泄漏特征，或代理损失与业务目标不一致。要检查独立验证集、业务指标与样本分桶，最终测试集不能用于反复调参。
:::

::: details 自测答案：为什么不能在全量数据上标准化？
全量均值、方差让测试数据参与训练预处理。应先切分，只在训练集 fit，在其他集合 transform；交叉验证时每个训练折也应独立拟合。
:::
