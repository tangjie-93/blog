# 03. 大语言模型

## 1. 先拆掉一个误解：生成不等于查答案

你问“出差住宿上限是多少”，模型给出一句很自然的回答。这句话可能来自训练中的关联，也可能依据你提供的制度，但模型的基本动作是：**给定当前上下文，计算下一个 token 的分布，选择一个，重复。**

它不会因为语气肯定就自动拥有可靠来源，也不会在普通对话推理中自动更新权重。

<AiConcept mode="generation" />

| 容易混淆的对象 | 实际含义 | 不保证什么 |
| --- | --- | --- |
| 参数中的知识 | 训练留下的统计结构 | 最新、完整、可追溯 |
| 上下文 | 本次推理可见的输入序列 | 一定被正确利用 |
| 外部检索 | 本次找到的事实材料 | 材料正确、无冲突或回答忠实 |
| 工具结果 | 程序返回的数据 | 模型解释正确，或数据本身最新 |

目标不是让模型“尽量自信”，而是把事实、计算、权限与可验证的程序连接起来。

## 2. 从文本到 token：预算的最小单位

Tokenizer 将字符串编码为整数 ID。token 可能对应字节、子词、空格、标点或字符片段，不等于中文词语，也不总能单独解码为一个完整字符。

BPE 的简化直觉是反复合并高频相邻片段：若语料有 `low`、`lower`、`lowest`，可能逐步合并 `l+o→lo`、`lo+w→low`，但实际词表、预处理、频次与特殊符号决定最终结果。

**不能用肉眼断定具体模型怎么切分。**要用目标模型的 tokenizer 或官方计数接口，分别测中文、代码、长数字、JSON 与 URL。

一个真实模型扩展实验（非标准库实验，需要联网和安装 `transformers`）：

```python
from transformers import AutoTokenizer

# 教学用固定模型；下载行为与许可证要自行确认。
tokenizer = AutoTokenizer.from_pretrained("gpt2")
for text in ["你好", "hello", "calculate_total_price", '{"amount":600}']:
    ids = tokenizer.encode(text)
    assert tokenizer.decode(ids) == text
    print(repr(text), len(ids), ids)
```

不要运行来历不明的远程模型代码。本实验不需要设置 `trust_remote_code=True`。不同模型的 token 数不能互换估算价格和窗口。

## 3. 预训练：学习一个条件分布

自回归序列概率可以分解为：

```text
P(x₁,…,xₙ) = ∏ᵢ P(xᵢ | x₁,…,xᵢ₋₁)
L = −(1/N) Σ有效位置 ln P(正确下一 token | 前文)
```

模型利用大量序列学习语言、代码和知识关联，但这个目标没有直接要求“每个事实有来源”“拒绝越权”“工具必须执行成功”。

### 3.1 损失与困惑度说明什么

若两个目标 token 的预测概率分别是 `0.5` 和 `0.25`：

```text
平均交叉熵 = −(ln0.5 + ln0.25)/2 ≈ 1.0397
困惑度 PPL = exp(1.0397) ≈ 2.8284
```

PPL 描述模型在这个 token 序列上的预测表现，不是问答正确率。只有 tokenizer、数据和计算约定相同，比较才更有意义；不同词表下的 PPL 不能随意排名。

### 3.2 数据问题会成为模型问题

去重、质量过滤、隐私、版权和测试污染都影响可用性。重复文本可能被过度学习，过时文本不会因为训练规模大就自动变新。

训练集更大不代表每个专业领域都覆盖充分；“没见过”和“见过但检索不出来”也无法仅凭最终回答区分。

## 4. 后训练：学会响应指令与偏好

| 阶段 | 典型数据 | 优化方向 | 不能据此推断 |
| --- | --- | --- | --- |
| 预训练 | 大量文本/代码序列 | 预测分布与基础能力 | 已经是可靠助手 |
| SFT | 指令与示范回答 | 任务行为、格式、对话习惯 | 自动学到最新业务事实 |
| 偏好优化 | chosen/rejected 或奖励信号 | 偏好与行为取舍 | 事实完全正确或安全完备 |

RLHF 是一类结合人类反馈的训练流程，常见方案涉及奖励模型与强化学习；DPO 可直接用偏好对优化，无需训练时单独运行显式奖励模型。它们不是“给答案打一分”这么简单，也不是可靠性的证明。

在团队知识助手中：

- 格式总不符合要求：先改善协议与示例，必要时考虑 SFT。
- 制度每周更新：首先考虑 RAG 和版本管理，不是每周微调。
- 报销总额算错：调用确定性计算或数据库，不要用偏好优化代替算术。

详细适配取舍见 [08 训练与部署](./08-训练微调与推理部署.md)。

## 5. Logits、温度与 top-p：用数字看采样

### 5.1 Softmax 不是凭空创造证据

最后的词表投影输出 logits `z`，转为概率：`pᵢ=exp(zᵢ/T)/Σⱼexp(zⱼ/T)`。实际计算先减最大值，避免指数溢出。

若 logits 为 `[2,1,0]`：

| 温度 | 概率（近似） | 效果 |
| --- | --- | --- |
| 0.5 | [0.867, 0.117, 0.016] | 更集中 |
| 1.0 | [0.665, 0.245, 0.090] | 原始分布 |
| 2.0 | [0.506, 0.307, 0.186] | 更平坦 |

`T=0` 不能直接代入除法；服务若接受温度零，通常以特殊解码策略处理，具体行为查接口。贪心选择是 argmax，不保证跨服务版本逐字一致。

### 5.2 Top-p 最容易写错的一行

假设排序后概率为 `[0.6,0.3,0.1]`，`top_p=0.8`。正确的 nucleus 集合应为前两项，累计 `0.9≥0.8`，归一化后为 `[2/3,1/3]`。

**必须包含让累计概率第一次达到或越过阈值的那一项。**若只保留“累计概率 ≤0.8”的项，就只留下 0.6，错误地变成单一候选。

```python
# 输入已排序的 (token_id, probability)，省略输入校验。
kept, total = [], 0.0
for token_id, probability in ranked:
    kept.append((token_id, probability))
    total += probability
    if total >= top_p:
        break
kept = [(token_id, probability / total) for token_id, probability in kept]
```

Top-k 固定候选数，top-p 按分布动态决定候选数。若组合使用，过滤顺序和重归一化也影响结果；不要假设各 API 行为完全一致。

低温只能改变随机性：如果错误金额本来概率最高，它会让模型更稳定地输出错误金额。

## 6. 上下文工程：窗口不是长期记忆

一个简化预算：窗口 8,192 token，预留输出 1,024；输入预算最多 7,168。若系统指令 800、历史 2,000、问题 200、工具结果 1,000，则资料预算只剩：

```text
8192−1024−800−2000−200−1000 = 2168 token
```

实际还需计算消息封装、特殊 token 与接口额外开销；有些服务对输入、输出或推理 token 另设限制。上面的算式只演示预算方法，不是所有 API 的契约。

超预算时按信息价值选择，而不是机械截最后几千字：

1. 保留当前任务约束和授权边界。
2. 检索与问题有关的原文，绑定文档 ID 与版本。
3. 摘要可压缩的对话；事实出处不能只剩无来源摘要。
4. 工具结果限长度，保留分页、截断和错误标志。
5. 仍不够时分阶段处理或明确拒绝，而不是悄悄丢掉关键证据。

长期记忆是应用维护的状态或检索系统，不是普通对话使权重永久改变。摘要也可能遗漏或扭曲信息，因此要保留可回溯原文。

## 7. 推理速度：两类工作，不要混在一起

**Prefill：**处理输入上下文，构建各层 K/V 等状态。

**Decode：**逐个生成后续 token，复用缓存；新位置仍需计算自身的 Q/K/V、MLP 和输出。并不是“只算一个 query”。

KV Cache 避免反复计算旧位置表示，却占用额外显存。长输入影响首 token 延迟，长输出影响持续解码时间；并发会影响排队与吞吐。

量化改变权重或其他张量的数值表示，不直接增加上下文可靠性。缓存与量化细节见 [08](./08-训练微调与推理部署.md)。

## 8. 结构化输出：格式正确只是第一道门

团队知识助手可采用这样的响应协议：

```json
{
  "status": "answered",
  "answer": "教学制度规定住宿上限为每晚 500 元。",
  "citations": [{"doc_id": "travel-v2", "chunk_id": "c03"}]
}
```

校验至少分四层：

| 层 | 示例 | 为什么不能省略 |
| --- | --- | --- |
| 语法 | 是否为合法 JSON | 输出可能截断或夹杂文本 |
| Schema | status 枚举、字段类型、长度 | JSON 合法不代表符合协议 |
| 业务 | 文档存在、属于本租户、版本有效 | Schema 不理解业务授权 |
| 语义 | c03 是否真的支持每晚 600 元 | 引用存在不等于支持主张 |

约束解码可减少格式错误，但不证明内容事实正确。`confidence:0.99` 也只是模型输出的一个字段，未经校准不能拿来自动批准付款。

失败时区分：模型拒答、长度截断、网络错误、Schema 错误、事实不支持、权限拒绝。它们需要不同的恢复策略，不能统一无限重试。

## 9. 动手与模型选型实验

先运行无需联网的 [基础实验包](./examples/)：

```bash
python3 docs/public/ai-examples/foundations.py --test
```

检查稳定 softmax、top-p 跨阈值 token 和因果 mask。测试证明机制实现，不证明某个模型真实表现。

真实选型时，用同一份固定任务集比较模型：

- 10 条结构化抽取：包含空字段、异常金额、长文本。
- 10 条带证据问答：包含无答案、冲突、过期制度。
- 10 条工具情形：包含超时、越权、参数错误。

这是初期诊断样本建议，不是足以统计证明上线可靠的规模。记录模型标识、日期、提示、解码配置、输入输出 token、停止原因与校验结果；不要只保存最好看的回答。

## 10. 分层练习与自测

**入门：**用 `[0.6,0.3,0.1]` 分别计算 `top_p=0.5、0.8、1.0` 的保留集合。

**进阶：**让预算计算器显式预留输出和工具结果空间，超预算时返回结构化错误。

**工程：**对同一组题，只改变一项提示或模型配置，比较退步样本、格式有效率与事实支持率，而非只看平均分。

::: details 自测：为什么 temperature=0 不等于事实正确？
贪心解码选最高分 token；概率来自已学分布和上下文，不是外部真实性验证。错误 token 排第一时仍会被选中。
:::

::: details 自测：SFT、RAG、工具怎样选择？
SFT 主要适配行为与任务模式；RAG 引入可更新可追溯的资料；工具负责确定性计算、查询或受控动作。三者可以组合，不能互相替代所有功能。
:::

::: details 自测：能把一段无依据但低熵的回答当作高可信输出吗？
不能。低熵描述分布集中，不描述事实支持。应验证引用、业务数据和工具结果，必要时拒答。
:::
