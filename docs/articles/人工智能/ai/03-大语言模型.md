# 03. 大语言模型

## 1. 生成不是查答案

问“出差住宿上限是多少”时，模型的基本动作仍是：给定上下文，计算下一个 token 的分布，选一个，再重复。自然语气不等于来源，低温也不等于事实正确。

| 名称 | 实际作用 | 不保证 |
| --- | --- | --- |
| 参数知识 | 训练留下的统计结构 | 最新、完整、可追溯 |
| 上下文 | 本轮推理可见输入 | 一定被正确利用 |
| 外部检索 | 本轮找到的材料 | 材料正确或无冲突 |
| 工具结果 | 程序返回的数据 | 模型解释正确或数据最新 |

## 2. Token 与预训练：优化的究竟是什么

Tokenizer 把字符串编码为整数 ID；token 可能是字节、子词、空格、标点或字符片段，不等于中文词语。BPE 的直觉是合并高频相邻片段，但具体切分必须用目标模型 tokenizer 测量，尤其要覆盖中文、代码、长数字、JSON 和 URL。

自回归概率分解为：

```text
P(x₁,…,xₙ)=∏ᵢP(xᵢ | x₁,…,xᵢ₋₁)
L=−(1/N)Σ有效位置 ln P(正确下一 token | 前文)
```

这要求预测“下一个 token”，没有直接要求每个事实有来源、拒绝越权或工具执行成功。训练集更大也不会自动解决过时资料、数据污染、隐私、版权与覆盖不足。

::: details 展开分词实验与困惑度边界
以下实验需联网并安装 `transformers`，不要把远程模型代码当作无风险依赖：

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("gpt2")
for text in ["你好", "hello", "calculate_total_price", '{"amount":600}']:
    ids = tokenizer.encode(text)
    assert tokenizer.decode(ids) == text
    print(repr(text), len(ids), ids)
```

两个目标 token 概率为 `0.5`、`0.25` 时，平均交叉熵约 `1.0397`，困惑度 `exp(1.0397)≈2.8284`。PPL 描述给定 token 序列的预测表现，不是问答正确率；不同 tokenizer、数据和计算约定不可直接排名。
:::

- 格式不稳定：先修协议与示例，必要时再考虑 SFT。
- 制度频繁更新：先用带版本的 RAG。
- 金额计算：调用确定性计算或数据库，不用偏好优化代替算术。

RLHF 是一类结合人类反馈的流程，DPO 可直接用偏好对优化；二者都不是事实正确或安全完备的证明。

## 4. Logits、温度与 top-p

<AiConcept mode="generation" />

logits `z` 经温度 softmax 得到 `pᵢ=exp(zᵢ/T)/Σⱼexp(zⱼ/T)`；实现通常先减最大值以防指数溢出。对 `[2,1,0]`：

| 温度 | 概率（约） | 直觉 |
| --- | --- | --- |
| 0.5 | `[0.867,0.117,0.016]` | 更集中 |
| 1.0 | `[0.665,0.245,0.090]` | 原始分布 |
| 2.0 | `[0.506,0.307,0.186]` | 更平坦 |

`T=0` 通常是服务端特殊解码而不是除法输入。top-p `[0.6,0.3,0.1]` 取 `0.8` 时必须保留前两项，因为累计 `0.9` 才首次越过阈值，重归一化为 `[2/3,1/3]`。低温只能让错误答案更稳定。

::: details 展开采样实现与组合边界
```python
# 输入已按概率排序；必须保留首次越过阈值的项
kept, total = [], 0.0
for token_id, probability in ranked:
    kept.append((token_id, probability))
    total += probability
    if total >= top_p:
        break
kept = [(token_id, probability / total) for token_id, probability in kept]
```

Top-k 固定候选数量，top-p 按分布决定数量；二者组合时过滤顺序与重归一化会影响结果，具体行为要查服务 API。
:::

## 5. 上下文工程：窗口不是长期记忆

窗口 `8192`、预留输出 `1024`，系统指令 `800`、历史 `2000`、问题 `200`、工具结果 `1000` 时，资料预算是：

```text
8192−1024−800−2000−200−1000 = 2168 token
```

还要计算消息封装、特殊 token 和接口额外限制。超预算时保留任务约束与授权边界，检索带版本的原文，摘要可压缩对话但不丢出处，工具结果保留错误和截断标志；仍不够就分阶段或明确拒绝。

长期记忆是应用维护的状态或检索系统，不是普通对话让权重永久改变。

## 6. 推理和结构化输出

Prefill 处理输入上下文并构建各层状态；Decode 逐 token 生成，复用 KV Cache，但新位置仍需算自己的 Q/K/V、MLP 和输出。长输入主要影响首 token 延迟，长输出影响持续解码；并发还会引入排队。

一个知识助手的输出协议可以是：

```json
{"status":"answered","answer":"住宿上限为每晚500元。","citations":[{"doc_id":"travel-v2","chunk_id":"c03"}]}
```

## 7. 动手、评测与边界

运行无需联网的实验：

```bash
python3 docs/public/ai-examples/foundations.py --test
```

它可检查稳定 softmax、top-p 跨阈值 token 和因果 mask；证明的是机制实现，不是某个模型上线可靠。

::: details 选型实验、练习与答案
固定任务集可包含结构化抽取、带证据问答、工具超时/越权/参数错误各 10 条；记录模型标识、日期、提示、解码配置、token 数、停止原因和校验结果，不只保存漂亮答案。这个规模只是初期诊断建议，不是统计证明。

- **入门**：求 `[0.6,0.3,0.1]` 在 `top_p=0.5、0.8、1.0` 下的集合。
- **进阶**：让预算计算器为输出和工具结果预留空间，超预算返回结构化错误。
- **工程**：只改一项提示或配置，比较退步样本、格式有效率与事实支持率。

**为什么 temperature=0 不等于正确？** 它只选最高分 token，最高分可能是错误事实。

**SFT、RAG、工具如何选？** SFT 适配行为与模式；RAG 引入可更新出处；工具负责确定性计算、查询或受控动作，可组合但不能互相替代。

**低熵回答是否高可信？** 低熵只表示分布集中，要核对引用、业务数据和工具结果。
:::
