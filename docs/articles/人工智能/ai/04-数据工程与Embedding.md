# 04. 数据工程与 `Embedding`

## 1、直觉：先修书，再做目录

团队想做一个知识助手，回答“出差住酒店最多报多少”。共享盘里却有扫描件、旧制度和不同部门的附件。
即使换一个更大的模型，它也不知道哪份文件有效、表格哪列对应上海、哪些员工有权查看。
**数据工程负责把资料变成可信资产；Embedding 负责让不同说法有机会在检索时相遇。**

可以把向量想成图书馆的语义坐标：“酒店报销”和“住宿限额”字不同，却可能在空间中靠近。
它不是数据库主键，不是内容压缩包，更不是“真相分数”。相似的旧制度仍然可能是错误证据。

## 2、输入输出：向量之外还要交付什么

沿用这套团队知识助手，输入为一份《差旅制度》：2026-11-01 生效，上海住宿上限 500 元/晚。
这里的金额和日期是**贯穿三篇的虚构教学数据**，不是本项目或任何公司的真实制度。

| 环节 | 输入 | 输出与必须保留的信息 |
| --- | --- | --- |
| 采集 | 文件、来源身份、授权 | `document_id`、原始文件、来源与使用范围 |
| 解析 | PDF / Markdown | 正文、标题树、表格结构、原文位置 |
| 清洗与切分 | 有结构的正文 | `chunk_id`、正文、标题路径、页码/偏移 |
| 编码 | 块正文、编码配置 | 向量、模型修订号、维度、预处理版本 |
| 发布 | 块、向量、业务元数据 | 索引版本、权限、生效区间、删除状态 |

块里不能只有“500”。至少要保留“差旅制度 / 上海 / 住宿 / 500 元每晚 / 生效日期”。
标题可以作为编码输入，但引用仍需指回真实原文，不能把补充标题伪装成原文中的一句话。

训练数据与检索数据的目的不同：训练集更新参数，检索库给每次问答提供外部证据。
前者关心标注一致性、训练/测试泄漏；后者还必须处理权限变更、生效时间和及时删除。
两者都要记录来源、许可证或授权依据、清洗版本与抽样质检结果。

## 3、核心机制：编码器学的是相对关系

真实编码器通常通过训练，让匹配的查询—文档向量靠近，让不匹配的样本远离。
例如“住宿上限？”与制度条款是正例，“住宿上限？”与请假流程是负例。
**难负例**可以是同样谈住宿、却属于另一城市或已失效版本的条款：它能暴露“主题对但条件错”。

双编码器分别处理查询与文档，因此文档向量可提前计算；查询到来只算查询向量再搜索。
某些模型要求查询前缀和文档前缀不同，或分别使用查询/文档编码接口；不能凭经验随意省略。
模型、提示前缀、池化方式、截断长度、归一化方式都属于编码契约。

向量的每一维通常没有“第 1 维就是住宿”这样的人工含义。
下一节故意给维度命名只是为了手算；不要把演示坐标当成神经模型的真实内部结构。

### 3.1 手算一次余弦相似度

设教学坐标依次是“住宿、报销、休假”，查询向量 `q=(1,1,0)`。
制度 A 为 `(2,1,0)`，休假制度 B 为 `(0,0,2)`，重复扩写的 A′ 为 `(20,10,0)`。

```text
cos(q, A) = (1×2 + 1×1 + 0×0) / (√2 × √5)
          = 3 / √10 ≈ 0.949
cos(q, B) = 0
cos(q, A′) = 30 / (√2 × √500) ≈ 0.949
```

余弦比较方向，不因 A′ 单纯放大十倍就给更高分；原始点积却会从 3 变成 30。
对两边都做单位长度归一化后，点积等于余弦，且平方欧氏距离为 `2 - 2×余弦`。
所以换距离度量前，要连同归一化和索引配置一起检查；零向量没有可定义的余弦方向。

**0.949 不是 94.9% 正确率。** 它既不证明制度有效，也不证明块里包含答案。
不同模型、领域和切分方法会改变分数分布，没有可以到处复制的“0.8 安全阈值”。

### 3.2 切分会改变你在比较什么

| 切法 | 对助手的影响 | 验证办法 |
| --- | --- | --- |
| 每 50 字硬切 | “上海”和“500”可能分离 | 单看命中块能否回答完整问题 |
| 整份制度一个块 | 多主题稀释查询，生成输入昂贵 | 检查命中是否只是主题相关 |
| 按标题、条款、完整表格切 | 条件与数值更可能在一起 | 抽查城市、币种、例外条款 |
| 过量重叠 | 前几名都是同一段，挤掉别的证据 | 统计同源块占比与去重后覆盖 |

先按结构切，再用 token 长度控制上限；表格不要随意拆掉表头、单位和脚注。
重叠是降低边界损失的手段，不是越多越好；参数应该由真实问题集检验。

## 4、连贯案例：一份制度如何更新

1. 初次摄取 v1：上海 400 元/晚，有独立内容哈希和有效期。
2. 收到 v2：上海 500 元/晚，解析器保留城市列与“每晚”单位。
3. 比较内容哈希，只重算变化块；但权限变化即使正文不变也要更新元数据。
4. 在新索引里验证 v2 能被检索，旧块不会作为当前条款参与回答。
5. 原子切换查询别名，并使绑定旧版本的缓存失效；失败时回滚整套索引配置。

同一段文字可能被两个部门引用。精确去重可以节约编码，但不能合并掉各自的授权和引用关系。
近重复去重更要谨慎：“上海 400”和“上海 500”很像，却正好是必须保留的差异。

建议用 `document_id + source_revision + chunk_id` 跟踪逻辑对象，用内容哈希检测正文变化。
哈希不是匿名化：短文本、手机号等内容仍可能被枚举；敏感字段应按用途最小化处理。

## 5、零依赖实验：相似度、过滤和版本拒绝

把下面代码存入临时目录的 `embedding_lab.py`，运行 `python3 embedding_lab.py`。
仅使用 Python 3 标准库，不联网、不需要 API key、不读写项目数据。
这是**词典特征编码器**，不是训练好的语义模型；实验目的是观察契约和失败分支。

```python
from hashlib import sha256
from math import sqrt
import unicodedata

GROUPS = (("住宿", "酒店"), ("报销", "限额"), ("休假", "请假"))
SPEC = ("toy-v1", len(GROUPS), "NFKC-v1")

def clean(text):
    return unicodedata.normalize("NFKC", text).strip()

def encode(text):
    text = clean(text)
    return tuple(sum(text.count(w) for w in words) for words in GROUPS)

def cosine(a, b):
    if len(a) != len(b):
        raise ValueError("dimension mismatch")
    norm = sqrt(sum(x*x for x in a) * sum(y*y for y in b))
    return sum(x*y for x, y in zip(a, b)) / norm if norm else 0.0

raw = [
    ("old", "住宿报销限额400元", "team", False),
    ("new", "住宿报销限额500元", "team", True),
    ("private", "酒店报销限额900元", "finance", True),
    ("leave", "请假休假流程", "team", True),
]
records = []
for doc_id, text, scope, current in raw:
    records.append(dict(id=doc_id, text=text, scope=scope, current=current,
                        hash=sha256(clean(text).encode()).hexdigest(),
                        vector=encode(text), spec=SPEC))

def search(query, scopes, spec=SPEC):
    if any(r["spec"] != spec for r in records):
        raise ValueError("encoding contract mismatch; rebuild index")
    q = encode(query)
    # scopes 来自服务端身份；此处只模拟已确定的授权结果。
    visible = [r for r in records if r["scope"] in scopes and r["current"]]
    ranked = sorted(((cosine(q, r["vector"]), r["id"]) for r in visible),
                    key=lambda item: (-item[0], item[1]))
    return [(doc_id, round(score, 3)) for score, doc_id in ranked if score > 0]

print("未过滤：", [(r["id"], round(cosine(encode("酒店限额"), r["vector"]), 3))
                    for r in records])
print("可用结果：", search("酒店限额", {"team"}))
assert search("酒店限额", {"team"}) == [("new", 0.949)]
assert search("火星基地", {"team"}) == []
assert records[0]["hash"] != records[1]["hash"]
try:
    search("酒店限额", {"team"}, ("toy-v2", 3, "NFKC-v1"))
except ValueError as exc:
    print("拒绝查询：", exc)
```

预期：旧版、新版、财务专用条款都得到约 `0.949`，过滤后只剩 `new`；换模型版本被拒绝。
这证明**高相似度无法代替权限与时效**，不证明该编码器能理解任何自然语言。
把查询换成“差旅过夜能花多少”，词典会漏掉；真实模型也需要同义问法测试，不能只测原句。

## 6、工程取舍：先可重建，再追求更快

小库可以先精确遍历向量；规模增长再比较近似近邻索引的召回、内存和延迟。
近似检索为了速度可能漏掉真实近邻；向量越多，不代表必须马上引入分布式向量数据库。
双精度/单精度/量化也有空间—精度权衡，应在同一问题集上比较，而不是只看存储节省。

| 决策 | 不能只看 | 还要验证 |
| --- | --- | --- |
| 增加向量维度 | “维度越高越聪明” | 任务质量、存储、带宽与模型适配 |
| 更换编码模型 | 单个问题效果好 | 全量重嵌入成本、契约兼容、回滚 |
| 批量摄取 | 每秒处理数量 | 限流、断点、幂等写入与失败重放 |
| 删除文档 | 向量库条目消失 | 原文、块、缓存、评估副本与备份保留策略 |

删除要先让数据不可访问，再清理派生副本；备份若受保留策略限制，应记录到期清理与恢复拦截机制。
训练进模型的个人数据不能靠删向量解决；需单独评估训练数据治理与模型处理流程。

## 7、失败诊断：不要先怪模型

| 现象 | 最先查的证据 | 最小修复方向 |
| --- | --- | --- |
| 上传了但搜不到 | 解析文本、入库状态、索引别名 | 补解析或修发布链路 |
| 突然搜到一堆无关内容 | 查询/文档模型、前缀与维度 | 拒绝不兼容请求，重建对应索引 |
| 查“500”却只有“上海” | 原文与块边界 | 重切完整条款或表格 |
| 旧版总排第一 | 有效期过滤、旧缓存 | 修版本筛选，不靠模型猜最新 |
| 别人搜得到我搜不到 | 服务端 ACL 与索引权限快照 | 修权限同步，不关闭鉴权 |

保留一组固定问题及正确块 ID，记录每次发布的命中变化；测试集不要混入训练或调参样本。
继续实现可看 [数据摄取](../rag/04-数据摄取.md)、[向量化与索引](../rag/05-向量化与索引.md)，本文不重复数据库配置细节。

## 8、分层练习与带答案自测

- **入门**：手算 `q=(1,0)` 与 `(2,0)`、`(0,2)` 的余弦，说明为什么长度不是相关性。
- **实践**：给实验增加第二租户，断言未授权条款从不进入返回列表；再改变权限但不改正文。
- **工程**：设计 v1→v2 发布与删除演练，交付配置快照、回滚步骤和派生数据清单。

**问 1：维度相同，模型不同，可以混用吗？** 答：不能据此判断兼容；坐标含义可能完全不同，应按编码契约拒绝。

**问 2：为什么“400”和“500”相似度一样？** 答：演示编码没包含数字，真实语义模型也不保证数值区分；事实要回原文核对。

**问 3：内容哈希没变就不用更新吗？** 答：正文可能不变，但 ACL、生效期或来源关系已经改变；正文与元数据要分开追踪。

**问 4：入门手算答案是什么？** 答：分别为 1 和 0；第一个向量同向，第二个正交。
