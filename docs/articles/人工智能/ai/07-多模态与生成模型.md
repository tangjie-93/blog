# 07. 多模态与生成模型

> 学习目标：解释图片怎样进入模型，区分理解与生成，能为扫描件问答设计可追溯验证，并拆出实时语音的延迟预算。
> 贯穿案例：团队知识助手既要读制度 PDF、报销截图，也要听会议录音；生成宣传配图则是另一条有独立验收标准的链路。

## 1. 先建立直觉：多模态不是“多传一个附件”

同一句“这个项目可以报销多少”，在纯文本、带表格的 PDF 和录音中包含的证据不同。系统首先要把原始媒体变成可计算的表示，再把表示与问题关联，最后验证回答有没有忠于证据。

<AiConcept mode="multimodal" />

图中的五个阶段都可能丢失信息：分片切断表格、编码忽略小字、融合找错对象、输出补全不存在的数字。更大的模型不能恢复被预处理彻底抹掉的像素。

| 任务 | 输入与输出 | 主要验收点 |
| --- | --- | --- |
| 视觉理解 | 图片 → 类别、坐标、描述 | 对象是否找对，坐标是否对应原图 |
| 文档问答 | 页面与问题 → 答案及证据 | 数字、页码、版本、权限是否正确 |
| 图像生成 | 文本或参考图 → 新图 | 条件遵循、构图、文字、版权风险 |
| 语音识别 ASR | 音频 → 带时间戳文本 | 词错率、专名、数字、说话人 |
| 语音合成 TTS | 文本 → 音频 | 可懂度、自然度、首段可播放延迟 |
| 视频理解 | 帧、音轨、时间 → 事件 | 事件顺序、漏采样、跨帧身份一致性 |

“理解图片”不意味着擅长生成图片；图文检索分数高，也不意味着能可靠读取发票税额。

## 2. 图像 patch：从二维像素到 token 序列

### 2.1 分片到底做了什么

以简化的 ViT 为例：把 `224×224` 的 RGB 图像切成 `16×16` 的不重叠 patch，共 `(224/16)² = 196` 块。每块展平为 `16×16×3 = 768` 个数，再通过可学习线性投影变为隐藏向量，并加入位置信息。

```text
224×224×3 像素 → 14×14 个 patch → 196 个向量 + 位置信息 → 视觉编码器
```

196 是这个教学设置下的 patch 数，不是所有多模态 API 的计费 token 数。真实模型可能增加分类 token、采用不同 patch 大小、动态切图、压缩视觉 token，或走完全不同的编码路线。

### 2.2 分辨率与成本不是线性关系

保持 patch 大小为 16，把边长加倍到 448，patch 数变成 784，即原来的 4 倍。在朴素全局自注意力中，注意力矩阵元素数约随序列长度平方增长，此部分约增为 16 倍；这不等于整套系统耗时必然增为 16 倍。

对知识助手而言，整页缩成缩略图很便宜，却可能让 `8` 与 `3` 不可区分。更合理的做法是先定位表格，再以较高分辨率重读局部，同时保存局部坐标到原页的变换。

| 选择 | 好处 | 代价与失败信号 |
| --- | --- | --- |
| 整页低分辨率 | 快、保留整体布局 | 小字混淆，复杂表格单元格串行 |
| 整页高分辨率 | 细节更充分 | token、显存和延迟上升 |
| 带重叠区域的切图 | 小字可读、可并行 | 边界重复，跨切片表头关联困难 |
| 布局分析后局部重读 | 对关键区域投入计算 | 定位漏检会让后续模型无从补救 |

视频同样要先采样。10 分钟视频按每秒 1 帧抽取是 600 帧，若只取每分钟 1 帧则是 10 帧；后者便宜，但可能完全错过持续两秒的错误提示。采样率必须由要捕捉的事件决定。

## 3. 跨模态对齐：让“图片中的猫”靠近“猫”

### 3.1 CLIP 式双编码器

图像编码器把图片映射成向量，文本编码器把描述映射成向量；训练时提高正确图文对的相似度，降低同一批次中不匹配组合的相似度。通常先归一化向量，再用点积计算余弦相似度，并通过温度参数调整分布。

假设一个批次有 3 张图和 3 条对应描述，得到一个 `3×3` 相似度矩阵，目标是让对角线相对更高；一般同时做“图找文”和“文找图”的对比学习。负样本也可能存在误标：两张不同图片都可以是“猫”。

团队助手可以用这种表示找“含报销流程的图”，但相似度 `0.82` **不是**“答案有 82% 概率正确”。相似度排序也不能证明图片里的金额被正确识别。

### 3.2 从检索走向问答

视觉语言模型还需要把视觉特征接入语言模型，例如通过投影层、跨注意力或共享 token 序列。图文指令数据让模型学习“按问题选择视觉信息并组织回答”。

```text
双编码器检索：问题向量 ↔ 页面向量 → 候选页面
视觉问答：问题 + 候选页面视觉特征 → 答案 + 原页证据
业务校验：原页、版本、金额规则、权限 → 接受 / 重读 / 转人工
```

检索、细读和校验可使用不同模型。不要为了“端到端”而丢掉独立可观察的中间结果。

## 4. 扩散：训练时学去噪，采样时多步生成

### 4.1 加噪与训练目标

经典 DDPM 从真实样本 `x₀` 出发，按预设噪声日程逐步加高斯噪声。借助闭式形式，可以在训练时直接采样某个时间步，而不是每次真的从第 1 步一直加到最后一步：

```text
xₜ = √ᾱₜ · x₀ + √(1−ᾱₜ) · ε，ε ~ N(0, I)
常见噪声预测目标：最小化 ||ε − εθ(xₜ, t, 条件)||²
```

`ᾱₜ` 表示累计保留的信号比例。模型看到含噪样本、时间步以及文本等条件，学习预测噪声；其他实现也可能预测干净样本或使用不同参数化，不能把这条公式当成所有生成模型的统一训练目标。

### 4.2 推理不是把训练图反向播放

采样时通常从随机噪声开始，用训练好的模型和选定采样器反复更新，得到符合条件的新样本。潜空间扩散先在压缩后的表示上生成，再经解码器回到像素，可降低计算量，但会引入压缩误差。

训练噪声时间步数与推理采样步数不是一个超参数；特定采样器可以只选其中一部分时间点。改变采样器、步数、随机种子或条件强度，都应重做质量与耗时对照。

| 调节项 | 可能收益 | 不能保证的事 |
| --- | --- | --- |
| 增加采样步数 | 某些设置下细节更稳定 | 质量不是始终单调上升 |
| 提高条件引导强度 | 更强调文本条件 | 可能过饱和、损伤自然度 |
| 固定种子 | 便于同配置比较 | 跨硬件、实现不一定逐像素相同 |
| 潜空间生成 | 降低高分辨率计算成本 | 不能保证小字与精确计数 |

### 4.3 生成模型不只有扩散

自回归模型按条件逐个生成 token；GAN 通过生成器与判别器博弈；VAE 学习潜变量分布与重建；流匹配等方法学习分布之间的连续变换。现代系统可能组合多条路线，不能因输出是图像或音频就断言使用 DDPM。

知识助手制作制度宣传海报时，可以先生成背景与布局，再用确定性排版渲染中文标题和金额。让图像模型“画出所有文字”通常不如把精确文字交给排版系统。

## 5. 文档问答：把证据链做成产品功能

### 5.1 不只保存抽取文本

每个字段至少关联 `document_id、version、page、bbox、原始文本、规范化值、抽取器版本`。说明坐标原点、单位和旋转方向；不同页面大小不能直接混用像素坐标。OCR 置信度也只代表该引擎的评分，不是未经校准的正确概率。

案例：现行 v2 差旅制度第 3 页写“住宿上限 500 元/晚”，失效 v1 为 400。回答必须同时验证：文档版本是否生效、500 是否来自住宿一行、单位是不是每晚，以及当前用户是否能查看该文件。

```text
上传 → 文件限额与隔离解析 → 布局/OCR → 保留页面和区域
提问 → 服务端权限过滤 → 检索页面 → 局部重读 → 字段/引用校验 → 回答
```

“引用第 3 页”不够：第 3 页必须存在，引用区域必须包含支持结论的内容。引用可点击原图，才能让复核者快速发现“有引用但证据不支持”的问题。

### 5.2 标准库实验：验证字段，而不是相信置信度

以下数据完全是教学构造，不是任何 OCR 或视觉模型的实测输出。保存为 `verify_document.py`，使用 Python 3 执行；无依赖、无网络。金额用 `Decimal`，避免二进制浮点误差。

```python
from decimal import Decimal, InvalidOperation

pages = {1: (1000, 1400), 2: (1000, 1400)}
rows = [
    dict(page=1, bbox=[100, 100, 500, 200],
         net="100.00", tax="13.00", total="113.00", confidence=0.92),
    dict(page=1, bbox=[100, 300, 500, 400],
         net="1O0.00", tax="13.00", total="113.00", confidence=0.99),
    dict(page=3, bbox=[100, 100, 500, 200],
         net="100.00", tax="13.00", total="113.00", confidence=0.99),
    dict(page=2, bbox=[100, 100, 500, 200],
         net="100.00", tax="13.00", total="118.00", confidence=0.99),
]

def check(row):
    reasons = []
    if row["page"] not in pages:
        reasons.append("页码不存在")
    else:
        width, height = pages[row["page"]]
        x1, y1, x2, y2 = row["bbox"]
        if not (0 <= x1 < x2 <= width and 0 <= y1 < y2 <= height):
            reasons.append("坐标越界")
    try:
        net, tax, total = (Decimal(row[k]) for k in ("net", "tax", "total"))
        if not all(v.is_finite() for v in (net, tax, total)):
            reasons.append("金额不是有限数")
        elif net + tax != total:
            reasons.append("金额不守恒")
    except InvalidOperation:
        reasons.append("金额无法解析")
    return reasons

results = [check(row) for row in rows]
assert results == [[], ["金额无法解析"], ["页码不存在"], ["金额不守恒"]]
print("通过", sum(not r for r in results), "/", len(rows))
for i, reasons in enumerate(results, 1):
    print(i, reasons or ["待原图复核"])
```

预期通过 `1 / 4`。其余三条即使置信度为 0.99 也会失败；第一条只是通过业务约束，仍可能把同一行三个数字一起读错，因此“校验通过”不等于“事实正确”。生产输入还需做字段类型、坐标长度和字段缺失的 schema 校验。

复现实验扩展：人工标注 12 张自有脱敏页面，分为清晰、旋转、低清、跨页表格四组，每组 3 张；固定解析器和提示词，再逐字段核对。12 张只能帮助发现问题，不能支撑泛化能力结论。

分别报告“正确字段/应抽字段”“正确字段/已抽字段”和“转人工页面/总页面”，避免通过少抽字段或全部转人工制造高准确率。任何真实结果都需要附样本清单与配置。

## 6. 音频：听清楚与及时接话是两件事

语音链路可以是 `音频→ASR→文本助手→TTS`，也可以由端到端音频模型承担部分环节。前者更便于检查转写与证据，后者可能减少中间转换，但不自动解决权限与幻觉。

一个**假设的串行预算**：端点检测等待 300 ms、ASR 200 ms、检索 100 ms、模型首段 400 ms、TTS 首段 150 ms、网络与缓冲 100 ms，合计 1250 ms。这不是产品跑分；流式流水线会有重叠，应以真实时间戳计算端到端延迟，不能机械相加已重叠阶段。

| 指标 | 定义与观察点 |
| --- | --- |
| 首段可播放延迟 | 用户结束发言到客户端可播放首段音频，包含端点检测 |
| 实时率 RTF | 处理耗时 / 音频时长；离线处理快不等于互动首响快 |
| WER | `(替换+删除+插入)/参考词数`；中文需固定切词或另报 CER |
| 数字与专名准确率 | 单独统计“500/晚”“项目代号”等关键实体 |
| 打断响应 | 用户插话到旧音频停止，以及新回复启动的时间 |

降延迟时先看端点检测：停顿阈值过短会把一句话切碎，过长则让用户感觉迟钝。会议纪要还要保留时间戳和说话人，未经确认不能把语音推断的身份当认证凭据。

## 7. 失败诊断与工程取舍

| 现象 | 优先检查 | 修复取舍 |
| --- | --- | --- |
| OCR 连续把 0 读成 O | 原图分辨率、字体、旋转 | 局部重读与规则校验；不要无条件全局替换 |
| 表格金额读对却归错项目 | 表头、合并单元格、切图边界 | 保留布局与相邻区域，增加跨页关联 |
| 页面“像相关”但答非所问 | 检索相似度与细粒度证据脱节 | 增加重排和区域验证，而非直接调高相似度阈值 |
| 引用页码不存在 | 模型自编页码、版本映射错误 | 引用只能从服务端实际候选 ID 中选择 |
| 生成图构图不错但字错 | 任务要求精确排版 | 背景生成与文字渲染分离 |
| 音频快但金额错 | 数字实体、噪声、口音 | 关键金额复述确认，必要时转人工 |

上传与解析应在受限环境中执行，限制文件大小、页数、像素数、解析时长和外部 URL。图片、OCR 文本和音轨里的“忽略规则”都可能是间接提示注入，不能升级成系统指令。

## 8. 分层练习与自测答案

1. **入门**：`448×448` 图像、`16×16` patch，有多少块？相较 224 输入，朴素注意力矩阵规模如何变化？
2. **机制**：解释“CLIP 相似度 0.9 不等于 OCR 准确率 90%”，并说明为何检索与问答应分别评估。
3. **实验**：给 Python 样本再加一条坐标越界和一条 `NaN` 金额，写出期望失败原因；不要改正确样本通过条件。
4. **工程**：设计一次只改变采样步数的图像生成对照，如何避免把随机性误判为收益？
5. **挑战**：团队说“语音模型已很快，用户仍要等两秒”，你应先补哪类观测？

**答案要点**：① 784 块，是原来的 4 倍；注意力矩阵元素约为 16 倍，不代表总耗时同倍率。② 相似度来自表示空间，OCR 是字符/字段任务；分别看召回与证据正确率。③ 越界触发坐标错误，`NaN` 被有限性检查拒绝。④ 固定模型、提示、分辨率、采样器和多组种子，盲评条件遵循与瑕疵，同时记录时延，不能只挑一张好图。⑤ 打通客户端与服务端时间戳，分离端点检测、排队、检索、生成、TTS、网络和缓冲的 p50/p95，并检查阶段是否重叠。
