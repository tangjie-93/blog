# 11. 学习路线与实战任务

## 1. 从时间表改为能力门槛

“八周掌握 AI”容易造成两个错觉：读完就是学会；进度慢就是能力差。本路线用六个里程碑衡量进度，时间只是安排资源的参考。

若你每周能投入 6–10 小时，可以先尝试约八周完成应用原型；这不是掌握模型训练或达到生产可靠性的承诺。原理路线通常需要更长时间。

先完成下面的自我检查，再决定入口：

| 问题 | 能做到 | 还不能 |
| --- | --- | --- |
| 能写 HTTP/JSON 程序并处理超时吗？ | 进入模型调用 | 先补 Python、HTTP、测试 |
| 能解释一次参数更新吗？ | 进入 Transformer | 先读 01、跑基础实验 |
| 能把模型错误拆成数据、检索、生成吗？ | 从评测改进现有系统 | 从里程碑 C 开始 |
| 能说明谁为工具调用授权吗？ | 进入受限 Agent | 先完成只读工具门禁 |

## 2. 贯穿项目的边界

**团队知识助手：**输入脱敏 Markdown、PDF 与图片制度，输出带引用的答案、版本说明或无证据拒答；可读取当前用户有权查看的申请状态。

第一版明确不做：自动批准、付款、发送外部邮件、任意执行 shell、多 Agent 协作。先把低风险只读路径做对，再讨论扩展。

准备一个自有小样本包，不上传真实敏感资料：

- 两份同主题不同生效时间的制度。
- 一份表格或扫描件，检查解析问题。
- 一份只允许另一测试租户访问的文档。
- 普通、无答案、冲突、越权和故障五类问题。

这是发现问题的教学集合，不是泛化评测的充分样本。

## 3. 六个里程碑与验收

### A. 能解释模型在计算什么

**阅读：**[01](./01-基础数学与机器学习.md) → [02](./02-深度学习与Transformer.md) → [03](./03-大语言模型.md)。

**动手：**运行[标准库实验包](./examples/)，先手算梯度与 attention，再对照脚本。故意改错 top-p 跨阈值逻辑，确认测试能发现。

**产物：**一页 shape 表、一次参数更新、三个采样边界测试。

**进入下一阶段的条件：**不用“模型懂了”解释结果；能区分上下文变化与权重更新。

### B. 能交付受校验的模型输出

**阅读：**03 的 token、采样、预算和结构化输出。

**动手：**做一个制度问题抽取器，输出 `topic、year、needs_clarification`。先用固定假响应测试程序，再接真实模型；接入时单独记录模型与依赖版本。

**失败注入：**缺字段、错误类型、超长文本、无效 JSON、长度截断、网络超时。

**产物：**请求/响应契约、校验器、错误分类、有限重试日志。

**验收：**未经校验的字段不会进入后续业务调用；空输入和失败不会被伪装成成功。

### C. 能定位检索问题

**阅读：**[04 数据](./04-数据工程与Embedding.md) → [05 RAG](./05-RAG与知识库.md)，再运行 [RAG 最小实现](../rag/03-最小实现.md)。

**动手：**对每题保存授权集合、候选 ID、分数、重排名次、实际上下文和最终引用。

**失败注入：**修改生效版本、删除某 chunk、移除必要表头、让关键证据落在上下文预算之外。

**产物：**数据 manifest、索引版本、固定题集与失败归因表。

**验收：**能分别指出“没召回”“被重排压低”“被预算截掉”“证据在但回答错”，不是统一归因模型弱。

### D. 能让工具受控执行

**阅读：**[06 Agent](./06-Agent与工具调用.md)；有外部连接需求再读 [12 扩展生态](./12-Agent扩展生态知识图谱.md)。

**动手：**只加入 `get_request_status(request_id)`，身份由服务端上下文提供，不能让模型自行填写 `tenant_id` 决定访问范围。

**失败注入：**未知工具、越权 ID、额外参数、超时、重复调用、达到步数上限。

**产物：**状态结构、工具 schema、授权矩阵、最大步数、超时和轨迹日志。

**验收：**服务端拦截越权；工具失败如实返回；达到预算就停止并报告未完成。

### E. 能解释媒体与性能代价

**阅读：**[07 多模态](./07-多模态与生成模型.md)、[08 部署](./08-训练微调与推理部署.md)。

**动手：**先运行合成媒体校验与时间戳实验；有条件再做真实图片清晰度对照、长短输入分层压测。

**产物：**原页证据定位、权重/KV 预算、TTFT/TPOT/端到端延迟与错误率。

**验收：**能区分假设计算、合成日志与真实测量；不会把权重能装下当成高并发一定可行。

### F. 能拿出发布与回滚证据

**阅读：**[09 评估与治理](./09-评估安全与治理.md)。

**动手：**冻结盲测集合，先写门禁再测新版本；完成一次权限撤销、缓存失效与回滚演练。

**产物：**每层指标、风险分桶、退步题、人工复核、许可记录、回滚说明。

**验收：**高风险失败不能靠普通题加分抵销；知道谁负责接受残余风险。

## 4. 两种节奏，只有一套验收

| 阶段 | 应用优先 | 原理优先 |
| --- | --- | --- |
| 起步 | 先跑 B/C，遇公式再回 A | 完成 A，重写核心函数 |
| 实践 | 用成熟模型和检索组件 | 加做微型 decoder 与训练循环 |
| 扩展 | 完成 D，再决定是否需要 MCP | 比较训练目标、LoRA 与量化 |
| 上线 | F 必须先于真实开放 | 同样需要 F，模型理解不能代替安全 |

不要同时学习所有框架。默认用普通函数构造第一版，只有恢复、状态、并行等需求确实出现时才引入编排框架。

## 5. 每次实验都留下可比较的记录

```text
实验 ID / 日期：
问题与风险边界：
数据集与标注版本：
代码 / 模型 / 提示 / 索引版本：
基线与本次唯一改动：
指标的分子、分母和测量端点：
成功、失败、超时、缺失结果：
退步样本及根因：
质量、延迟、成本与安全取舍：
结论与下一步：
回滚目标：
```

结论要能被证伪，例如“本次重排让 5 道缺失证据题中的 3 道进入 top-3，但增加 X 毫秒”；没有实测就写待测，不能写“显著提升”。

## 6. 常见卡点与自测

**读很多但写不出：**缩小到一次调用和一个测试，不要再找一份更长的学习路线。

**总想先训练模型：**先确认问题是否是知识更新、工具计算或权限配置。多数应用原型不需要自己预训练。

**总想换框架：**画出当前数据流和失败位置，框架只能改变实现方式，不能自动修复错误数据。

::: details 自测：什么时候可以升级到多 Agent？
当存在可独立完成、输入输出契约清楚、合并结果可验证的子任务，而且单 Agent 基线已明确。先测额外成本、信息丢失和一致性问题；“角色更多”不是质量提升证据。
:::

::: details 自测：每个里程碑都完成就能直接生产吗？
不能。这些门槛证明完成了教学链路；真实发布还需要代表性数据、组织风险要求、可靠负载测试、安全审查和运维能力。
:::
