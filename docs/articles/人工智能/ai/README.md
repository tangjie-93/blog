# AI 系统学习：从直觉到原理与工程

会调用模型接口，不等于知道模型为何出错；知道很多名词，也不等于能交付可靠系统。这套专题面向有编程基础、希望真正理解 AI 的读者：**先建立直觉，再追踪计算，最后用实验和失败案例检验理解。**

不要求先把所有数学学完才开始实践，也不承诺用几周掌握整个领域。你需要的是一条能循序渐进、能看见学习结果的路线。

::: details 类比的帮助与失效边界
把 AI 助手想成一位能组织语言的协作者，有助于入门；但不要把这种类比当作机制解释：

| 直觉类比 | 工程上实际是什么 | 类比失效的地方 |
| --- | --- | --- |
| 模型“读过很多书” | 权重拟合训练数据的统计规律 | 不能保证原文记忆、最新事实或来源 |
| 上下文是“工作台” | 本次推理可见的 token 序列 | 放进去不意味着一定能准确利用 |
| RAG 是“开卷查资料” | 检索证据后条件生成 | 找到相关资料不等于答案受证据支持 |
| 工具像“手和计算器” | 有明确输入输出的程序接口 | 模型请求调用不等于已经获得授权 |
| 评测像“考试与体检” | 固定题集、分层指标与线上监控 | 一次高分不能保证新场景可靠 |
:::

## 2. 一条贯穿全篇的案例

我们逐步构建一个**团队知识助手**。它能读取脱敏制度文档，回答“出差住宿如何报销”，引用原文；必要时通过只读工具查询申请状态。没有证据时拒答，无权限时不读取，不自动批准或付款。

示例资料中的金额、文档和权限均是教学设定，不是现实制度。

| 版本 | 新增能力 | 必须看到的中间结果 | 对应章节 |
| --- | --- | --- | --- |
| V0 | 理解模型如何学习 | 一次参数更新、验证切分 | 01–02 |
| V1 | 结构化抽取问题 | token、分布、输出校验错误 | 03 |
| V2 | 整理可检索资料 | chunk、向量、版本和 ACL | 04 |
| V3 | 带引用回答 | 候选、重排、证据、拒答原因 | 05 |
| V4 | 受限只读工具 | 请求参数、授权结果、执行轨迹 | 06、12 |
| V5 | 处理图片与上线 | 原图核验、延迟、成本、回归报告 | 07–09 |

每增加一个组件都问：**它修复了哪类失败？新引入了什么成本和风险？不用它能否完成任务？**

## 4. 按你的起点选择入口

**初次接触 AI，但会编程：** README → 01 → 02 → 03 → [基础实验](./examples/) → 04–06。第一次读先抓输入输出，不必一次记住每个公式。

**已经能写 API，想做应用：** 03 → 04 → 05 → 06 → 09，遇到概率、向量和注意力问题再回查 01–02；部署前补 08。

**已经做过 RAG 或 Agent：** 从 09 建立基线 → 按失败类型回读 04–06 → 08 做性能分析 → 12–13 看扩展与源码。不要用更复杂的架构代替错误分析。

**想深入模型内部：** 01 → 02 → 03 → 08，先完成数值实验，再阅读小型训练项目；能跑训练不等于理解训练目标。

## 5. 图解和实验怎么用

- 每张交互图按步骤展示机制与边界，可用键盘操作，也能展开完整文字说明。
- 图解是概念模型，不是未经测量的 benchmark；数值例子会注明假设。
- [基础实验包](./examples/)只需 Python 标准库，无账号、API Key、GPU 或模型下载。
- 需要真实模型的扩展实验单独标注依赖；模型、许可证、数据和硬件不同，结果不能直接照搬。
- 各章以“直觉 → 原理 → 例子 → 实验 → 取舍 → 自测”递进，**能解释反例比记住术语更重要**。
