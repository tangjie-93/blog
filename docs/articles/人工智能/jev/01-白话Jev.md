# 01 白话 Jev：会做选择题的模型

[返回专题](./) · [下一篇：API 与工单实操](./02-API与工单实操.md)

> **记住一句话：Jev 给判断，不替你的程序做决定。**

## 问：它和聊天机器人有什么不同？

想象你在值客服班。用户发来「付款成功了，但订单一直没生成」。你需要的第一件事不一定是写一封漂亮的回信，而是弄清楚：这单交给谁，有没有必要加急，是否提到了重复扣款？

把聊天机器人想成擅长写答复的同事；把 `Jev` 想成一位填分流表的同事。**区别不在于其他模型不能填表，而在于这个接口一开始就要求你把题目和答案形式定下来。** 接口返回答案后，由你写的程序核验并决定下一步。

![一条客服工单经过模型判断，最后由业务代码决定去向](/image/jev/decision-flow.svg)

*图 1：模型负责读懂话里的意思，代码负责应用企业规则。两者都可能出错，但要分开排查。*

| 名字 | 在这里具体指什么 | 容易误会成什么 |
| --- | --- | --- |
| `System One` | TypeSafe 对这类受约束判断能力的称呼，也是其 API 文档中的概念 | 某条工单规则，或心理学理论的完整实现 |
| `Jev` | TypeSafe 为这类任务提供的模型 | 一个能自行访问订单、扣款或发邮件的完整客服 Agent |
| `state` | 这次让模型看的材料，如工单正文和已知状态 | 真实支付记录；用户自述只是材料，不是已验证事实 |
| `questions` | 业务侧事先设置的一组判断题 | 用户输入里的任意命令 |

## 问：做文本判断，常用哪三类题？

仍用上面那条工单。我们不问「请全权处理」，而是拆开问：

| 原语 | 生活里的比喻 | 这条工单怎么问 | 读答案时要注意 |
| --- | --- | --- | --- |
| `Choice` | 单选题 | 根据本轮的主要诉求，交给订单、账单还是人工分流？ | 若漏了「信息不足」选项，模型仍须在现有选项中选。 |
| `Score` | 按标准打分 | 影响程度 0–2：0 是一般咨询、1 是单笔交易受阻、2 是有证据的广泛中断。 | 返回值可以落在两档之间；1 分不等于 50% 置信度。 |
| `Noul` | 判断一个命题有多成立 | 「消息明确提到同一笔交易被扣了两次。」 | 厂商将 `0` 到 `1` 定义为答“是”的预测概率，不是现成的 `true`/`false`，也不表示真实扣款概率。 |

官方文档还列了第四种题型：[Box](https://docs.typesafe.ai/primitives/box)，用四个相对坐标圈出图像中的目标；图像与 Box 目前被厂商标为试验能力，不建议当成成熟的生产接口。本文工单是纯文本，不需要它。

如果模型给出「订单、接近 1 分、未体现明显重复扣款信号」，代码可以进入订单队列。如果换成「同一笔订单被扣了两次，怎么退」，团队选择可能变成账单，但**触发复核不是立刻退款**。真实扣款笔数要去支付系统查。

## 问：怎样把问题写清楚，而不只是写得更长？

| 不建议 | 改成 | 为什么 |
| --- | --- | --- |
| 「用户是不是很生气，而且问题严重？」 | 「用户是否明确表达不满？」和「已描述的业务影响有多大？」 | 愤怒和影响范围可能完全不一致。 |
| 「是不是重复扣款？」 | 「用户是否明确声称同一笔交易被扣两次？」 | 不要求模型猜测真实账本。 |
| 「评估紧急性」 | 定义每个档位；说明缺少影响范围时不得推定为大面积中断。 | 同一条样本才能被不同标注者和版本稳定比较。 |
| 「判断并处理退款」 | 模型判断诉求；服务端验证订单、交易和权限，按政策处理。 | 不把判断接口当授权接口。 |

写完一题，找两个人独立标注五到十条真实脱敏样本。最先看的是**人为什么意见不一致**，不是让模型多试几次。若「付款后订单没生成」在订单和账单之间来回跳，优先明确两类的归属边界，再调阈值。

## 问：什么时候根本不需要 Jev？

- 状态已经有精确枚举，例如 `payment_status == declined`：直接写业务规则。
- 用户要解释账单条款：先找到有权限的条款，再用能生成文本的模型回答。
- 你只需要一个成熟、稳定的分类器，而且已有足够标签：把传统分类器作为基线，别单凭产品介绍改架构。
- 你要把表达多样的自然语言变成少数明确的分支：这是值得试用受约束判断接口的场景。

**动手题：**「昨天扣了两次，今天订单终于出现了。」哪一道题应该改变？订单出现是最新状态，不会抹掉用户自述的历史重复扣款；所以不应仅凭「订单已出现」跳过复核。接着看[怎样把这几道题写进一次请求](./02-API与工单实操.md)。
