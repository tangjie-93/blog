# 04 Jev 的数字能信吗？评估、校准与上线

[返回专题](./) · [上一篇：Agent 与 RAG 分流](./03-Agent与RAG分流.md) · [下一篇：文章、视频和练习路线](./05-资料与练习.md)

## 问：`0.80` 是不是有八成把握？

**先看字段，再看它在你的数据上是否校准。** `Score.score` 是业务等级的加权平均；`Noul.noul` 在官方契约里是答“是”的预测概率，没有另一个 `confidence` 字段；`Choice` 和 `Score` 的 `confidence` 则由概率分布计算，**不是“这次答对的概率”**。例如三选一的最高选项概率为 `0.80`，按[官方公式](https://docs.typesafe.ai/confidence#choice)，其 `confidence` 是 `(0.80 − 1/3) ÷ (1 − 1/3) = 0.70`。不要把这些数塞进同一条 `> 0.8` 规则。

概率校准关注的是一批样本：如果有 100 条被预测为「大约 0.8 概率要复核」，且其中约 80 条真的需要复核，那么这组预测在这一段表现得像概率。若只中 60 条，说明这一段偏乐观。这里是假设数字本来就被当作概率来使用；**没有这个约定时，只把它当分数比较，不对外说“八成准确”。**

想画可靠性图：把概率分段，横轴画每段平均预测值，纵轴画这个段位真实阳性比例；附上每段样本量。点贴近对角线才是校准较好的信号，但少量样本很不稳定。Brier 分数可以看概率预测的总体平方误差，不能单独拿来证明“校准一定更好”。

## 问：阈值怎么选？能不能直接用 0.8？

假设目标是找出**用户明确声称重复扣款**的工单。标注 100 条，其中 20 条确实表达了这件事。令模型输出达到阈值便进入复核，其余按普通工单处理：

![阈值 0.55、0.70、0.85 时，送审分别为 42、28、18 条，漏报分别为 1、3、7 条](/image/jev/threshold-tradeoff.svg)

*图 1：数字是教学用的虚构样本，不是 Jev 的实测成绩，也不是推荐阈值。*

| 阈值 | 送人审 | 其中真的声称重复扣款 | 漏报 | 精确率（审对多少） | 召回率（找全多少） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.55 | 42 | 19 | 1 | 19/42 ≈ 45% | 19/20 = 95% |
| 0.70 | 28 | 17 | 3 | 17/28 ≈ 61% | 17/20 = 85% |
| 0.85 | 18 | 13 | 7 | 13/18 ≈ 72% | 13/20 = 65% |

如果现阶段每百单最多人工审 30 条，目标召回至少 85%，**这个玩具例子**里只有 `0.70` 同时满足两个目标。如果要求最多审 25 条且召回至少 95%，这三档没有一个达标；需要补规则、改善数据或调整人力，不是挑一个看起来高级的数字。

实际项目：先在验证集选阈值，再在未用于调参的测试集复核指标。可把一个区间留给人工确认或澄清问题；避免把所有不确定样本强行归类，也要计算复核队列能否承受。遇到必审事件码、账户异常等已知硬规则，以规则为先。

## 问：拿什么样的样本评估？

1. **先写标签手册**：区分「用户说被扣两次」和「支付系统证实有两笔成功扣款」；这是不同标签。
2. **用脱敏真实样本**：包括正常、错别字、多语言、否定、反讽、转述及信息不足。例：「不是重复扣款，是退款一直没到账。」关键词命中也不能算正例。
3. **避免样本串场**：同一工单的多轮消息不要一部分用于调参、另一部分用于测试。可以保留最近一段时间当最终测试，正负比例与真实流量接近；稀有情形另外做切片。
4. **设对照组**：比如关键词、传统分类器、现用生成模型。分别看类别混淆、关键类召回、转人工比例、端到端 P95 和每千单总成本（含重试和人工）。
5. **分析错例再改题**：记录是模型没懂否定、业务类别含糊、资料缺失，还是代码回退失败。每类都有不同修法。

## 问：上线时要留哪些后路？

| 场景 | 建议 |
| --- | --- |
| API 超时、限流或响应不合法 | 设置请求和整体流程的超时预算；能安全重试时才有限重试，否则到规则或人工。不要把请求失败当成否。 |
| 模型建议重复扣款但账本不支持 | 以可信交易记录为准，保留复核而不自动退款。 |
| 模型别名、题目或标签边界更新 | 记录可获得的模型标识和题目版本，先跑回归；支持固定版本时优先固定。 |
| 真实流量分布变化 | 分类别观察转人工率和低分比例；抽样复核模型自动通过的工单，才能发现漏报。 |
| 需要日志排障 | 记录规则版本、分支、耗时和错误类型；限制原始文本和身份数据的收集、保留与访问。 |

建议按**影子运行（记录建议，不影响用户）→ 小流量分流 → 逐步扩大**部署。如果漏报异常升高，能立即回到旧规则或人工流程。上线前也应核对供应商的数据处理与留存条款；若不允许把数据发到外部服务，就不把真实敏感工单发过去。
