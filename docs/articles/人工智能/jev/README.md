# Jev 专题：让模型做判断，让代码管动作

> **付款成功了，但订单没生成。** 客服系统不只要回复这一句话，还得弄清楚：交给谁、影响多大、要不要人工看一眼？

这是 TypeSafe 的 `Jev` 擅长的问题形式：开发者先把问题和答案形式定好，模型读材料、给出受约束的判断，然后由应用决定下一步。这个专题不从一堆缩写讲起，而是沿着同一条客服工单，看它怎么从一句话变成一个可测试、可回退的程序分支。

## 问：最容易搞混的是什么？

1. **答案格式对，不等于事情判断对。** `billing` 是合法类别，却未必是这条工单的正确去向。
2. **模型看不到真实账本。** 用户说「扣了两次」可以成为复核信号，不等于支付系统已经证实扣了两次。
3. **判断不是授权。** 模型可以建议查订单，只有业务代码能在核对身份和订单归属后放行。
