# `RAG` 专题：从一句话到可运维的知识问答

这个专题只回答一个问题：**当模型不知道你公司的文档时，怎样让它基于文档回答，并且答得对、说得出出处、答不出时敢说不知道。**

它分成三层：

1. **能用大白话讲清楚**：不写代码的人读完 [01 白话 `RAG`](./01-白话RAG.md)，也能说明白 `RAG` 是什么、解决什么问题、什么时候没用。
2. **能自己写出来**：跟着 [03 最小实现](./03-最小实现.md) 跑通一个三百行左右、零依赖的版本，再逐层替换成生产组件。
3. **能解释故障并上线**：用 [08 全链路](./08-文档上传到问答全链路.md)、[09 评估](./09-评估.md)、[10 生产化](./10-生产化.md)、[12 排障手册](./12-排障手册.md) 把 Demo 变成可运维系统。

两条链路通过一份**持久化的索引**衔接，而不是通过内存或一次请求衔接。这决定了三件事：

- 生产环境的大文档处理通常异步执行，并记录状态、重试与幂等（重复执行不重复写入）；
- 索引必须带版本、来源、权限和删除能力；
- 问答失败时要能判断是“文档没进来”“没检索到”还是“模型没用好证据”。

## 3、同一段资料，四种角色

**数据契约就是各环节约定“交给下一步哪些信息”。** 用“午餐补贴是多少？”看一次数据变化：

<RagConcept mode="contract" />

| 必须保留 | 为了什么 |
| --- | --- |
| 块 ID、版本、位置 | 找回准确原文，而非只剩一句答案 |
| 服务端校验的访问权限 | 未授权内容不能进入模型 |
| 本次排名、本轮证据编号、run_id | 分清“没找到”“没选入”“模型没用对” |

字段参考见 [02 数据契约](./02-原理地图.md#_7、数据契约再展开)。分数不是正确概率；出处由系统绑定，不让模型编地址。

## 5、示例代码

[`examples/rag_demo.py`](https://github.com/tangjie-93/blog/blob/dev/docs/articles/人工智能/rag/examples/rag_demo.py) 是本专题的基线：

- 只用 `Python` 标准库，通过 `HTTP` 调 OpenAI 兼容接口：硅基流动做嵌入、`OpenAI` GPT 做对话；
- `ingest` 把 `Markdown` 切成片段、算向量、原子写入 `JSON` 索引；
- `ask` 做余弦召回、阈值过滤、编号证据、带引用回答，证据不足时拒答；
- 自带单元测试，用假客户端隔离网络。

**先看代码从哪里开始执行：** 两个子命令通过 `index.json` 衔接，建索引与问答不是同一次运行。

- 开源项目的许可证以仓库 `LICENSE` 为准。`Dify`、`FastGPT`、`WeKnora` 在 `GitHub API` 中显示为 `NOASSERTION`，属于自定义/修改条款，不能简单写成 `MIT` 或 `Apache-2.0`。
- 论文数字（如 `Contextual Retrieval` 的失败率下降）只在原实验设置下成立，不能直接当成本项目的预期收益。

## 7、一句话总结

`RAG` 不是“把文档塞给模型”，而是**建一套可追溯的证据供应链**：文档进得来、切得好、找得到、排得准、用得对、说得清、错得了可查。
