# `AI` 出海副业从零到一：程序员实战路线与学习资料

**适合谁**：会编程，但还没完整做过面向海外用户的付费产品，希望用业余时间验证一条副业路线。

**先说结论**：不要从“学完所有大模型知识”或者“先注册海外公司”开始。优先找到一类你能接触到、确实有重复工作的人，用人工辅助服务验证付费意愿，再把重复部分做成小工具。

本文默认你暂时没有海外公司、没有现成流量，先面向一个英语细分市场，每周能投入约 `6～10` 小时。这个时间安排是规划假设，不是对你当前条件的判断。已有客户、行业经验或者英语以外的语言优势，可以直接调整市场。

## 1. 怎样使用这份文档

### 1.1 你的第一轮目标

第一轮不是“月入多少”，而是形成四类证据：

1. **需求证据**：目标用户最近真的遇到过问题，并已付出时间或金钱解决。
2. **效果证据**：你的输出在真实样本上比现有办法更省事，且用户愿意采用。
3. **付费证据**：有人按明确的价格、范围、交付和退款条件实际付款。
4. **复用证据**：用户在下一个同类任务出现时再次使用，而不是只体验一次。

“有人点赞”“朋友说不错”“候补名单有邮箱”都是线索，但不是以上四类证据的替代品。

### 1.2 资料的核验边界

- **整理日期**：`2026-11-22`；本轮联网检索与主要官网正文核对发生于 `2026-11-21`。
- **官网正文已核对**：收款平台迁移公告、`Stripe` 支持地区、`Paddle` 商户支持地区及域名审核要求、`Paddle` 价格、`AI SDK` 和 `Supabase` 的部分文档等。
- **视频索引已核对**：核对了搜索索引中的发布者、标题、简介或章节；**没有逐一实测播放，也没有看完整视频**。字幕、登录和地区可访问性未实测。
- **官方资料入口**：部分来源只完成官方链接与搜索摘要核对；各处另行注明，不假装已通读。
- 免费公开视频不代表其配套社群、源码、课程全部免费；作者展示的收入和用户数不视为经过审计的事实。

**使用原则**：旧视频学方法；涉及账号、收款、税务、平台条款和接口版本时，回到当前官方文档查证。

## 2. 先选副业模式，而不是先选模型

### 2.1 哪类模式更适合起步

| 模式 | 怎样获得收入 | 起步优势 | 主要难点 | 本文建议 |
| --- | --- | --- | --- | --- |
| `AI` 辅助服务 | 为客户完成明确任务，按项目收费 | 可以先人工交付，最快接触真实需求 | 需要沟通，收入与个人时间相关 | 没有流量或行业证据时，优先尝试 |
| 垂直小工具，即 `Micro-SaaS` | 用户为一个具体工作流按次或订阅付费 | 容易定义交付，能逐步自动化 | 获客、留存、收款、售后都要承担 | 已发现重复需求后，作为主路线 |
| 插件或平台应用 | 浏览器、设计或电商平台内收费 | 用户场景比较明确 | 平台审核、权限及分成依赖 | 熟悉对应生态时再选 |
| 模板、脚本、数字资料 | 一次性销售 | 产品范围小，交付简单 | 分发与差异化，未必有复购 | 可作需求试验，不等于稳定订阅业务 |
| 通用聊天、通用写作、通用图片站 | 会员或点数 | 容易做演示 | 同质化、获客成本、滥用和算力费用 | 不建议作为无资源起点的第一款产品 |

**推荐组合：先服务，后工具**。例如先帮几位小团队整理客户反馈，确认他们愿意付费且存在重复工作，再开发反馈整理器。纯人工咨询或定制服务不一定符合软件收款平台的商品政策，应另查支付服务商允许范围，不能直接套用后文的软件收款方案。

### 2.2 三个可验证的方向假设

以下只是待验证的假设，不是已经证明有市场的推荐项目。

| 方向假设 | 潜在用户 | 具体任务 | 需要先验证什么 |
| --- | --- | --- | --- |
| 客户反馈整理器 | 小型软件团队、产品顾问 | 把获授权的反馈表整理为主题、证据和待办 | 用户是否反复整理，是否已有足够好的替代方案 |
| 带术语表的版本说明本地化 | 开源维护者、小型软件团队 | 把一份版本说明转换为目标语言并保留术语 | 术语一致性是否值得付费，而非免费翻译即可 |
| 电商商品描述质量检查 | 小型卖家、代运营人员 | 根据客户提供的商品信息指出缺项和不一致 | 能否拿到合法样本，检查结果是否真能进入上架流程 |

第一款产品尽量避开医疗诊断、法律结论、金融建议、儿童敏感数据，以及自动付款、自动发信等高影响操作。

## 3. 视频怎么学：先需求，再开发，最后按需补课

**建议学习预算**：前两周只选需求验证和首客两类视频，边看边行动。不要先连续刷完整个频道。

## 4. 第一步：找到一个值得解决的小问题

### 4.1 用一张表筛选，不用“现在很火”筛选

对每个候选方向写清以下问题。有任意一项完全答不上来，先研究，不开工。

| 问题 | 好信号 | 警惕信号 |
| --- | --- | --- |
| 谁在什么情况下遇到问题？ | 能描述具体角色与触发事件 | “所有想提高效率的人” |
| 他们现在怎么办？ | 有表格、外包、脚本或竞品等真实替代方案 | 从未采取任何解决行动 |
| 不解决有什么损失？ | 占用时间、延误交付、反复返工 | 只是“看起来很酷” |
| 我能接触到他们吗？ | 有公开社群、行业关系或自愿受访者 | 只能指望上线后自动有人来 |
| 免费通用工具为什么不够？ | 需要固定格式、证据、术语、权限或流程衔接 | 仅换一个界面，输出没有实质差别 |
| 能合法拿到数据吗？ | 用户有权提供样本，能脱敏和删除 | 依赖违规抓取、私有数据或无授权转载 |

可以在相关社群、竞品评价、公开问题区里找线索，但遵守社区规则和平台条款。不要抓取邮箱群发，不要冒充用户，不要把竞争对手的付费资料复制成自己的产品。

### 4.2 一份可直接使用的访谈提纲

每次约 `15～20` 分钟，先了解过去，再讨论方案：

1. 上一次处理这类任务是什么时候？具体为什么要做？
2. 可以按实际步骤讲一遍吗？中间用了哪些工具？
3. 最费时间或最容易返工的是哪一步？大概花了多久？
4. 试过哪些替代办法？哪里仍然不够好？
5. 谁使用结果，谁决定是否购买工具？
6. 如果愿意参与试验，能否提供一份有权分享、已脱敏的样本？
7. 我按约定范围交付一次结果后，能否一起比较新旧流程？

**不要这样问**：“如果我做一个很厉害的 `AI` 工具，你会用吗？”回答“会”没有真实成本，证据很弱。

**记录模板**：

```text
访谈对象角色／访谈日期：
最近一次具体任务：
当前步骤与现有工具：
时间、费用和返工：
用户原话及对应证据：
使用者／付款决策者：
样本授权和保密要求：
是否愿意试一次；下一步与时间：
尚未确认的假设：
```

### 4.3 人工交付，比先做后台更有价值

1. 使用获授权的脱敏样本，先借助现有工具和人工整理完成任务。
2. 把“原始材料 → 整理结果 → 用户实际采用了什么”记录下来。
3. 请用户指出遗漏、错分和不值得保留的内容。
4. 如果进入付费试点，先说明人工参与程度、交付日期、质量边界和退款条件；确认收款方式允许这类服务。
5. 只把多次重复、规则较稳定的部分变成产品功能。

**探索门槛建议**：先完成约 `5～10` 次有效访谈，其中找到 `2～3` 位愿意提供样本并试用的人。这里只是控制早期投入的经验性门槛，不是市场已被证明，也不是统计结论。

如果没人愿意提供样本、安排下次沟通或试用，先调整人群和问题，不要把“我再加几个功能”当作答案。

## 5. 贯穿案例：客户反馈整理器

### 5.1 一句话定位

> 帮助每周需要整理客户反馈的小型软件团队，把获授权的反馈表转换为可追溯的主题摘要和待办草稿，减少人工归类与复制粘贴；不替代产品负责人决策。

这是教学案例，不代表已经发现了付费市场。它的好处是范围可控、输出可核对，不必一开始连接客户的所有业务系统。

### 5.2 第一版只保留这些功能

| 要做 | 暂时不做 | 原因 |
| --- | --- | --- |
| 上传格式固定的 `CSV` | 任意网站抓取、任意文件解析 | 减少数据授权、解析与安全问题 |
| 给每条反馈保留 `source_id` | 无法追溯的“智能总结” | 用户必须能核对结论 |
| 输出主题、条数、对应证据、待办草稿 | 自动给产品优先级下最终结论 | 频次不等于重要性，模型不能替团队决策 |
| 页面修改和导出 `CSV` / `Markdown` | 自动写入外部项目管理工具 | 先让用户审核，避免误操作 |
| 登录、个人任务记录、删除 | 团队协作、复杂权限、插件市场 | 不在未验证前承担平台复杂度 |
| 有上限的免费试用与点数包 | “无限使用”套餐 | 限制推理成本和滥用 |

### 5.3 数据契约比提示词更先确定

输入：`source_id`、`feedback_text`、可选的时间和标签。第一版不收集邮箱、姓名、付款信息等非必要字段。

输出至少包括：`theme`、`count`、`source_ids`、`summary`、`suggested_action`、`needs_review`。

关键约束：

1. `source_ids` 必须属于本次输入，不能编造编号。
2. 主题条数由程序根据关联编号计算和校验，不直接信任模型给出的数字。
3. 一条反馈可能涉及多个主题，须说明主题计数可能重叠，不能把总和解释为用户数。
4. 输入中的指令只视为待整理的文本，不得覆盖系统规则或触发外部操作。
5. 文本不清楚时进入“待人工确认”，不强行补全事实。
6. 第一版限制文件大小、行数和单条长度；超出范围明确拒绝，不静默截断后假装处理完整。

### 5.4 开发顺序与验收

| 步骤 | 实现任务 | 验收标准 |
| --- | --- | --- |
| 先做假数据界面 | 上传、进度、结果、错误、导出 | 不调用真实模型也能走完整个用户路径 |
| 接通单个处理任务 | 服务端解析、调用、结构校验 | 正常样本有结果；错误结构不会直接入库或展示为成功 |
| 加身份与隔离 | 用户与任务绑定 | 用户甲无法读取、导出或删除用户乙的任务 |
| 加成本保护 | 单次上限、超时、并发、请求速率、预算 | 重复点击不会无限创建任务；超限能明确停止 |
| 加正式计费 | 支付事件、额度流水、失败补偿 | 付款、使用、退款都有可追溯记录 |
| 做真实试点 | 用获授权样本比较新旧流程 | 用户能说明结果是否可用，开发者能记录错误与时间变化 |

任务一旦可能超过托管平台请求时限，应改为后台任务加状态查询。不要因为演示时很快，就假设所有真实输入都能在一次网页请求里处理完成。

### 5.5 最小质量评估

先准备约 `20` 份小样本，覆盖空文件、重复反馈、混合语言、模糊表达、长文本、诱导指令及不同用户的任务。

- **硬约束**：源编号合法；没有串读其他用户的数据；格式可解析；超限有明确错误。发现越权或数据泄漏就停止上线。
- **人工判断**：有没有漏掉关键反馈、错误合并主题、夸大结论或凭空建议？让目标用户标出是否可用于实际工作。
- **业务判断**：从开始整理到完成审核，新流程总共花了多久？不要只计算模型生成时间。
- **变更回归**：改提示词、模型或解析逻辑后，重跑相同样本，记录新增和修复的错误。

样本少只能帮助发现问题，不能声称“准确率已被充分证明”。

## 6. 开发栈与官方资料：只学项目当前缺的部分

### 6.1 不要为了出海重新学一整套前端

如果你已经熟悉一套前后端技术，就继续用。演示教程常用 `Next.js`，不意味着使用其他框架无法出海。

没有既有偏好时，可把 `Next.js`、服务端模型接口、`Supabase` 和一家经审核可用的收款平台作为学习组合。它是文档较集中的一种方案，不是最低成本或唯一方案。

模型只选择你所在地及主体合规可用、允许相应商业用途的服务。**开发工具会员不自动包含产品对外调用的 `API` 额度**。不要购买来历不明的共享密钥、出租账号或绕过地区限制。

### 6.3 上线前的工程底线

1. 密钥只放在服务端；浏览器只使用官方明确允许公开的客户端凭据。
2. 所有读写都校验身份和资源归属；有登录页面不等于数据已隔离。
3. 输入、文件、任务并发和用户调用都有上限；预算告警与真正的硬停止要区分。
4. 超时、重试、失败、取消都有明确状态；不能失败了还显示扣费成功且无法追踪。
5. 日志默认不保存原始敏感文本；确需调试时使用脱敏样本和限制访问的日志。
6. 明确上传数据交给谁、保存多久、如何删除。对外承诺必须与数据库、备份、日志及模型服务商实际政策一致。
7. 导出表格时处理以 `=`、`+`、`-`、`@` 等开头的用户内容，降低被电子表格当作公式执行的风险。
8. 对长任务做队列或可恢复状态；部署失败时有回滚办法，数据库有适合业务的备份和恢复验证。

### 7.1 当前特别容易踩坑的信息

| 方案 | 本轮核验到的事实 | 对新手意味着什么 |
| --- | --- | --- |
| `Stripe` 直接收单 | [全球支持地区](https://stripe.com/global)的商户开放列表包含香港，不包含中国内地；地区语言选择器中的“中国内地”不是开户支持名单 | 如果你只有内地主体，不能因为能打开中文官网就认为可以直接开户。香港或其他地区主体仍须满足真实经营、身份、账户和产品审核 |

| 海外公司加当地支付账户 | 是一种经营主体安排，不是快捷支付按钮；注册公司、银行开户、支付审核是不同程序 | 先弄清楚客户需求、持续维护成本和申报责任，再决定是否设立；不要为了试一个点子立即承担长期成本 |

`Lemon Squeezy` 公告推荐符合条件的商户迁移至 `Stripe Managed Payments`，但**有地区和商品资格限制**，不是所有内地开发者都能自动使用的替代方案。

### 7.2 什么是名义商户模式

在 `MoR` 模式下，平台通常以法律上的销售方身份向买家销售，按合同承担相关销售税、增值税、支付争议等环节中的责任。你的收入与义务依据具体合同及所在地规则确认。

这不意味着“你不用报税”，也不代表平台包办全部法律责任。经营所得、企业所得、个人所得、会计、外汇及本地申报等，应按实际主体和税务居民身份咨询专业人士。

### 7.3 申请前的准备和验证顺序

1. **先询问资格**。向官方说明经营地区、个人或企业主体、商品类型、预计买家地区、希望使用的结算账户，请其确认要求。不要伪造地址、借用身份或购买成品账号。
2. **准备可访问的网站**。有清楚的产品说明、价格、交付范围、联系渠道，以及真实适用的服务条款、隐私政策和退款政策。
3. **提交审核**。身份、主体、域名和商品审核各自可能需要补充材料。`Paddle` 的[域名审核要求](https://www.paddle.com/help/start/account-verification/what-is-domain-verification)明确要求产品、价格、条款、隐私、退款信息和安全访问等内容。
4. **跑通沙箱**。验证支付成功、失败、退款、重复通知和额度发放。
5. **正式交易**。资格通过后，用平台允许的真实试点交易验证交付；不要用自刷交易“验证”可用性。
6. **验证结算**。确认结算周期、最低金额、收款账户、手续费及所需文件。买家付款成功不等于资金已最终结算。

审核期间可以验证需求、提供样本演示和使用沙箱，但不能把尚未获批的收款渠道宣传成正式可用。

### 7.4 支付不是放一个按钮就结束

技术接入参考 [`Paddle Webhooks` 官方文档](https://developer.paddle.com/webhooks/overview)。该入口已访问核对，实施时须继续阅读签名验证与事件处理的具体章节。

- 不根据“支付成功”跳转页发放权益；跳转页可以被伪造或重复打开。
- 验证服务端支付通知签名，校验商品、金额、币种和归属用户。
- 用事件编号去重，防止重复通知重复充值；处理通知乱序和延迟。
- 使用额度流水记录购买、预留、消耗、释放和退款，而不只是覆盖一个余额数字。
- 把“收到支付款”和“模型任务成功”分开；付了钱但任务失败，应提供重试、返还额度或按政策退款。
- 试点阶段可以先卖明确额度的一次性点数包，避免在需求不稳定时引入续费、按比例变更和复杂订阅状态。

## 8. 定价与预算：先确认每单不会越卖越亏

### 8.1 先算成本，再设计套餐

以下金额**全部是美元教学假设，不是市场平均值、收入预测或服务商报价**：

| 项目 | 示例假设 |
| --- | --- |
| 一个点数包的价格 | `$9`，包含 `30` 次有输入上限的处理 |
| 每次处理的平均模型成本 | `$0.03`，包含在该假设内的重试 |
| 本例采用的支付费用 | `5% + $0.50`，来自本轮核对的 [`Paddle` 标准价格页](https://www.paddle.com/pricing)，实际合同另行确认 |
| 单包支付费 | `$9 × 5% + $0.50 = $0.95` |
| 全部次数用完的模型成本 | `30 × $0.03 = $0.90` |
| 单包剩余金额 | `$9 - $0.95 - $0.90 = $7.15` |

**`$7.15` 不是净利润**，还没扣托管、存储、汇兑、税费、退款、拒付、获客、人工审核和客服时间，也未处理税费是否内含于售价等实际差异。

进一步看压力场景：如果长输入和重试令单次成本变成 `$0.30`，模型成本就是 `$9`，仅算支付和推理就已亏损。因此要限制输入、记录真实用量，并基于高成本样本而非最好看的演示做预算。

第一版不建议承诺“无限次”“终身无限用”，也不应因为单次模型报价很低就忽略免费试用被滥用的风险。

### 8.2 可自行设定的试验预算

| 项目 | 第一轮建议 |
| --- | --- |
| 域名 | 可先用演示子域名；准备正式对外经营时再核对购买和续费价格 |
| 模型试验 | 自定如 `$10～20` 的总试验上限；确认服务商是否支持硬限制，不把邮件告警当硬限制 |
| 托管、数据库 | 先选最低的合规可用组合；免费方案的商用、休眠、备份、额度和超额计费都要核对 |
| 模板和课程 | 第一轮可以先不购买，优先用本文免费材料补齐当前阻塞点 |
| 公司、会计和法律 | 不塞进“几美元做产品”的预算；如确有需要，向专业服务方取得独立报价 |

这张表是控制投入的建议，不构成“花这些钱一定能上线”的承诺。开发订阅、支付验证条件、所在地区和产品类型不同，总费用会不同。

## 9. 第一批用户从哪里来

### 9.1 每轮只选一个主要渠道

| 渠道 | 适合什么情况 | 第一轮怎样做 | 不要做什么 |
| --- | --- | --- | --- |
| 熟悉行业的人与转介绍 | 对行业有经验，能获得真实反馈 | 邀请对方评价一份具体样例，询问是否能介绍同类用户 | 把朋友客气的赞美当购买证据 |
| 行业社群、论坛、`Reddit` 等 | 目标用户在固定社区讨论工作问题 | 先读规则，公开说明身份，经允许发布问题或样例 | 群发私信、伪装用户、复制营销帖刷屏 |
| 个性化商务联系 | 能找到合法公开的商务联系入口 | 少量人工研究，围绕对方具体任务提出试验，提供退出方式 | 抓取个人邮箱批量发送，把公开邮箱视为任意营销授权 |
| `SEO` 搜索内容 | 用户主动搜索明确任务或问题 | 做一个有真实样例、边界和可用工具的长尾页面 | 批量生成低质页面、承诺很快获得搜索流量 |
| `Product Hunt` 等发布平台 | 产品基本可用，已有样例与一些种子用户 | 当成一次分发试验，记录真实使用与付款 | 把榜单名次、投票或当天访问量当成持续需求 |

**英语起步建议**：先准备一页清楚的英文说明、一段演示和一份结果样例。`AI` 可以帮助润色，但产品能力、数据处理和退款承诺必须由你逐句确认。

### 9.2 一份不夸大承诺的英文联系示例

仅在平台允许、联系目的适当且遵守适用反垃圾邮件规则时使用；它不是自动群发脚本。

```text
Hi [Name],

I saw your public post about [specific workflow/problem].
I'm testing a small tool that turns an authorized, anonymized feedback CSV
into editable themes with links back to the original rows.

Would you be open to reviewing a short sample? If it looks relevant,
we can agree on the scope and data handling before using your own data.
No pressure if this is not a priority.

I'm the developer of the tool, and it is still an early pilot.
If you'd rather not hear from me again, please let me know.

[Your name / business contact]
```

模板只是在表达层面提供参考，不保证满足所有地区对商业邮件的法律要求。

### 9.3 落地页最小结构

1. **谁的问题**：例如“为每周整理客户反馈的小型软件团队服务”。
2. **输入和结果**：展示一份脱敏输入与对应输出，标明示例而非伪造客户案例。
3. **为什么不用通用工具**：只写已经验证的差异，例如固定导出格式和来源追溯。
4. **价格与限制**：包含次数、输入上限、有效期、退款及失败处理。
5. **行动入口**：早期只放一个主要按钮，例如“申请试点”或“查看演示”。
6. **信任与责任**：联系渠道、开发者身份、条款、隐私政策，以及数据是否交给第三方模型处理。

搜索入门参考 [`Google` 搜索引擎优化入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=zh-cn)。这是官方公开资料，本轮核对到官方索引与摘要，但正文抓取未成功；不据此承诺收录或排名。

## 10. 八周行动计划

按照每周约 `6～10` 小时安排。以下数量是**本轮试验的操作目标，不是成功概率或收入保证**。如果某周尚未形成证据，就缩小范围或延长，不强行赶开发日程。

| 周次 | 主要任务 | 只看这些资料 | 当周交付与验收 |
| --- | --- | --- | --- |
| 第 `1` 周 | 列三个细分方向，选一个可接触人群，安排访谈 | `V1`、按需看 `V3` | 一份需求假设表；约到实际受访者，而不是只收藏资料 |
| 第 `2` 周 | 完成约 `5～10` 次有效访谈，取得授权样本，人工交付 | `V2`、`V4` | 找到 `2～3` 位愿意试验的人；若没有，调整人群或任务 |
| 第 `3` 周 | 用假数据搭最短流程，完成一次真实任务处理；并行咨询收款资格 | `D1`、`D2`，按需看 `V5` | 输入到结果可演示；写明输出契约和所有已知限制 |
| 第 `4` 周 | 接身份、存储、隔离、限额和错误状态，建立小样本回归 | `D3`、`D4`、第 `5` 节 | 双账号越权测试通过；坏输入明确失败；真实处理成本可见 |
| 第 `5` 周 | 完成产品说明、政策、定价，提交或跟进审核，跑通沙箱 | 第 `7～8` 节、支付官方文档 | 能演示支付成功、重复通知、任务失败、退款的处理；未通过审核就不正式收费 |
| 第 `6` 周 | 受控上线，邀请已沟通的种子用户，演示并跟进 | 第 `9` 节、按需重看 `V2` | 至少记录真实使用反馈；渠道已就绪时尝试获得首笔合规付款，不承诺一定成交 |
| 第 `7` 周 | 修复最影响交付的问题，邀请用户处理第二批同类任务 | 回归样本与实际反馈 | 分清“不会用”“结果不好”“不值得付钱”三种问题；记录复用情况 |
| 第 `8` 周 | 计算费用、投入时间、付款与复用，决定继续或停止 | 第 `11` 节 | 一页复盘；只选择一个下一步：继续、调整、暂缓或停止 |

**每周时间分配建议**：访谈和触达约占三成，产品与质量约占五成，学习与复盘约占两成。不要让“继续学技术”长期挤掉与用户接触的时间。

如果只有每周 `3` 小时，可以把同一任务拆成更长周期；缩小第一版范围，不以压缩安全和隐私检查来赶进度。

## 11. 怎样判断继续、转向还是停止

### 11.1 用表格就能记录的最小漏斗

| 环节 | 记录什么 | 发现问题后先查什么 |
| --- | --- | --- |
| 有效接触 | 联系了多少符合目标的人；有多少真实回复 | 人群和渠道是否匹配，表达是否围绕对方的问题 |
| 完成任务 | 开始试用的人中，多少获得了完整结果 | 输入要求、性能、错误和引导是否阻塞 |
| 结果采用 | 用户是否实际修改、导出或用于工作 | 输出是否可信，审核成本是否抵消节省的时间 |
| 实际付款 | 成交金额、退款、商品与付款者角色 | 价值、价格、付款体验与决策人是否匹配 |
| 再次使用 | 下一个同类任务出现后是否回来 | 任务频率、结果质量和现有工具是否更合适 |
| 成本与时间 | 推理、托管、费用、客服与个人工时 | 收入是否覆盖变动成本，副业是否变成低价外包 |

分别保存分子、分母和时间窗口。样本很小时优先看个案，不用几个用户算出漂亮百分比误导自己。

**复用按任务周期衡量**。每月才整理一次反馈的用户，一周未回访不能直接算流失；订阅也不一定适合低频任务。

### 11.2 决策参考

- **继续**：真实任务反复出现，输出被采用，有实际付款，下一轮还有明确任务，成本和维护时间可接受。
- **调整定位**：有人使用但不是原先设想的人群，或只有其中一个子步骤值得付费。
- **先修质量**：需求明确，但输出错误、数据处理或交付不可靠；不要先扩大推广。
- **暂停收费**：支付或主体审核未通过、关键法律责任不清楚，或数据保护措施不到位。
- **停止当前方向**：经过多轮有效接触和人工交付，仍没有具体痛点、样本和进一步合作意愿；保留访谈记录，比继续堆功能更有价值。

不是“八周没赚钱就失败”，而是“八周后是否比开始时更清楚谁需要什么，以及你能否合规、可持续地交付”。

### 12.2 正式上线清单

- [ ] 不是只凭朋友赞美，已经和目标用户讨论过最近发生的任务。
- [ ] 样本使用、第三方处理及保留期限有清楚授权和说明。
- [ ] 结果可追溯、有适用范围和人工审核提示，不编造用户评价。
- [ ] 密钥不在前端，双账号隔离已验证，删除与导出有权限检查。
- [ ] 文件、频率、并发和预算限制已验证，不仅仅设置了告警邮件。
- [ ] 支付主体、商品、地区及结算路径得到平台确认。
- [ ] 沙箱已验证成功、失败、签名、重复通知、乱序和退款。
- [ ] 免费额度与付费额度发放、预留、消耗、返还可审计。
- [ ] 落地页、价格、条款、隐私、退款与联系渠道一致且能访问。
- [ ] 托管商业使用条款、资源限制、费用与异常停止方式已确认。
- [ ] 能回滚版本，有必要的数据备份和恢复验证。
- [ ] 明确谁负责客服、故障处理，以及副业会不会影响本职工作。

### 12.3 现在就可以开始的三个动作

1. 看 `V1`，从自己熟悉的工作流里写出三个具体问题，而不是三个热门产品名。
2. 选最容易接触用户的一个方向，今天发出两条合适、个性化的访谈邀请；不先买模板、课程或公司注册服务。
3. 用一份自己有权使用的样本手工完成交付，记录哪里真的省了时间，再决定是否开发。

**最终建议：让“学习 → 联系用户 → 交付结果 → 复盘”形成循环，而不是把观看教程当作副业进度**。
