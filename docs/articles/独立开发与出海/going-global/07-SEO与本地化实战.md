# `SEO` 与本地化实战：先做好一个可索引的任务页

**先让一个页面回答一个真实任务，再考虑更多语言和页面。** 本文以客户反馈整理器为教学案例，不讨论模型实现，也不假定已有客户。示例域名、搜索词和数字均为设计假设，没有搜索量、排名或收益承诺。

> **视频跟练**：中文可看 [`Search Console` 操作讲解](https://www.bilibili.com/video/BV1H5abzEEBk/)，英语可看 [`Google` 官方网址检查演示](https://www.youtube.com/watch?v=Pe_-TkdbXN0)。抖音也可参考[独立站如何提交给谷歌收录](https://www.douyin.com/video/7501171626013117696)，公开页作者、日期与时长已核对，未完整观看。在自己管理的测试站完成所有权验证、站点地图提交及单页检查；只练这些基础动作，不照搬拒绝外链等扩展操作。[验收记录与旧界面提示](./10-视频跟练与项目实操路线.md#_6-搜索控制台-跟着检查一个真实页面)见跟练页。

## 1. 从搜索任务选页，不从关键词数量选页

目标用户是需要把反馈表整理成周报的小型软件团队负责人。先收集访谈原话和公开问题，再人工查看目标地区的搜索结果，记录查询、日期、地区、结果类型和缺少的信息。不要凭个人搜索的一次结果推断所有用户，也不要把自动补全当搜索量证明。

| 假设查询 | 可能意图 | 页面应交付什么 |
| --- | --- | --- |
| `how to categorize customer feedback` | 学习归类方法 | 分类步骤、冲突案例、审核方法 |
| `customer feedback CSV organizer` | 寻找可操作工具 | 输入格式、样例结果、限制与试用入口 |
| `customer feedback software pricing` | 比较采购条件 | 真实价格、用量、退款与适用范围 |

首轮选第二类，原因不是“竞争低”，而是能用现有教学产品回答完整任务。一个查询可能混合多种意图，先看结果主要是教程、工具还是采购页；如果产品无法满足主要任务，就改选题，不只改标题迎合排名。`Google` 入门指南强调帮助用户理解内容，并明确没有保证第一名的方法（来源 `G1`）。

## 2. 写出一个能独立使用的任务页

示例地址是 `https://example.com/en/feedback-organizer/`。标题、主标题和正文围绕同一任务，不罗列大量近义关键词。下面是英文页面骨架，不代表产品已经支持所列能力；正式使用前逐项与实际功能核对。

```text
Title: Organize Customer Feedback CSV into Reviewable Themes
H1: Turn a feedback CSV into editable themes
Description: Review a synthetic sample, inspect source-row references,
and check the input limits before trying your own authorized data.
Primary action: View sample output

Who it is for: Small software teams preparing feedback reviews.
Input: source_id and feedback_text; remove unnecessary personal data.
Output: Editable themes, source-row references, and draft actions.
Boundary: Theme frequency does not decide product priority.
```

正文按“输入要求—完整样例—审核步骤—限制—行动入口”展开。合成输入可写“反馈甲要求批量导出，反馈乙希望导出时保留筛选条件”，输出归到“导出流程”，并逐条保留来源；解释这两条不一定是同一需求，用户必须确认是否拆分。

让读者不注册也能看清样例、理解如何核对结果。说明重复反馈可能影响计数、人工审核仍有成本，以及哪些数据不应上传。只展示实际支持的格式、额度和删除方式，不用虚构客户标志或未经测量的“节省九成时间”。

再从已有相关教程、产品入口添加描述明确的普通链接，帮助访问者与爬虫发现该页。相关性不足的页面不要硬塞入口，价格信息也不必在多个页面复制出互相冲突的版本。

## 3. 上线后先检查“能否被处理”

把发现、抓取、索引和获得展示分开。页面可打开不代表已被发现，抓取成功也不保证索引或排名。按下面顺序排查，避免每天重复请求收录。

1. **发现**：从站内可访问页面用 `<a href>` 链接到任务页；在站点地图中列出希望收录的正式地址，不混入测试站和跟踪参数地址。
2. **响应**：公开页返回有效的 `200`，不是登录页、错误说明伪装成功或循环跳转。检查移动端正文和资源能否访问。
3. **指令**：核对 `robots.txt`、页面 `noindex` 和响应头 `X-Robots-Tag`，避免测试环境禁索引设置遗留。禁止抓取不是可靠的删除或保密方式；私有上传结果必须依靠身份与权限保护。
4. **内容**：确认搜索引擎看到的是完整任务说明和样例，不是空壳。依赖 `JavaScript` 时检查渲染结果，不把禁用脚本后的表现当唯一判据。
5. **检查工具**：验证站点所有权后，在 `Search Console` 的网址检查中分别查看索引记录和实时测试；修复后再考虑请求索引。实时测试不等于已收录，也不保证最终规范页选择（`G5`，仅核对索引）。

留一条检查记录：页面地址、发布时间、响应状态、可见正文、索引指令、自声明规范页、工具状态和复查日期。`site:` 搜索只能辅助观察，不能替代完整索引诊断。

## 4. 先两种语言，再谈地区矩阵

### 4.1 分清语言版本与重复地址

假设先提供英文与简体中文任务页，用 `/en/feedback-organizer/` 和 `/zh-hans/feedback-organizer/` 分别承载真实译文。`hreflang` 表示对应语言版本，`canonical` 表示重复或高度相似地址中的首选版本，不能互相替代（`G2～G4`）。

本例两页均有独立完整译文，**各自指向自身规范地址**，不要把中文规范页一律指向英文。同一英文页加上 `utm_source` 后仍是同一内容，规范关系应回到不带跟踪参数的英文地址；站内链接与站点地图也保持一致。规范标注是信号，不是强制命令。

英文页的 `<head>` 示例如下。中文页保留相同的语言替代集合，但把规范地址改成自己的中文地址。

```html
<link rel="canonical"
      href="https://example.com/en/feedback-organizer/">
<link rel="alternate" hreflang="en"
      href="https://example.com/en/feedback-organizer/">
<link rel="alternate" hreflang="zh-Hans"
      href="https://example.com/zh-hans/feedback-organizer/">
<link rel="alternate" hreflang="x-default"
      href="https://example.com/en/feedback-organizer/">
```

`G2` 正文要求完整地址、自引用与双向对应；缺少返回关系的标注可能被忽略。本例将英文页作为未匹配语言的默认页；若改用语言选择页，`x-default` 就指向真实存在的选择页，不能指向不存在的占位地址。

只用语言 `en` 即可覆盖通用英语，不因准备出海就批量建国家页。确有美国与英国内容差异时再考虑 `en-US`、`en-GB`；近似重复的同语言地区页要另行规划首选版本和替代关系，不能机械套用“全部自规范”。地区码也不能单独代替语言码。

### 4.2 本地化不是只翻译菜单

`Google` 用可见正文判断语言，并建议不同语言使用不同地址、让用户自主切换，避免按推测语言强制跳转（`G3`）。页面的 `lang` 仍应正确设置以服务可访问性，但不能把它当成搜索语言判定开关。

客户反馈整理器应连同样例、报错、输入说明和导出说明一起本地化。先定术语表，例如将“主题”稳定对应 `theme`，避免同一流程中在“话题、类别、标签”之间漂移。让能熟练使用目标语言的人按整条流程审读，核对日期、时区、小数、币种和支持时间；翻译价格页不能擅自改变计费币种或承诺当地客服。

没有审读资源时，宁可先只上线英文。需要两种语言，并不意味着用户反馈原文也要擅自翻译或公开；教学样例与客户私有数据继续分开。

## 5. 用数据定位问题，不批量造页面

观察窗口可先设约 `4` 周，用作复查日程而非见效承诺。`Search Console` 效果报告可按查询、页面、国家等维度看展示与点击（`G6`，仅索引核对）；网站自己的试用、审核和导出数据另行记录，不能把搜索点击当客户。

- 没展示：先查发现、索引和意图，不马上复制更多页面；新站也可能数据不足。
- 有展示少点击：比较真实查询与标题承诺是否匹配，不写超过产品能力的诱饵描述。
- 有点击无采用：查看样例是否解释清楚、入口是否失败，以及访问者是否真的有任务。

复盘保留“窗口／页面／查询意图／展示／点击／开始试用／完成审核／未知因素”，每轮只改一个主要假设。少量数据不宜算出漂亮增长结论；查询报告也不代表完整用户行为。

`Google` 的规模化内容滥用政策关注主要为操纵排名而大量生成、缺乏用户价值的页面，与制作方式无关（`G7`）。不要把同一页替换城市、语言或关键词后批量发布；只有任务、内容和维护责任确实不同，才新增页面。

## 6. 常见错误与验收清单

常见错误包括用 `robots.txt` 代替保密、把所有语言规范到英文、只在一边配置 `hreflang`、仅翻译导航，以及用站点地图提交成功证明已索引。分别通过权限测试、规范关系表、双向核对、整流程审读和索引记录复查来纠正。

- [ ] 一个任务页回答一个主要意图，有完整合成样例和能力边界。
- [ ] 正式页可发现、正常响应、无意外禁索引；私有结果不公开。
- [ ] 规范地址、站内链接、站点地图一致，语言页互相对应且自引用。
- [ ] 实际译文、报错、日期、币种和支持承诺均经过审读。
- [ ] 索引状态、实时测试、展示点击和产品采用分别记录。
- [ ] 没有批量垃圾页面、虚构评价或排名及收益承诺。
