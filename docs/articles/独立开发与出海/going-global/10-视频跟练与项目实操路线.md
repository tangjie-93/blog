# 视频跟练与项目实操路线：从演示到自己的可验收成果

前面的文章给出判断框架，这一篇补上“看别人操作，再自己完成”的学习路径。**不要只点开收藏：每个任务都要留下可检查的结果。** 贯穿项目仍是客户反馈整理器这一教学案例；视频未必开发同一种产品，跟练时要把技能迁移到自己的项目，而不是照抄作者的商业承诺。

先说明边界：本轮于 `2026-11-25` 检索 `Bilibili`、`YouTube`、抖音与小红书。**没有完整观看视频或运行配套项目**。`Bilibili` 与 `YouTube` 未实测播放；抖音两条视频已打开公开页面，核对可见元数据，其中一条播放器短暂自动播放，但未核对完整画面与音轨。小红书浏览器搜索触发平台安全限制，仅保留搜索索引线索，不列为已核实教程。以下“操作演示”依据各平台简介、分集或索引判断，不代表已审计每一步；练习和验收是本专题另行设计的，不冒充作者课程内容。

## 1. 先选路线，不必看完全部视频

| 你现在缺什么 | 先看哪组 | 跟练成果 |
| --- | --- | --- |
| 不知道怎样与用户交谈 | `B1` 或 `Y1` | 访谈提纲、一次征得同意的模拟访谈及复盘 |
| 还没有可访问的页面 | `B2` | 测试站部署、更新与回退记录 |
| 不会接认证和数据库 | `B3` | 双账号任务隔离及输入结果存取 |
| 不会跑通支付与权益 | `Y2` | 沙箱交易、验签、重放与退款测试记录 |
| 不知道如何报价或找首客 | `Y3`、`Y4` | 套餐说明、一轮合规首客实验 |
| 不会检查搜索收录 | `B4`、`Y5` 或 `D1` | 站点验证、站点地图和网址检查记录 |
| 想看抖音或小红书的独立开发经验 | `D2` 与第 `9.3` 节线索 | 区分实际证据、自述和未核实内容，不把线索当已审阅教程 |
| 不会配置分析工具 | `Y6` | 测试环境漏斗及逐条核对的事件记录 |
| 没做过恢复演练 | `Y7` | 隔离环境恢复与缺失项清单 |

`B` 表示 `Bilibili`，`Y` 表示 `YouTube`，`D` 表示抖音；小红书只保留待核验线索，不编视频编号。编号不代表质量评分。方法课不强求屏幕操作，操作演示也不能替代需求与经营判断。视频页面是公开入口，**不代表源码、社群或配套课程全部免费**；不要为了完成练习先购买课程或交出不必要的个人信息。

## 2. 用户访谈：先听问题，再展示产品

### 2.1 视频入口

- **`B1`：[第十六讲：如何做用户访谈](https://www.bilibili.com/video/BV14gvKzYEhN/)**。上传者 `DayOne实验室`，讲者 `Emmett Shear`；平台上传日期 `2025-08-27`，时长 `46:28`。**访谈方法课，不是产品开发录像**。标题标“中英”，字幕完整性未实测；上传日期也不等于原课程录制日期。平台接口已核对标题、上传者、时长与简介，简介只写“网络”，转载授权链未核实；优先使用原作者官方版本或自己可合法访问的版本。
- **`Y1`：[How To Talk To Users — Startup School](https://www.youtube.com/watch?v=z1iF1c8w5Lg)**。`Y Combinator`，英语方法课；只核对官方视频搜索索引，未验证当前字幕和播放。与 `B1` 不是同一集，可以二选一，不把它们当互为译本。

### 2.2 暂停后完成什么

1. 先写“最近一次整理反馈如何完成”的开放问题，不先问会不会购买。
2. 与一位同意参与的人做模拟访谈，围绕实际经历；没有真实经历时明确标注模拟，不能算需求证据。
3. 回放笔记，分别标出事实、解释、称赞和下一步承诺。
4. 再展示合成反馈样例，观察对方是否能追溯主题来源。

**验收**：保存一页提纲和记录，指出至少一个自己提出的诱导问题并改写。模拟练习只是训练表达，下一步仍要接触真实目标用户。完整模板见[需求验证与付费试点](./02-需求验证与付费试点.md)。

## 3. 部署和数据：做出自己的最短闭环

### 3.1 `B2`：先部署一个不含客户数据的页面

[两分钟使用 `Vercel` 免费部署你的静态网站](https://www.bilibili.com/video/BV1kX4y1v75w/)，上传者“拿大锤的坏叔叔”；`2023-06-30`，平台时长 `03:28`，中文操作演示。平台简介涉及静态产物、分支推送自动部署和自定义域名，元数据已核对。标题中的“两分钟”和“免费”保留原题，**不是当前耗时、套餐或商用许可保证**。

跟练时只部署测试页：写清产品对象、放一组合成输入输出和一个演示按钮。随后修改一段文案推送更新，再通过当前平台支持的方式回退，保存更新与回退前后的版本记录。实际界面可能与旧视频不同，以[当前部署文档](https://vercel.com/docs/deployments)为准；商业用途还需核对[套餐使用规则](https://vercel.com/docs/limits/fair-use-guidelines)。

**验收**：在另一浏览器环境访问测试地址，确认更新与回退生效，页面和构建日志不含密钥。不把静态页部署成功说成支付、数据库和后台任务已经完成。

| 分集 | 入口 | 平台分集时长 | 本专题练习 |
| --- | --- | --- | --- |
| 创建项目 | [第 `2` 集](https://www.bilibili.com/video/BV1GD7GzUExH/?p=2) | `04:57` | 建独立测试项目，记录地区、限额与删除方式 |

简介还列出实时功能和边缘函数，第一轮可跳过。视频简介要求通过公众号获取源码，因此**不把源码列为无门槛公开下载**；可以只参考操作，自建最小示例。标题中的“免费”不代表当前套餐足以支撑你的商业用途或备份要求。

**验收**：保留双账号测试结果，而不只是登录截图。公开读取、公开存储或服务端高权限密钥若出现在演示中，不可直接搬到客户数据环境。安全边界以[行级权限文档](https://supabase.com/docs/guides/database/postgres/row-level-security)及[上线验收](./03-最小产品与上线验收.md)为准。

## 4. 沙箱支付：不要停在“成功页出现了”

[Full Guide: Using Paddle with Next.js for Payments — Subscriptions, Transactions and MORE!](https://www.youtube.com/watch?v=ot5BrFCjo8c)，`Atharva Deosthale`；搜索索引标注发布于 `2025-01-14`，英语、第三方开发演示，**不是平台准入保证**。

搜索索引中的章节提供以下定位；没有实测跳转与画面同步，找不到时按章节名称定位，不将时间戳当作已观看证明：

- [沙箱设置，`00:31`](https://www.youtube.com/watch?v=ot5BrFCjo8c&t=31s)。
- [目录商品支付，`03:40`](https://www.youtube.com/watch?v=ot5BrFCjo8c&t=220s)。

- [支付通知，`34:30`](https://www.youtube.com/watch?v=ot5BrFCjo8c&t=2070s)。

本轮不用复制整套动态计价功能。先在沙箱创建一种明确额度的商品，发起测试支付，记录订单与事件；再对照[当前官方入门套件](https://developer.paddle.com/get-started/starter-kits/nextjs-saas/)及[签名验证文档](https://developer.paddle.com/webhooks/about/signature-verification)检查安全实现。教程能展示接口流程，不代表其中全部实现都符合当前规则。

### 4.2 本专题另加的故障练习

| 动作 | 应留下的证据 |
| --- | --- |
| 正常测试支付 | 交易、用户、商品、额度流水能对应 |
| 重复投递同一事件 | 记录重复接收，但只发一次权益 |
| 篡改签名或错误环境凭据 | 拒绝事件，不改变额度 |
| 模拟本地处理失败 | 可安全重试，不因已接收而永久跳过 |
| 在平台沙箱退款 | 退款事实与权益调整可追溯，不删除原流水 |

这些练习是本专题的补充，**没有核实视频逐项演示了它们**。只在自己的沙箱进行，不发正式交易、不自刷测试。验收方法见[支付状态机](./04-海外收款与支付状态机.md)。

## 5. 报价与首客：看方法课，做真实记录

- **`Y3`：[How To Price For B2B — Startup School](https://www.youtube.com/watch?v=4hjiRmgmHiU)**。`Y Combinator`，讲者 `Tom Blomfield`；索引日期 `2024-07-25`，英语定价方法课，不是支付界面教程。看后写出客户任务、收费单位、价格、限制和退款条件；用[成本模型](./05-定价与单位经济模型.md)重算正常与高成本场景，再请目标用户解释他们为何会买或不买。
- **`Y4`：[How to Get Your First Customers — Startup School](https://www.youtube.com/watch?v=hyYCn_kAngI)**。`Y Combinator`，讲者 `Gustaf Alströmer`；本轮核对到标题和来源的搜索关联，发布日与时长未独立核实。英语首客方法课，不是 `Product Hunt` 后台发布演示。看后选一个允许交流的渠道，写清目标角色和联系许可，做少量个性化接触，记录真实回复与下一步。

**验收**：留下套餐说明、成本表和一轮渠道实验记录。没有成交就写没有成交，不用朋友赞美或作者收入故事替代结果。不要照搬任何批量私信、求票或夸大承诺的做法；[渠道实验](./06-首批用户与发布渠道实验.md)中的规则核对仍是前置条件。

## 6. 搜索控制台：跟着检查一个真实页面

### 6.1 两个入口，按语言选一个

- **`B4`：[谷歌站长工具从入门到精通，Google Search Console](https://www.bilibili.com/video/BV1H5abzEEBk/)**。上传者“吕推无止境”，`2025-09-05`，时长 `14:53`，中文操作讲解。平台简介列出添加站点、网域与网址前缀、收录检查和站点地图；平台元数据已核对，未核实配套收费或所有延伸建议。
- **`Y5`：[URL Inspection Tool — Google Search Console Training](https://www.youtube.com/watch?v=Pe_-TkdbXN0)**。`Google Search Central`，讲者 `Daniel Waisberg`；搜索索引日期 `2020-01-23`，英语官方工具演示。旧界面只用于理解索引记录、实时测试和网址检查，以[当前工具说明](https://support.google.com/webmasters/answer/9012289?hl=zh-Hans)为准。

`B4` 简介还涉及拒绝外链等扩展话题，本轮**不建议照做**，也不把这些步骤列为新站常规任务。只练站点验证、地图提交和单页检查。

### 6.2 具体操作与验收

1. 使用自己有权管理的测试站，选择合适的所有权验证方式；不修改不属于自己的域名。
2. 提交实际存在、只含正式公开地址的站点地图。
3. 检查一个任务页，分别记录索引状态、实时测试、自声明与搜索引擎选择的规范地址。
4. 如发现意外禁索引或错误规范关系，修正后再次检查。

**验收**：保存带日期的检查表，说明“已经提交”“当前可抓取”和“已索引”之间的差别。没有收录就如实记录，视频标题或讲者承诺不能保证排名。页面结构见[搜索与本地化](./07-SEO与本地化实战.md)。

## 7. 漏斗：先用合成测试事件做出一张可核对的分析

**`Y6`：[Conversion Funnels: Building, Analyzing, and Optimizing — PostHog Tutorial](https://www.youtube.com/watch?v=cMFz_xFlHaE)**。搜索索引标注发布者 `PostHog`、日期 `2022-12-12`，英语产品操作教程；目前只核对视频搜索索引，未验证当前界面、全部步骤或字幕。使用时对照[现行漏斗文档](https://posthog.com/docs/product-analytics/funnels)。

跟练只用隔离测试项目和合成标识，不把客户原文、邮箱或付款凭据发送给分析服务。先手工准备以下预期路径，再按工具当前支持的测试方式产生事件：

| 测试标识 | 预期事件 |
| --- | --- |
| `demo_a` | 注册 → 有效输入 → 结果成功 → 导出 |
| `demo_b` | 注册 → 有效输入 → 结果成功 |
| `demo_c` | 注册 → 有效输入 |
| `demo_d` | 注册 |

这些是本专题设计的测试数据，不是用户成绩。配置有序漏斗、统一窗口与去重口径，预期每步人数分别为 `4、3、2、1`，总体演示转化为 `1 ÷ 4 = 25%`。再重复发送一个已有事件，核对计数是否仍符合去重规则。

**验收**：事件明细与各步人数一致，能解释为什么按用户而非事件次数计数。工具演示不代替[激活与留存](./08-激活留存与经营指标.md)中的价值定义；`25%` 只验证测试配置，不是产品转化率。

## 8. 恢复：看到表回来，不代表整个产品已恢复

**`Y7`：[I Tested Supabase Backup: Restoring Everything to a New Project — Step-by-Step](https://www.youtube.com/watch?v=het8VeSoBZw)**。`Drops Technology`，索引日期 `2026-06-08`，英语第三方操作演示。搜索简介涉及在本地 `PostgreSQL` 检查备份，再用 `DBeaver` 恢复到新项目并检查表与数据。**标题中的“Everything”不作为完整恢复保证**；未审计脚本、命令或配套项目。

跟练前，先确认目标是独立、可销毁的测试环境，不含正式订单、用户数据或生产凭据：

1. 只用合成任务和反馈生成测试备份，按官方当前流程操作；任何覆盖动作前核对目标。
2. 在新测试环境恢复，关闭正式支付、发信与后台自动执行。
3. 逐项检查任务、权限、文件、必要配置与删除记录，不只数数据库表。
4. 记录恢复耗时、遗漏内容和手动步骤，再清理测试资源。

**验收**：能指出已恢复和未恢复的部分。数据库备份不包含对象存储文件本身，参见[官方备份边界](https://supabase.com/docs/guides/platform/backups)；完整手册见[客服与持续经营](./09-客服故障与持续经营.md)。
