## 1. 从这里开始

目标是遇到陌生问题时，能明确输入输出、写出朴素方法，再根据约束选择结构、优化并验证。无需先把整个目录读完。

- **安排学习**：[十六周学习路线](./算法学习路线.md)，每周 `4` 次，每次 `30～45` 分钟；没过关就顺延。
- **开始练习**：仓库 `learning/algorithms/daily/day-01.md`，先独立完成一次数组扫描。
- **按周推进**：仓库 `learning/algorithms/roadmap.md` 链接全部十六周具体任务；每周有验收与复盘。
- **检查迁移**：[综合训练与验收](./综合训练与验收.md)，隐藏题型、改变约束、联系菜单树场景。

本目录已完成原有 `19` 个文档的整理，并补齐线性技巧、栈队列与综合训练。旧文件路径保留；原排序首页迁到[排序算法](./排序算法.md)，当前首页作为学习入口。代表实现提供可执行测试，其他变式明确作为独立练习，不把题单当成现成答案。

## 3. 文章与笔记的统一写法

每个专题围绕一个明确问题组织：

1. **问题与契约**：输入、返回值、允许修改什么、先修知识。
2. **朴素方法**：先有正确答案，再找重复工作或可排除范围。
3. **关键推导**：循环不变量、递归返回值或状态含义。
4. **最小实现**：默认 `JavaScript`，尽量让代码块独立运行。
5. **复杂度与边界**：计算复制、输出和递归栈，不省略关键条件。
6. **练习与证据**：手推、边界断言、隔日重写、约束变化与失败反例。

专题负责可复用的方法，题单负责迁移练习，不在多个文件重复维护同一套长实现。学习笔记只记录自己的推导与错因，避免再次积累大量无法解释的代码。

## 4. 整理范围与验证方式

本次统一了原文中的概念、重复内容、空章节和代码示例，包括二分漏查、层序队列误用、线性对数阶误写、零钱兑换误归类及动态规划状态含义等问题。原有大题单中重复或不可靠的实现已收敛为代表实现与带提示的变式练习。

所有保留的可执行算法示例都应由 `tests/algorithm-*.test.mjs` 直接读取文章代码验证，避免测试另抄一份实现。运行：

```sh
node --test tests/algorithm-*.test.mjs
```

发布前同时执行仓库检查：

```sh
pnpm test
pnpm run build
```

测试验证的是文章约定范围内的代表场景与边界，不是任意输入、无限规模或所有平台的证明。递归深度、数值安全范围、字符串单位、原地修改与复杂度模型以各篇契约为准。历史来源与示意图保留作参考，图中的结论以修订后的正文为准。

学习工作区的“待填写”是等待你实际练习后的证据，不能因为教程已整理完成而改成“通过”。
