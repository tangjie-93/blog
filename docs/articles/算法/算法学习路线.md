## 1. 目标与节奏

当前假设：已经能用 `JavaScript` 写业务代码，接触过算法，但独立解题的熟练度还需要摸底。历史文章数量不能证明当前掌握程度。

长期目标是能完成“理解约束 → 朴素解法 → 优化理由 → 正确实现 → 边界验证”的闭环，并逐步独立解决常见中等难度问题。`16` 个学习周是路线长度，不是水平保证，也不是考试截止日期。

- 每周 `4` 次，每次 `30～45` 分钟，约 `2～3` 小时。
- 每周以 `2～3` 道新题为上限，留下时间闭卷重做；遇到难点，一周只消化一道也可以。
- 前 `2` 周先建立扫描、计数和验证能力；今天只完成一个数组扫描任务。
- 如果只有 `15～20` 分钟，就做一次手推或重写，不追补题量。一个学习周可以跨两个自然周。
- 已熟悉某阶段时，用验收任务证明后跳过；反复失败则退回先修知识。

## 2. 十六个学习周

每行中的练习按从左到右推进，最后一项可作为选做。题名用于寻找练习，具体输入和约束以题面为准；自拟题按文字要求实现即可。

| 学习周 | 核心主题 | 练习顺序 | 本周验收 |
| --- | --- | --- | --- |
| `01` | 复杂度与数组扫描 | 自拟最大值扫描 → 移动零 | 能解释循环次数、辅助空间和输入是否被修改 |
| `02` | 哈希与计数 | 存在重复元素 → 两数之和 → 有效的字母异位词 | 能从重复查询推导存储信息；处理重复值与同一元素不能用两次 |
| `03` | 双指针与滑动窗口 | 验证回文串 → 有序数组去重 → 无重复字符的最长子串 | 能解释每个指针的含义，以及为什么移动它不会漏解 |
| `04` | 前缀和与基础回顾 | 自拟多次区间求和 → 一道数组混合题 | 定义前缀数组含义，解释区间端点；闭卷重做前两周错题 |
| `05` | 链表、栈与队列 | 反转链表 → 有效的括号 → 环形链表 | 画出指针更新；区分先进先出和后进先出 |
| `06` | 二分与排序入门 | 二分查找 → 搜索插入位置 → 自拟插入排序 | 统一一种区间约定；能测试无答案、首尾答案和重复值 |
| `07` | 递归与分治 | 自拟递归数组求和 → 自拟归并排序 | 定义函数返回值、终止条件和合并步骤；算上递归栈空间 |
| `08` | 二叉树 | 最大深度 → 层序遍历 → 验证二叉搜索树 | 能区分自顶向下的状态与自底向上的返回值 |
| `09` | 网格与图遍历 | 岛屿数量 → 图像渲染 | 能处理重复访问、环与不连通区域；解释访问标记时机 |
| `10` | 堆与优先队列 | 手推堆插入和删除 → 数组中第若干大元素 | 比较全排序与小顶堆的适用情况；正确维护堆性质 |
| `11` | 回溯 | 子集 → 全排列 | 解释路径、选择与撤销；输出结果不会随路径修改而变化 |
| `12` | 贪心 | 分发饼干 → 无重叠区间 | 给策略写正确性理由，能反驳一个看似合理的错误策略 |
| `13` | 动态规划入门 | 爬楼梯 → 打家劫舍 | 从递归推到记忆化；能逐字解释状态而不是背转移式 |
| `14` | 网格与序列动态规划 | 不同路径 → 最长递增子序列 | 推导初始化和依赖顺序，区分连续区间与非连续子序列 |
| `15` | 背包入门 | 自拟 `0/1` 背包 → 零钱兑换 | 区分物品是否可重复；解释一维优化时循环方向为何不同 |
| `16` | 混合练习与工程迁移 | 隐藏分类选两道基础或中等题 → 菜单树遍历小练习 | 独立选方法，处理空树、深层节点，解释复杂度并留下测试证据 |

前 `4` 周以简单题和手推为主。后续可以把某主题延长到 `2` 周，不通过验收就不赶进度。中等题遇阻可以先做对应的自拟小例子。

主线之后按需要增加单调栈、差分、并查集、拓扑排序和带权最短路；字符串匹配、平衡树、线段树、复杂背包和竞赛题继续后置。

## 3. 每周与每次怎么学

每周建议采用四次学习：

1. **理解**：读一个概念，手推例子，完成基础题的朴素解法。
2. **实现**：闭卷重写基础题，补边界；有余力再做一个变式。
3. **迁移**：做第二道题，比较相同方法的使用条件。
4. **回顾**：从旧题中选一道闭卷重做，再写本周复盘。

一次 `40` 分钟可以这样分配：`5` 分钟复述输入约束，`15` 分钟独立推导，`15` 分钟实现与验证，`5` 分钟记录错因。时间到了仍无思路，就记录尝试并寻求最小提示。

卡住时依次做：缩小输入 → 手算答案 → 写穷举 → 找重复工作 → 只看一个思路提示。需要看完整题解时，看完关闭页面再写，并将这次标为“借助题解”，不能记成独立完成。

复习起点建议为次日、第 `3` 天、第 `7` 天和第 `14` 天；它是可调整的提醒，不是必须每天完成的打卡。复习超量时暂停新题，优先重做最薄弱的两道。

## 4. 如何判断确实进步

每道题记录首次结果：**独立完成 / 提示后完成 / 题解后重写 / 尚未完成**。平台提交通过只说明当前实现通过了平台测试，不能单独证明自己理解。

一个主题过关，需要同时做到：

- 不看答案解释为什么选择该方法，以及什么条件改变后不能继续用。
- 独立实现一道代表题，并解释时间与空间复杂度。
- 给出至少 `3` 类相关边界用例和实际运行结果。
- 间隔至少 `3` 天后能闭卷重写，再尝试一个小变式。

首周只记录真实起点，不设正确率要求。每 `4` 个学习周对比：独立完成情况、提示依赖程度、复习保持情况、常见错误是否减少。记录样本数量，避免用两道题的正确率判断总体水平。

连续两次卡在同类问题时，用下一次学习补基础。例如二分总出错，就只手推左右端点；动态规划不会写，就先画递归树和状态表。

## 5. 笔记如何服务于解题

每道题只写最有价值的内容：

```text
题目与输入约束：
我的第一种方法及成本：
为什么可以优化：
循环不变量 / 递归返回值 / 状态定义：
失败用例与根因：
时间与辅助空间：
完成方式（独立 / 提示 / 题解）：
运行证据：
重做日期与结果：
约束变化后还能用吗：
```

例如移动零：关键不是记住两个指针，而是解释“已处理区间中哪些元素已按原顺序放好，下一次该写到哪里”。如果能用自己的话说清楚，再转成循环就容易检查。

使用 `AI` 时，先贴出自己的尝试、输入输出和卡点，请它给反例或追问；不要在第一次尝试前直接索要完整解法。

## 6. 资料与工作区

主参考只选一本：[Hello 算法](https://www.hello-algo.com/)。它包含复杂度、数组链表、哈希、树图、搜索、排序、回溯和动态规划等章节；每周只读对应章节，不需要从头背完。不同资料的结论冲突时，先核对输入契约与实现，再手推并运行例子确认。

第一周实题使用[移动零](https://leetcode.cn/problems/move-zeroes/)，重点是原地处理和保持非零元素顺序。题目之外可自行增加空数组等测试，并说明它们是否超出原题约束。

仓库中的 `learning/algorithms/` 保存个人计划和证据，不参与博客发布：

- `README.md`：目标与使用方式。
- `roadmap.md`：阶段里程碑及本学习路线入口。
- `weekly/week-01.md` 到 `weekly/week-16.md`：每周四次具体任务、先修、验收和调整。
- `daily/day-01.md`：今天的任务和验收。
- `notes/index.md`：笔记与错因索引。
- `demos/README.md`：练习文件和运行方式约定。
- `reviews/week-01-review.md`：第一周复盘；后续周的复盘直接填写在对应周文件末尾。
- `progress.md`：实际进度和下一步。

下次汇报只需带上代码、测试结果，以及一个最卡的问题，再根据证据调整下一周，而不是机械填满整个日历。


可在主线对应阶段查阅教材的[图遍历](https://www.hello-algo.com/chapter_graph/graph_traversal/)、[零一背包](https://www.hello-algo.com/chapter_dynamic_programming/knapsack_problem/)与[回溯](https://www.hello-algo.com/chapter_backtracking/backtracking_algorithm/)章节，作为本地推导的交叉参考。
