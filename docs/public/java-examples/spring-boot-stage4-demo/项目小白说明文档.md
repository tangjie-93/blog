# spring-boot-stage4-demo 项目小白说明文档

这份文档面向刚开始学习 Java 后端和 Spring Boot 的同学。它会用尽量直白的话解释：这个项目是做什么的、怎么启动、每个目录和文件有什么用、一次接口请求进来后代码是怎么流转的。

## 1. 这个项目是做什么的

`spring-boot-stage4-demo` 是一个 Spring Boot 入门示例项目。它模拟了一个简单的博客后端 API，包含：

- 用户列表、用户详情、注册、登录
- 文章分页列表、文章详情、创建文章、删除文章
- 评论列表、创建评论
- 统一 JSON 响应格式
- 参数校验
- 全局异常处理
- AOP 请求日志
- Knife4j / Swagger 接口文档
- Actuator 健康检查

项目现在已经连接 MySQL，不再默认使用内存里的 `ConcurrentHashMap` 模拟数据库。应用启动时会自动创建博客表结构和默认数据；运行期间新增的用户、文章、评论会保存到 MySQL，应用停止后数据不会丢失。

## 5. 一句话理解分层

这个项目采用常见的三层架构：

```text
浏览器 / Postman / 前端页面
        |
        v
Controller：接收 HTTP 请求
        |
        v
Service：处理业务规则
        |
        v
Repository：读写数据
        |
        v
MySQL：持久化保存数据
```

每一层只做自己的事：

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Controller | 接收请求、取参数、调用 Service、返回结果 | 不写复杂业务逻辑 |
| Service | 判断业务规则，比如用户名是否重复、文章是否存在 | 不关心 HTTP 细节 |
| Repository | 保存和查询数据 | 不判断业务规则 |
| Entity | 表示系统内部的数据对象 | 不直接返回给前端 |
| DTO | 表示前端传进来的请求参数 | 不代表数据库表 |
| VO | 表示返回给前端看的数据 | 不包含密码等敏感字段 |

## 6. 一次请求是怎么走的

以“注册用户”为例：

1. 用户发送 `POST /stage4/api/users/register`。
2. `UserController.register()` 接收到请求。
3. `@Valid` 校验 `UserCreateRequest`，比如用户名不能为空、密码长度不能太短。
4. Controller 调用 `UserService.register()`。
5. `UserServiceImpl.register()` 检查用户名是否已经存在。
6. 如果用户名重复，抛出 `BusinessException`。
7. 如果可以注册，创建 `User` 对象，交给 `UserRepository.save()` 保存。
8. `JdbcUserRepository` 通过 SQL 把用户保存到 MySQL。
9. Service 把 `User` 转成 `UserVO`，去掉密码。
10. Controller 用 `Result.success()` 包装成统一 JSON 返回。
11. 如果中间抛异常，`GlobalExceptionHandler` 会统一转成错误 JSON。

## 7. 根目录文件说明

### `pom.xml`

Maven 项目配置文件，决定项目叫什么、用什么 Java 版本、依赖哪些库、怎么打包。

重点内容：

- 父工程是 `spring-boot-starter-parent`，版本是 `3.2.12`。

- 使用 `spring-boot-maven-plugin`，方便用 Maven 启动和打包。

小白可以把 `pom.xml` 理解成“项目配方表”：项目需要什么能力，就在这里声明依赖。

### `README.md`

项目原始说明文件，简要介绍项目功能、启动方式、常用接口和后续练习方向。

### `项目小白说明文档.md`

当前这份详细说明文档，用于更系统地解释项目结构和每个文件用途。

### `target/`

Maven 编译、测试、运行时生成的输出目录。

常见内容：

- `target/classes/`：编译后的主程序文件和资源文件。
- `target/test-classes/`：编译后的测试文件。
- `target/surefire-reports/`：测试报告。
- `target/spring-boot-run.log`：之前启动项目时留下的运行日志。

注意：`target/` 是构建产物，不是手写源码。一般不用手动修改。

## 8. 配置文件说明

### `src/main/resources/application.yml`

主配置文件，所有环境都会读取。

里面配置了：

- `server.port: 8080`：服务端口是 8080。
- `server.servlet.context-path: /stage4`：所有接口前面都会带 `/stage4`。

- `management.endpoints`：Actuator 暴露健康检查、信息、指标接口。

### `src/main/resources/application-dev.yml`

开发环境配置。默认会启用它。

主要作用：

- 把 `com.example.stage4` 日志级别设为 `debug`。
- 配置 MySQL 连接地址、用户名、密码。
- 配置启动时执行 `sql/blog-schema.sql` 初始化表结构。
- 覆盖 `app.description`，说明当前是开发环境。

小白理解：本地开发时更需要看到详细日志，所以用 dev 配置。

### `src/main/resources/application-prod.yml`

生产环境配置示例。

主要作用：

- 开启响应压缩。
- 把项目日志级别设为 `info`。
- 覆盖 `app.description`，提示真实项目应接入 MySQL、Redis、安全认证、集中日志等。

小白理解：线上运行不应打印太多调试日志，所以比 dev 更克制。

### `src/main/resources/sql/blog-schema.sql`

博客系统的数据库建表示例。

包含三张表：

- `sys_user`：用户表。
- `article`：文章表。
- `comment`：评论表。

当前项目启动时会自动执行这个 SQL。脚本使用 `CREATE TABLE IF NOT EXISTS` 和 `INSERT IGNORE`，重复启动不会删除已有数据。

## 10. common 通用返回对象

### `common/Result.java`

统一响应体。

项目所有接口返回 JSON 时，都尽量保持同一种格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-07-02 10:00:00"
}
```

这样前端处理起来更稳定：

- `code`：业务状态码。
- `message`：提示信息。
- `data`：真正的数据。
- `timestamp`：响应时间。

里面提供了几个静态方法：

- `Result.success(data)`：成功返回。
- `Result.success(message, data)`：成功并带自定义提示。
- `Result.fail(code, message)`：失败返回。

### `common/PageResult.java`

分页结果对象。

文章列表接口会用到它，字段包括：

- `list`：当前页的数据。
- `total`：符合条件的总条数。
- `page`：当前页码。
- `size`：每页条数。
- `totalPages`：总页数。

小白理解：当数据很多时，不一次性全返回，而是分页返回。

## 11. config 配置类

### `config/AppProperties.java`

读取 `application.yml` 里 `app` 开头的配置。

例如配置文件里有：

```yaml
app:
  name: 阶段4 Spring Boot Demo
  version: 1.0.0
  description: 面向小白的 Spring Boot 分层架构示例
```

`AppProperties` 会把它们映射成 Java 字段：

- `name`
- `version`
- `description`

首页接口会读取这些配置并返回。

### `config/JacksonConfig.java`

JSON 全局配置。

主要做两件事：

1. 统一 `LocalDateTime` 的 JSON 格式为 `yyyy-MM-dd HH:mm:ss`。
2. 把 `Long` 类型转成字符串返回，避免 JavaScript 处理大整数时丢精度。

小白理解：后端对象变成 JSON 时，格式由 Jackson 管。这个类就是在调整 JSON 输出规则。

### `config/RequestLogAspect.java`

AOP 请求日志切面。

它会拦截 `controller` 包下的方法，记录：

- 请求方法，比如 `GET`、`POST`。
- 请求地址，比如 `/stage4/api/users`。
- 接口耗时。
- 如果接口失败，也会记录失败信息。

优点是：不用在每个 Controller 方法里重复写日志代码。

### `config/WebConfig.java`

Web 全局配置。

当前主要配置了 CORS，也就是跨域访问。

为什么需要跨域：

- 前端开发服务器可能是 `http://localhost:5173`。
- 后端是 `http://localhost:8080`。
- 浏览器会认为这是不同来源，需要后端允许访问。

当前示例为了方便学习，跨域配置放得比较宽。真实生产项目应该限制成明确的前端域名。

## 15. vo 返回展示对象

VO 是 View Object，可以理解为“返回给前端看的数据”。

为什么不直接返回 Entity：

- Entity 可能包含敏感字段，比如 `User.password`。
- Entity 的结构更贴近数据库，不一定适合前端展示。
- VO 可以把多个对象组装起来，比如文章里带作者信息。

### `vo/UserVO.java`

用户展示对象。

字段：

- `id`
- `username`
- `nickname`
- `email`
- `createdAt`

不包含 `password`。

### `vo/ArticleVO.java`

文章展示对象。

字段：

- `id`
- `title`
- `content`
- `summary`
- `category`
- `tags`
- `author`
- `viewCount`
- `createdAt`

其中 `author` 是 `UserVO`，说明返回文章时会附带作者展示信息。

### `vo/CommentVO.java`

评论展示对象。

字段：

- `id`
- `articleId`
- `user`
- `content`
- `createdAt`

其中 `user` 是 `UserVO`，说明返回评论时会附带评论用户信息。

## 16. repository 数据访问层

Repository 是“数据管理员”。Service 要数据时，找 Repository；Service 要保存数据时，也找 Repository。

这个项目先定义接口，再提供 JDBC 实现。Service 层依赖的是接口，所以从“内存 Map”切换到“MySQL”时，Controller 和 Service 基本不用改。

### `repository/UserRepository.java`

用户仓库接口。

定义了用户数据操作能力：

- `findAll()`：查询所有用户。
- `findById(Long id)`：按 ID 查询用户。
- `findByUsername(String username)`：按用户名查询用户。
- `save(User user)`：保存用户。

### `repository/JdbcUserRepository.java`

用户仓库的 MySQL 实现。

关键点：

- 用 `JdbcTemplate` 执行 SQL。
- 从 `sys_user` 表查询用户。
- 新增用户时使用数据库自增 ID。
- `save()` 根据是否有 ID 决定新增或更新。
- `findByUsername()` 用于注册和登录时查询用户。

默认用户：

```text
username: admin
password: 123456
```

### `repository/ArticleRepository.java`

文章仓库接口。

定义了文章数据操作能力：

- `findAll()`：查询所有文章。
- `findById(Long id)`：按 ID 查询文章。
- `save(Article article)`：保存文章。
- `deleteById(Long id)`：删除文章。

### `repository/JdbcArticleRepository.java`

文章仓库的 MySQL 实现。

关键点：

- 用 `JdbcTemplate` 执行 SQL。
- 从 `article` 表查询文章。
- 新增文章时使用数据库自增 ID。
- `tags` 字段在数据库里用逗号分隔字符串保存，读取后再转成 `List<String>`。
- `findAll()` 按 ID 倒序返回，新的文章排前面。

默认文章标题：

```text
Spring Boot 第一篇文章
```

### `repository/CommentRepository.java`

评论仓库接口。

定义了评论数据操作能力：

- `findByArticleId(Long articleId)`：查询某篇文章下的评论。
- `save(Comment comment)`：保存评论。

### `repository/JdbcCommentRepository.java`

评论仓库的 MySQL 实现。

关键点：

- 用 `JdbcTemplate` 执行 SQL。
- 从 `comment` 表查询评论。
- 新增评论时使用数据库自增 ID。
- `findByArticleId()` 只返回指定文章的评论。
- 保存评论时自动设置创建时间。

## 17. service 业务层

Service 是“业务规则中心”。它负责判断事情能不能做，以及怎么做。

### `service/UserService.java`

用户业务接口。

定义能力：

- `listUsers()`：用户列表。
- `getUser(Long id)`：用户详情。
- `register(UserCreateRequest request)`：注册用户。
- `login(LoginRequest request)`：登录。

### `service/impl/UserServiceImpl.java`

用户业务实现。

主要逻辑：

- 查询用户列表时，把 `User` 转成 `UserVO`。
- 查询用户详情时，如果用户不存在，抛出 `BusinessException(404, "用户不存在")`。
- 注册用户时，先检查用户名是否重复。
- 登录时，检查用户名和密码是否正确。
- 登录成功后返回一个演示用 token：`demo-token-user-{id}`。

重要提醒：

- 当前密码是明文保存，只适合学习演示。
- 当前 token 是假的演示 token，不是真实 JWT。
- 真实项目必须加密密码，并使用成熟的认证方案。

### `service/ArticleService.java`

文章业务接口。

定义能力：

- `listArticles(...)`：分页查询文章。
- `getArticle(Long id)`：文章详情。
- `createArticle(ArticleCreateRequest request)`：创建文章。
- `deleteArticle(Long id)`：删除文章。
- `createComment(Long articleId, CommentCreateRequest request)`：创建评论。
- `listComments(Long articleId)`：评论列表。

### `service/impl/ArticleServiceImpl.java`

文章业务实现。

主要逻辑：

- 文章列表支持按分类和标签过滤。
- 文章列表目前在 Service 层对查询结果手动分页。
- 查看文章详情时，浏览次数 `viewCount` 加 1。
- 创建文章前，会检查作者用户是否存在。
- 删除文章前，会检查文章是否存在。
- 创建评论前，会检查文章和用户是否存在。
- 返回文章时，会组装作者 `UserVO`。
- 返回评论时，会组装评论用户 `UserVO`。
- `buildSummary()` 会把超过 50 个字符的正文截成摘要。

## 18. exception 异常处理

### `exception/BusinessException.java`

业务异常。

适合表示“业务规则不通过”的情况，例如：

- 用户不存在。
- 用户名已存在。
- 文章不存在。
- 用户名或密码错误。

它包含：

- `code`：业务错误码。
- `message`：错误提示。

### `exception/GlobalExceptionHandler.java`

全局异常处理器。

有了它，Controller 不需要到处写 `try-catch`。只要业务代码抛异常，Spring 会把异常交给这个类统一处理。

它处理的异常包括：

- `BusinessException`：业务异常。
- `MethodArgumentNotValidException`：请求体参数校验失败，比如 `@RequestBody` 上的 `@Valid`。
- `BindException`：参数绑定失败。
- `ConstraintViolationException`：请求参数校验失败，比如 `@RequestParam` 上的 `@Min`。
- `Exception`：其他未预料异常。

最终都会返回统一的 `Result` JSON。

## 21. 重点注解解释

| 注解 | 出现位置 | 作用 |
| --- | --- | --- |
| `@SpringBootApplication` | 启动类 | 启动 Spring Boot 自动配置和组件扫描 |
| `@RestController` | Controller | 声明这是返回 JSON 的接口类 |
| `@RequestMapping` | Controller | 定义一组接口的基础路径 |
| `@GetMapping` | Controller | 定义 GET 接口 |
| `@PostMapping` | Controller | 定义 POST 接口 |
| `@DeleteMapping` | Controller | 定义 DELETE 接口 |
| `@RequestBody` | Controller 参数 | 从 JSON 请求体读取参数 |
| `@PathVariable` | Controller 参数 | 从路径中读取参数，例如 `/users/{id}` |
| `@RequestParam` | Controller 参数 | 从查询字符串读取参数，例如 `?page=1` |
| `@Valid` | Controller 参数 | 开启对象参数校验 |
| `@Validated` | Controller 类 | 开启方法参数校验 |
| `@Service` | Service 实现 | 声明业务层组件 |
| `@Repository` | Repository 实现 | 声明数据访问组件 |
| `@Configuration` | 配置类 | 声明配置类 |
| `@Bean` | 配置方法 | 把方法返回值交给 Spring 管理 |
| `@ConfigurationProperties` | 配置类 | 把 YAML 配置映射到 Java 对象 |
| `@RestControllerAdvice` | 异常处理类 | 全局处理 Controller 异常 |
| `@ExceptionHandler` | 异常处理方法 | 指定处理哪种异常 |
| `@Aspect` | AOP 类 | 声明切面 |
| `@Around` | AOP 方法 | 包裹目标方法执行前后逻辑 |
| `@PostConstruct` | Repository 初始化方法 | Spring 创建对象后自动执行初始化 |
| `@Schema` | DTO/VO | 生成接口文档说明 |

## 22. 初学者推荐阅读顺序

建议不要一上来就从头到尾看所有代码。可以按这个顺序：

1. 看 `README.md` 和本说明文档，先知道项目目标。
2. 看 `pom.xml`，知道项目依赖了哪些能力。
3. 看 `Stage4Application.java`，知道 Spring Boot 从哪里启动。
4. 看 `application.yml`，知道端口、路径、环境配置在哪里。
5. 看 `controller/UserController.java`，理解接口怎么写。
6. 看 `dto/UserCreateRequest.java`，理解请求参数和校验。
7. 看 `service/impl/UserServiceImpl.java`，理解业务逻辑放在哪里。
8. 看 `repository/JdbcUserRepository.java`，理解数据怎么保存到 MySQL。
9. 看 `vo/UserVO.java`，理解为什么返回给前端的对象不包含密码。
10. 看 `exception/GlobalExceptionHandler.java`，理解异常怎么统一返回。
11. 看 `config/RequestLogAspect.java`，理解 AOP 日志。
12. 再看文章和评论相关代码，巩固同样的分层思路。

## 23. 当前项目的简化点和真实项目差异

这个项目为了入门学习做了很多简化：

| 当前项目 | 真实项目通常会怎么做 |
| --- | --- |
| 数据已经存在 MySQL | 真实项目还会按业务拆表、建索引、做迁移脚本管理 |
| 密码明文保存 | 密码必须加密哈希保存 |
| 登录返回简单字符串 token | 使用 JWT、Session 或 OAuth2 |
| 没有权限校验 | 使用 Spring Security 做认证授权 |
| 没有事务 | 数据库写操作通常需要事务 |
| 评论删除文章后不级联处理 | 真实项目要考虑关联数据一致性 |
| 标签存在 `List<String>` | 真实数据库常拆成标签表和关联表 |
| 测试只有容器启动测试 | 真实项目应补 Controller、Service、Repository 测试 |

这些简化不是错误，而是为了先把 Spring Boot 的主线学清楚。

## 24. 如果要继续练习，可以怎么改

适合下一阶段练习的方向：

1. 把 JDBC Repository 替换成 MyBatis-Plus 或 Spring Data JPA。
2. 扩展 `blog-schema.sql`，增加标签表、文章标签关联表等结构。
3. 给注册和登录增加密码加密。
4. 用 Spring Security + JWT 实现真正登录鉴权。
5. 给创建、删除文章增加权限判断。
6. 删除文章时同时删除评论。
7. 增加修改文章、修改用户资料接口。
8. 给 Controller 和 Service 补充单元测试。
9. 增加统一请求日志里的请求参数、响应状态。
10. 增加 Dockerfile，把项目打包成容器运行。

## 25. 最核心的一句话

这个项目的重点不是做一个完整博客系统，而是让你看懂一个 Spring Boot 后端项目的基本骨架：

```text
配置文件决定应用怎么运行
Controller 接请求
DTO 接参数
Service 写业务
Repository 管数据
Entity 表示内部数据
VO 返回给前端
Result 统一响应格式
GlobalExceptionHandler 统一处理错误
```

把这条线理解透，再接数据库、登录鉴权、缓存、事务，就会容易很多。
