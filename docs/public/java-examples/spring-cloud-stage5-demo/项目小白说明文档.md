# Spring Cloud Stage 5 Demo 项目小白说明文档

## 1. 这个项目是干什么的

这是一个“微服务电商系统”的学习项目。

它不是一个完整商城，而是用最小代码演示阶段 5 文档里的核心知识：

- API 网关怎么统一接收请求
- 用户服务、商品服务、订单服务怎么拆开
- 订单服务怎么调用用户服务和商品服务
- OpenFeign、Gateway、Nacos、Sentinel、RabbitMQ、Seata 分别放在什么位置

你可以把它理解成一个简化版电商系统：

```text
用户服务：负责用户信息
商品服务：负责商品信息和库存
订单服务：负责创建订单
网关服务：负责统一入口，把请求转发给对应服务
```

## 2. 为什么要拆成多个服务

阶段 4 的 Spring Boot 项目通常是单体应用：

```text
一个项目里同时写用户、商品、订单、文章、评论等所有功能
```

阶段 5 开始学习微服务：

```text
用户功能放到用户服务
商品功能放到商品服务
订单功能放到订单服务
外部请求先进入网关
服务之间通过 HTTP 调用
```

这样做的好处是：

- 每个服务职责更清楚
- 某个服务可以单独启动、单独部署
- 用户服务挂了，不一定影响商品服务
- 项目大了以后，不同团队可以负责不同服务

代价是：

- 项目结构更复杂
- 服务之间要互相调用
- 要考虑注册中心、网关、限流、消息队列、分布式事务

所以这个项目先做一个“能看懂、能跑通”的版本。

## 4. 每个服务的端口

| 服务 | 模块 | 端口 |
| --- | --- | --- |
| 网关服务 | `gateway` | `9000` |
| 用户服务 | `service-user` | `8081` |
| 订单服务 | `service-order` | `8082` |
| 商品服务 | `service-product` | `8083` |

为什么端口不一样？

因为每个微服务都是一个独立的 Spring Boot 应用。它们要同时启动，所以不能都占用 `8080`。

## 5. 请求是怎么流动的

以“创建订单”为例。

你访问的是网关：

```text
POST http://127.0.0.1:9000/api/orders
```

实际流程是：

```text
浏览器 / curl
  |
  v
gateway:9000
  |
  v
service-order:8082
  |
  |-- OpenFeign 调用 --> service-user:8081 查询用户
  |
  |-- OpenFeign 调用 --> service-product:8083 查询商品
  |
  |-- OpenFeign 调用 --> service-product:8083 扣减库存
  |
  v
订单服务生成订单
```

所以你只访问了 `9000`，但背后其实经过了多个服务。

## 6. 先不用管 Nacos 也能运行吗

能。

这个项目默认是“本地直连模式”，先不强制依赖 Nacos、RabbitMQ、Seata。

原因是：刚开始学习微服务时，如果一上来就要安装很多中间件，很容易卡在环境问题上。这个项目先让你看懂服务拆分和服务调用。

默认模式下：

```text
网关直接转发到 http://127.0.0.1:8081
网关直接转发到 http://127.0.0.1:8082
网关直接转发到 http://127.0.0.1:8083

订单服务直接调用 http://127.0.0.1:8081
订单服务直接调用 http://127.0.0.1:8083
```

等你理解清楚以后，再开启 Nacos 模式：

```text
服务启动后注册到 Nacos
网关通过服务名找服务
订单服务通过服务名调用用户服务和商品服务
```

## 7. 怎么启动项目

先进入项目目录：

```powershell
cd D:\personal\study\code\spring-cloud-stage5-demo
```

先确认能编译：

```powershell
mvn test
```

再启动全部服务：

```powershell
mvn -pl service-user spring-boot:run
mvn -pl service-product spring-boot:run
mvn -pl service-order spring-boot:run
mvn -pl gateway spring-boot:run
```

注意：这 4 条命令需要分别在 4 个 PowerShell 窗口里执行，因为每个服务启动后都会一直运行。

这 4 条命令会启动：

```text
service-user
service-product
service-order
gateway
```

启动后，网关地址是：

```text
http://127.0.0.1:9000
```

### 9.4 订单服务

接口文件：

```text
service-order/src/main/java/com/example/stage5/order/controller/OrderController.java
```

```java
userClient.getUser(1L)
```

## 10. common 模块是干什么的

`common` 模块放公共类。

比如统一返回结构：

```text
common/src/main/java/com/example/stage5/common/ApiResult.java
```

所有接口都返回类似结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

公共 DTO：

```text
UserDTO
ProductDTO
OrderCreateRequest
OrderVO
```

为什么要放 common？

因为订单服务调用用户服务时，也需要知道用户返回的数据长什么样。与其每个服务都复制一份 `UserDTO`，不如放到公共模块。

## 11. Nacos 在这个项目里的位置

Nacos 是注册中心。

你可以先这样理解：

```text
每个服务启动后，去 Nacos 报到：
我是 service-user，我的地址是 127.0.0.1:8081
我是 service-product，我的地址是 127.0.0.1:8083
我是 service-order，我的地址是 127.0.0.1:8082
```

然后网关或订单服务不需要写死 IP 和端口，可以通过服务名找到目标服务。

本项目默认关闭 Nacos：

```yaml
enabled: ${NACOS_ENABLED:false}
```

如果要开启：

```powershell
$env:NACOS_ENABLED='true'
$env:SPRING_PROFILES_ACTIVE='nacos'
```

然后分别执行：

```powershell
mvn -pl service-user spring-boot:run
mvn -pl service-product spring-boot:run
mvn -pl service-order spring-boot:run
mvn -pl gateway spring-boot:run
```

开启后，网关配置会从：

```text
http://127.0.0.1:8081
```

变成：

```text
lb://service-user
```

`lb` 是 load balance，表示通过服务名做负载均衡。

## 12. Gateway 在这个项目里的位置

Gateway 是统一入口。

如果没有 Gateway，前端要记住很多地址：

```text
用户服务：http://127.0.0.1:8081
订单服务：http://127.0.0.1:8082
商品服务：http://127.0.0.1:8083
```

有了 Gateway，前端只需要记住：

```text
http://127.0.0.1:9000
```

然后：

```text
/api/users    走用户服务
/api/products 走商品服务
/api/orders   走订单服务
```

这个思想和前端项目里用 Nginx 做反向代理很像。

## 13. OpenFeign 在这个项目里的位置

OpenFeign 用在订单服务里。

订单服务创建订单时，需要知道：

```text
这个用户存在吗？
这个商品存在吗？
商品库存够不够？
```

这些信息不在订单服务自己手里，所以它要调用：

```text
用户服务
商品服务
```

对应代码：

```text
service-order/src/main/java/com/example/stage5/order/client/UserClient.java
service-order/src/main/java/com/example/stage5/order/client/ProductClient.java
```

订单服务里直接这样调用：

```java
userClient.getUser(request.userId());
productClient.getProduct(request.productId());
productClient.deductStock(product.id(), request.quantity());
```

这就是“服务间调用”。

## 14. Sentinel 在这个项目里的位置

Sentinel 用来做限流和降级。

你可以先理解成：

```text
如果某个接口访问太多，Sentinel 可以拦住一部分请求
如果某个服务出问题，Sentinel 可以返回兜底结果
```

项目里有两类演示：

控制器方法上：

```java
@SentinelResource(value = "createOrder", blockHandler = "handleCreateOrderBlock")
```

Feign fallback：

```text
UserClientFallback
ProductClientFallback
```

比如商品服务挂了，订单服务调用商品服务失败，就可以走 fallback，返回一个更友好的失败信息。

## 15. RabbitMQ 在这个项目里的位置

RabbitMQ 用来做异步消息。

正常创建订单后，后续可能还有很多事情：

```text
发短信
发邮件
通知仓库
生成日志
更新统计数据
```

这些事情不一定要在创建订单接口里同步完成，可以先发一条消息，让其他消费者慢慢处理。

本项目里定义了：

```text
交换机：stage5.order.exchange
队列：stage5.order.created.queue
路由键：order.created
```

对应文件：

```text
service-order/src/main/java/com/example/stage5/order/config/RabbitConfig.java
service-order/src/main/java/com/example/stage5/order/config/OrderMessageListener.java
```

默认没有开启 RabbitMQ，因为本地不一定装了 RabbitMQ。

如果你已经启动 RabbitMQ，可以设置：

```powershell
$env:RABBITMQ_ENABLED='true'
```

然后再启动项目。

## 16. Seata 在这个项目里的位置

Seata 用来处理分布式事务。

什么叫分布式事务？

比如创建订单时，至少涉及两个服务：

```text
订单服务：保存订单
商品服务：扣减库存
```

理想情况：

```text
订单创建成功，库存也扣减成功
```

最怕这种情况：

```text
库存扣了
订单创建失败
```

这就造成数据不一致。

Seata 的作用就是尽量保证多个服务之间的操作要么都成功，要么都回滚。

本项目里在订单创建方法上放了：

```java
@GlobalTransactional(name = "stage5-create-order", rollbackFor = Exception.class)
```

对应文件：

```text
service-order/src/main/java/com/example/stage5/order/service/OrderService.java
```

默认关闭 Seata：

```yaml
seata:
  enabled: ${SEATA_ENABLED:false}
```

因为真正使用 Seata 还需要启动 Seata Server，并且数据库里要准备 `undo_log` 表。这个项目先让你知道它应该放在哪里。

## 17. 为什么现在用内存数据

用户、商品、订单现在都存在 Java 内存 Map 里。

好处：

```text
不用安装 MySQL
不用建表
不用配置数据库账号密码
一启动就能看懂微服务调用流程
```

缺点：

```text
服务重启后数据会丢
不是生产项目写法
不能演示真实数据库事务
```

后续你可以继续升级：

```text
service-user 使用 user_db
service-product 使用 product_db
service-order 使用 order_db
每个服务有自己的数据库
```

这才更接近真实微服务项目。

## 18. 常见问题

### 18.1 端口被占用怎么办

如果启动失败提示端口占用，检查这些端口：

```text
9000
8081
8082
8083
```

可以在对应模块的 `application.yml` 里修改：

```yaml
server:
  port: 8081
```

### 18.2 为什么启动后访问 9000 没反应

可能原因：

```text
gateway 没启动成功
对应后端服务没启动成功
端口被占用
脚本启动还没完成，服务还在初始化
```

先看日志文件：

```text
gateway.log
gateway.err.log
service-user.log
service-user.err.log
service-product.log
service-product.err.log
service-order.log
service-order.err.log
```

这些日志会生成在项目根目录。

### 18.3 为什么不用数据库

因为这个项目第一目标是学习微服务结构，而不是数据库。

数据库会在后续版本里更适合加入：

```text
先理解服务拆分
再理解服务调用
再加入数据库
再加入 RabbitMQ、Seata、Redis
```

### 18.4 为什么默认不开 Nacos

因为 Nacos 是额外中间件，需要单独下载和启动。

为了让项目第一次就能跑通，默认先用本地固定地址。等你理解网关和 Feign 后，再打开 Nacos。

### 18.5 为什么订单服务要调用商品服务扣库存

因为库存属于商品服务的数据。

微服务里有一个重要原则：

```text
谁拥有数据，谁负责修改数据
```

订单服务不能直接修改商品服务的数据，只能通过商品服务提供的接口来扣库存。

## 19. 建议学习顺序

建议按这个顺序看代码：

```text
1. README.md
2. 项目小白说明文档.md
3. common 模块
4. service-user 用户服务
5. service-product 商品服务
6. service-order 订单服务
7. gateway 网关
8. application-nacos.yml
9. RabbitConfig
10. Seata 注解位置
```

不要一开始就纠结所有中间件。

先把这条主线看懂：

```text
请求进入网关
网关转发到订单服务
订单服务用 Feign 调用户服务和商品服务
订单服务生成订单
网关把结果返回给调用方
```

这条线通了，阶段 5 的微服务基础就有了。

## 20. 下一步可以怎么扩展

你可以按这个顺序继续升级项目：

```text
1. 给每个服务加 MySQL 数据库
2. 把内存 Map 改成 MyBatis-Plus
3. 启动 Nacos，改成服务注册与发现
4. 启动 Sentinel Dashboard，配置限流规则
5. 启动 RabbitMQ，处理订单创建消息
6. 启动 Seata，演示真实分布式事务
7. 给网关加 JWT 鉴权
8. 加一个前端页面调用网关接口
```

每一步都只解决一个问题，不要一次性全加。
