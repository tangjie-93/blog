# 技能、插件和 MCP，应该怎么选

[返回 AI 工具箱](/skills/) · [技能入门指南](/skills/guide.html)

## 三者分别解决什么问题

| 类型 | 可以怎样理解 | 例子 |
| --- | --- | --- |
| `Skill` | 给助手的任务操作手册，说明何时用、怎么做和怎样验收 | 按流程排查故障，制作演示文稿 |
| `Plugin` | 一个可安装的能力包，可以包含技能、工具连接与配套资源 | `Cloudflare` 插件同时提供开发技能和服务声明 |
| `MCP` | 连接外部工具与数据的协议；目录中的条目是服务配置记录 | 连接 `GitHub` 服务读取仓库上下文 |

三者不是同一种东西。插件不一定有技能，也不一定有 `MCP`；有技能也不代表已经连接对应账号。可参阅 [OpenAI 插件架构](https://developers.openai.com/plugins/concepts/plugins) 和 [MCP 官方介绍](https://modelcontextprotocol.io/docs/getting-started/intro)。

## 从你想完成的事情开始

如果任务是“帮我检查这段代码”或“根据素材制作文稿”，先找技能。如果缺的是一组相关能力，查看插件。如果需要读取云端仓库、查询账户资源或调用本地外部程序，再检查工具连接。

比如调查一次部署失败，可以先用部署技能组织排查步骤，再通过已授权的工具读取构建日志。若连接尚未建立，技能只能使用你已经提供的材料，不能凭空读到远端数据。

## 插件如何使用

1. 在当前客户端提供的插件管理入口查找目标插件，核对名称和来源。
2. 安装并启用；如果带有应用连接器，按提示完成账号连接。
3. 查看实际出现的技能与工具，先用只读任务确认可用范围。
4. 提供项目、文件或资源名称，明确希望得到的结果。

```text
请检查当前环境是否提供【插件名称】。
如果已启用，说明它提供的技能和工具，以及哪些连接仍需授权。
我想完成【具体任务】，材料是【文件或项目】。
先确认可用能力，不要假装已读取无法访问的数据。
```

插件的技能数量不代表其全部能力。此目录中的 `GitHub` 与 `Codex App Tools` 没有技能文件，但仍可能提供工具；反过来，只有技能的插件也可以完成不需要外部连接的任务。

## MCP 如何配置与验证

`Codex` 支持连接本地进程式服务和远程服务。前者依赖自己电脑上的运行程序，后者通常需要可达的服务地址与授权。具体配置和登录方法以 [Codex 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 为准。

配置前先确认服务来自哪里、要访问什么、实际需要哪些权限。通过插件加载的服务优先沿用插件的连接方式；手动配置则使用服务提供方的官方说明。不要直接复制别人电脑的启动路径，也不要把令牌贴进公开提示词或代码仓库。

配置后分开验证这三件事：

1. **是否加载**：客户端识别到了服务配置，且没有被禁用。
2. **是否连接**：进程成功启动，或远程服务完成认证并响应。
3. **是否能完成任务**：实际工具列表包含所需能力，并具有目标资源的访问权限。

```text
请检查【服务名称】MCP 的连接状态。
列出当前实际可用的工具，解释每个工具的用途。
尝试读取【明确授权的测试资源】，不要修改任何数据。
分别报告配置、连接和访问权限是否正常；不输出凭据。
```

`MCP` 没有统一的“复制技能名即可调用”规则。任务中可以说明服务名称与目标，由助手使用当前实际加载的工具。目录里的提示词是检查和任务示例，不是服务安装命令。
