# 第一次使用技能，从一个具体任务开始

[返回 AI 工具箱](/skills/) · [了解插件安装与 MCP 连接](/skills/connections.html)

## 技能到底是什么

你可以把 `Skill` 理解为一份给 `Codex` 使用的任务操作手册：说明什么时候用、按什么步骤做、需要哪些工具，以及怎样检查结果。比如“检查网页”可以细化为打开页面、操作按钮、观察报错、保存截图。

技能通常以 `SKILL.md` 为入口，可以附带脚本、参考资料和模板；插件则可以打包多个技能和工具连接。调用技能不等于自动获得对应网站的账号、服务额度或文件权限。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)

这个目录是作者本地环境的整理快照。看到一张卡片，不代表你的电脑已经安装了它；复制提示词也不会自动安装技能。

## 三步完成第一次任务

### 先选一个具体目标

不要从“哪个技能最厉害”开始。先说清楚你想得到什么，再搜索任务词：

| 我想做什么 | 可以先看 | 先准备什么 |
| --- | --- | --- |
| 检查网页按钮和手机布局 | `playwright` | 页面地址、操作步骤、预期效果 |
| 看懂一个陌生项目 | `codebase-summary` | 已打开的项目、最想弄懂的问题；先确认技能可见 |
| 整理学习计划 | `tech-learning-coach` | 已有基础、每天时间、最终作品 |
| 处理表格文件 | `spreadsheets:Spreadsheets` | 表格文件、数据含义、希望得到的分析 |
| 制作演示文稿 | `presentations:Presentations` | 面向谁、主题、素材、页数 |
| 看懂财报 | `earnings-review` | 公司、报告期间、官方报告 |
| 查当前官方用法 | `openai-docs` | 产品名、具体问题、使用环境 |

### 确认技能可用，再提供材料

在 `Codex CLI` 或编辑器扩展中，可通过 `/skills` 查看技能，或输入 `$` 选择技能；也可以直接在任务中写“请使用某某技能”。模型还可能根据任务自动选择相关技能。重名时注明插件来源，并以你当前技能选择器中的名称为准。[官方调用方式](https://learn.chatgpt.com/docs/build-skills)

如果找不到技能，先确认是否安装、启用或需要重启。可以让 `skill-installer` 查询支持的技能，或提供一个你信任的技能仓库地址。个人技能未必有公开安装地址，不要凭目录中的名称猜测仓库。

```text
请检查当前环境是否提供 playwright 技能。
如果有，说明它需要哪些工具；如果没有，请告诉我缺少什么，不要假装已经使用。
```

准备材料时，给出项目内路径、上传文件或页面地址。把卡片提示词中的【占位内容】换成真实信息，尤其要说明目标平台，例如网页、微信小程序或手机应用。

### 说清楚交付物，并检查结果

```text
使用 $playwright。
页面地址：【本地网站地址】。
请检查搜索、分页和手机布局，分别在桌面和手机宽度操作。
预期：搜索能找到对应内容，翻页后列表更新，手机端没有横向滚动。
请输出操作记录、发现的问题和截图，不提交真实留言。
```

拿到结果后打开文件、看截图或重走操作。若不符合预期，补充实际结果继续修改，例如“第二页还是第一页的数据，请沿用刚才的测试继续排查”。技能提供做事方法，结果仍需要验收。

## 一份能反复使用的提示词结构

```text
请使用【技能调用名】技能，帮我完成【具体任务】。
背景：【我现在的情况、面向谁】。
材料：【文件路径、项目或网址】。
要求：【范围、格式、平台、截止条件】。
交付：【我希望得到的文件、修改或报告】。
验收：【怎样判断做对了】。
缺少必要材料时先指出缺口；无法验证的部分请明确标注。
```

任务越具体，越容易判断结果。比如“帮我优化项目”可以改成“查找列表页首次加载慢的原因，给出测量结果，修复最主要的问题，再比较修改前后”。

## 相似技能怎么选

| 容易混淆的技能 | 选择方法 |
| --- | --- |
| `vue-testing` 与三个测试子技能 | 不知道该测哪层时用总入口；已确定是组件测试、浏览器验收或测试质量审查时选对应子技能 |
| `playwright` 与 `vue-testing-e2e` | 前者偏浏览器操作与取证，后者偏结合项目风险验收完整业务流程 |
| `spreadsheets:Spreadsheets` 与 `spreadsheets:excel-live-control` | 前者处理表格文件；后者需要已连接的实时 `Excel` 会话 |
| 本地 `pdf` 与插件 `pdf:pdf` | 都处理文档，但来源、工具和流程不同；阅读卡片前提并注明要用哪一个 |
| `skill-creator` 与 `template-creator:template-creator` | 前者把工作流程做成技能；后者根据参考产物创建可复用的个人模板技能 |
| `ponytail-review` 与 `ponytail-audit` | 前者审查一组改动，后者检查整个仓库 |
| `earnings-review` 与 `earnings-team` | 前者精读一份财报，后者组织多个分析视角，所需材料和时间通常更多 |

开发类技能应匹配实际技术栈。面向 `React` 或 `Next.js` 的流程不能直接当作 `Vue`、`uni-app` 的项目规范。个人规范也不等于框架官方规定。

## 遇到问题时怎么办

- **提示找不到技能**：核对调用名、来源以及当前技能列表。目录名可能不同于调用名，例如模板规范实际名为 `vue-template-standards`。
- **能调用，但工具不可用**：查看卡片中的“使用前提”。浏览器、桌面软件、云平台连接和脚本需要各自可用。
- **复制按钮失败**：浏览器可能未授予剪贴板权限；直接选中提示词文本手动复制即可。
- **需要登录或配置密钥**：在对应工具的配置入口完成，不把密钥写进公开提示词或提交进代码仓库。
- **结果看起来很完整但没有证据**：要求提供实际运行记录、数据来源或文件链接，并说明未验证部分。
