# AI、RAG 与 Agent 统一路线设计

## 目标

把现有 AI 全栈学习专题和 RAG 两周培训计划连接成一条可执行路线。读者能够从基础知识一路走到带评估、权限和回滚机制的 RAG/Agent 服务，并在每个阶段知道学习内容、产出、验收方式和可替代技术。

## 范围

- 新增一个与 `RAG` 并列的 `AI 全栈路线` 专题，作为统一路线总入口。
- 覆盖八个阶段：基础与工具、模型原理、模型调用、Embedding 与搜索、RAG 实现、RAG 评估、Agent 编排、生产化。
- 每阶段固定包含：知识点、前置条件、实践产出、验收标准、替代方案或选型比较、对应仓库文章。
- 更新 AI 索引，链接统一路线和现有深度文章。
- 在 RAG 培训计划中增加统一路线入口和阶段对应关系。

## 非目标

- 不重写现有 AI、RAG、Agent 文章的主体内容。
- 不新增依赖、代码示例项目或外部服务配置。
- 不改变文章 URL、分类目录或现有导航规则。

## 结构决策

统一路线按学习依赖排序，而不是按工具品牌排序。工具比较只保留会影响学习路径或上线决策的差异：`BM25`/dense/混合检索、托管向量库/`PostgreSQL`、`LangGraph`/SDK/自研状态机、云端模型/本地模型。

RAG 作为主线中的核心实践阶段，另以两周培训计划承载团队协作和每日任务；Agent 作为 RAG 之后的编排阶段，链接现有 Agent 专题。每一阶段都必须有可检查的产物，避免路线退化成资源清单。

## 验收标准

1. 统一路线能明确回答每个阶段“学什么、做什么、如何证明完成”。
2. 至少四处技术选型比较包含适用场景、优点、代价和建议。
3. RAG 阶段包含数据摄取、检索、重排、生成、引用和评估的完整链路。
4. 每个阶段至少链接一个现有仓库文档，且索引链接可解析。
5. `pnpm test` 通过，Markdown 文件名和现有导航规则不变。
